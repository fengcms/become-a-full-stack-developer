### slug 取舍分析要点（供后续撰文）
- 纯 id（`/articles/123`）：零复杂度，但 URL 不友好、不利于 SEO/分享。
- 自动 slug（标题→拼音/英文）：SEO 友好，但要引入拼音库或翻译 API、处理冲突与中文/生僻字，复杂度明显；且中文内容拼音 URL 对百度 SEO 收益有限。
- 可选 slug（推荐）：id 作主键与默认路由，管理员可选地手动填 slug 用于更友好 URL，唯一约束仅在填写时生效。复杂度最低且兼顾。
- 因 CSDN 是主阵地、自建站仅为演示品，SEO 非重点，故选可选 slug。

## 第八轮：第三次复审（更严苛标准，schema 合法 ≠ 逻辑无漏洞）

用户要求以比上轮更严苛标准，再评审产品 AI 的 `回应复审.md`（声称 20 项全采纳、契约经 openapi-spec-validator PASS）。复审 AI 独立安装并运行 openapi-spec-validator 复验，并用 PyYAML 脚本逐项核验 N1–N20 落点，再逐文件重读找更深逻辑漏洞。

### 验收结论（与上轮"假通过"本质不同）
- 独立运行 `python -m openapi_spec_validator docs/api/openapi.v1.yaml` → `docs/api/openapi.v1.yaml: OK`，**PASS 属实**，N1 是真修（404 已归位 responses 顶层，非嵌套）。
- 脚本核验 N1–N20 基本真实落地：N2 公开列表无 status、N3 view 可选 Bearer 描述、N4 POST /me/history 存在、N7 users 404/403、N8 删除 409、N9 00 §10.2 #6 改 reviewing、N18 应急集含 M1-25/26/27 均确认。本轮回应**诚实**，非假通过。

### 核心论断
**契约结构合法 + 跨文档一致，但"无逻辑漏洞"未达成。** openapi-spec-validator 只校验结构，不校验状态机闭环/实体生命周期/约束机读/多实现分歧。

### 新发现 18 项（🔴3 / 🟠6 / 🟡9），详见 docs/review/第三次复审报告.md
- 🔴 P1：`reviewing` 评论态死胡同——唯一评论变更端点是 `DELETE /comments/{id}`，无任何端点能置进/移出 reviewing，自动流也不产生，100% 不可达（影响 M1-27/M3-11）。
- 🔴 P2：`Attachment` 孤儿实体——模型定义了完整 Attachment，但 `upload` 只返回 `{url, storage}`，全契约 0 端点返回 Attachment（脚本确认）；与 00 §10.2 #7、M1-18 矛盾。
- 🔴 P3：普通 member 无法列举自己的文章——`GET /articles` 仅 published、`GET /admin/articles` 限 author/admin、无 `GET /me/articles`；核心投稿流 member 侧断裂。
- 🟠 P4：view 可选 Bearer 不可机读（OpenAPI 无可选鉴权），生成客户端永远走匿名分支，§2.4 "user_id 去重可达"对生成客户端为假。
- 🟠 P5：列表 `category/tag/keyword/sort` 方向语义未定义 → Node vs Go 必然分歧（威胁 M6-09 同契约）。
- 🟠 P6：评论列表返回哪些 status 未定义；P7：白名单/约束仅散文（Sort 无 enum、脚本确认 0/40 operationId、category/tag 无 enum）→ 威胁七端一致；P8：`slug` member 权限未定义（status 有、slug 无）；P9：40 操作全无 operationId（脚本确认）→ 七端生成函数名可能不一致。
- 🟡 P10–P18：邮箱修改/找回密码/验证缺失、refresh 旋转策略未定义、Sort 白名单未进 enum、应急集缺管理员发布 UI(M2-11)/评论前台(M3-10/11)、submit/approve 错误态未定义、disabled 会员主页可见性、`:id`/`{id}` 等价仅 02 声明、被拒评论 UX、阅读历史无删除端点。

### 冻结建议
未达成"无逻辑漏洞"，不建议立即冻结，但地基已牢。🔴 P1/P2/P3 为冻结前硬门槛；🟠 P4–P9 强烈建议同批清零（P9 补 operationId、P5/P12 下沉枚举为低成本高回报）；🟡 P10–P18 可在 02 §九登记为已知边界后冻结。做完再用 openapi-spec-validator 复验，并做语义自查（每状态/实体/约束是否都有读写路径、两后端是否会因契约沉默分歧）。

## 第九轮（v1.6）：产品 AI 清零全部 P1–P18 第三轮复审整改

用户要求阅读 `docs/review/第三次复审报告.md` 并做出整改，"严苛要求自己"。本轮把 18 项全部清零，并升级验收方法为**两道校验门**。

### 契约整改落点（openapi.v1.yaml 升 1.3.0：37 路径 / 49 操作 / 30 schema）
- 🔴 **P1 reviewing 闭环**：新增 `PATCH /comments/{id}/status`（moderateComment，admin 进出 reviewing）+ `GET /admin/comments`（listAdminComments，reviewing/rejected 唯一读取路径）。
- 🔴 **P2 Attachment 一等实体**：`upload` 200 改 `$ref: Attachment`（含 id/mimeType/size/storage）；新增 `GET /me/attachments`（listMyAttachments）+ `DELETE /attachments/{id}`（deleteAttachment）。
- 🔴 **P3 member 列举自己文章**：新增 `GET /me/articles`（listMyArticles，含全部 status）。
- 🟠 **P4 可选鉴权机读**：改标准写法 `security: [{}, {bearerAuth: []}]`（空安全需求=匿名允许、Bearer 可选），3 端点（文章详情/view/评论列表）；02 §3.3 说明标准写法 + 生成客户端现实约束。
- 🟠 **P5/P7/P12 约束下沉 enum**：`Sort` 改 `enum` 6 组合（field,direction）+ 默认 `publishedAt,desc`；新增共享参数 `FilterCategory`/`FilterTag`（按 slug 匹配）/ `FilterKeyword`（匹配 title+summary，不含 content）。
- 🟠 **P6 评论列表 status**：公开 `GET .../comments` 仅 `approved`；管理 `GET /admin/comments` 可按 status。
- 🟠 **P8 slug member 忽略**：`ArticleCreate.slug` 写明 member/author 传入被忽略，仅 admin 指定；冲突 409/3002（对齐 P14 status 同规格）。
- 🟠 **P9 全量 operationId**：49 操作全部补稳定且全局唯一的 operationId。
- 🟡 **P11 refresh 旋转**：`refresh` 返回新 AuthResult 时作废旧 refreshToken，重放/旧 → 1003（OpenAPI + 02 §三 + 00 §10.3）。**P13 应急集登记「经 API 发文」前提 + 注册默认角色 member 一致（01 §13 + 00 §10.3）。P14 submit/approve 非法前态 409/3003（02 §2.3 矩阵）。P15 disabled 主页 404 其文章仍公开。P16 `:param`≡`{param}` 全文档声明。P17 被拒评论 UX（不插入列表）。P18 阅读历史 DELETE 两端点（幂等）。**
- 🟡 **P10 邮箱找回 Non-goal**：v1 不做邮箱验证/找回自助；遗忘由 admin `POST /admin/users/{id}/reset-password` 兜底（00 §四 + 02 §九）。
