## BUG 分析 · 后台创建文章 summary/coverImage/slug 校验失败（code 4001）
- 现象：/articles/new 提交空可选字段，后端报 4001，三字段 `expected string, received null`；`categoryId:null` 反而通过。
- 三方证据（契约真相源）：① 契约 ArticleCreate(summary/coverImage/slug 均 `nullable: true`，required 仅 title/content)；② 前端 ArticleFormPage 空串转 null 发出、api.gen.ts 生成类型 `summary?: string|null` 类型正确（build 绿）；③ 后端 node-backend/src/routes/articles-write.ts 的 createArticleSchema 用 `.optional()`（仅放行 undefined，拒 null），漏写 `.nullable()`，且同 schema 内 categoryId 已用 `.optional().nullable()` → 后端自身不一致，与现象严丝合缝。
- 结论：**后端 BUG（违背冻结契约），前端实现正确**。根因 = Zod `.optional()` 与 OpenAPI `nullable:true` 语义不对齐。
- 报告：`docs/bugs/BUG-文章创建-null校验.md`（现象/三方证据/结论/建议 diff/验证/误解澄清/关联）。建议修复（待后端 owner 确认）：三字段改 `.nullish()`（=optional+nullable）；updateArticleSchema 经 extend 自动继承。
- 所有权：根因在 M1 冻结后端仓库，走增量维护流程，前端 AI 不擅自改。
- 关联：与 M2 四轮审阅 R5(/me/likes 裸数组) 同类「契约↔实现偏差回流」，建议在门禁加反向断言防回归。
