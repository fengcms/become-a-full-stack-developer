## R2 读回 404 根因（2026-08-29，非存储 bug）
- 现象：`POST /upload` 200 + `storage:"r2"`（写通），但 `GET /api/v1/files/<key>` 返回**纯文本 `404 Not Found`**（非 JSON 信封）。
- 根因：文件路由 `app.ts:69` 刻意挂在根 `app.route('/files', filesRoute)`（策略 A：附件直出不进 /api/v1 前缀），而其余路由都在 `/api/v1` 下。用户测的 `/api/v1/files/<key>` 未注册 → Hono 默认 404。**不是 R2 读不出，是 URL 前缀错**。正确取法是 `https://<domain>/files/<key>`（域名根 + /files，不带 /api/v1）。
- 契约 `Attachment.url` 仅定义为 `string(format:uri)`（openapi.v1.yaml:447），未限定前缀；代码策略 A 返回 `/files/<key>`（根相对）。设计自洽，但**前端须用 `ORIGIN + url` 而非 `API_BASE + url` 拼接**，否则拼出 /api/v1/files 会 404（M2 前端联调关键坑，已写 FAQ）。
- **已复测 GREEN**：`GET https://api-befull.kao9.com/files/a4dd28db...ae6.png` 返回 `200` + `content-type: image/png` + `content-length: 70` + `x-content-type-options: nosniff`，二进制体正确透出。**R2 读路径线上彻底打通**，404 根因确为 URL 前缀误用（非存储 bug）。
