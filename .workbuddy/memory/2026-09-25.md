## 启动 web-frontend（Codex 版）并接 11000 后端（owner 要求）

- 配置：新建 `web-frontend/.env.local`（被 `.gitignore` 的 `.env*` 忽略，不入库）：`API_ORIGIN=http://localhost:11000` + `NEXT_PUBLIC_SITE_URL=http://127.0.0.1:13001` + `NEXT_PUBLIC_API_BASE_URL=/api/v1`。
- **修复代理缺口**：该版 README 称"浏览器经同源代理 `/api/v1` 请求"，但 `next.config.ts` 实际**没有 rewrite**——浏览器端 `lib/request/core.ts` 拼 `/api/v1/...` 同源请求会 404。已补 `async rewrites()`，把 `/api/v1/:path*` 代理到 `${API_ORIGIN}/api/v1/:path*`（复用同一 `API_ORIGIN`），无 CORS 依赖、目标不写死。
- 启动：`cd web-frontend && pnpm dev`（Next 16.3.5，Turbopack，:13001）。
- **结果**（实测）：前端托管运行于 http://127.0.0.1:13001；首页 200 且 RSC 经 `API_ORIGIN` 渲染出真实文章标题；浏览器端 `GET /api/v1/articles` 经同源代理返 200 统一信封（total:65）。**前后端全链路打通**。
