## 挖到的真实教学点（全部回源码核过）
- **M1-32**：`ALTER TABLE ... DEFAULT 1`（老用户默认已设凭据，老用户若是 0 则全部密码登录失败）；**随机密码哈希 + `!user.credentialsConfigured` 短路 = 两道独立防线**（短路还省掉 bcrypt 12 轮成本）；`EXISTS (SELECT 1 FROM wechat_identities...)` 防"任何登录用户给自己开后门设密码"；**`changes()=1` 绑定**（失败方无条件撤销会让"既没设成功又被登出"）；`uniq_wechat_user` 索引让"一个会员绑两个微信号"在库层不可能；`redirect:'manual'` + `!response.ok`（3xx 不算 ok）；`AbortSignal.timeout(8000)`（Workers CPU 配额）；**日志不能记异常对象**（fetch 异常对象里挂着含 AppSecret 的 URL）；微信错误码按"客户端下一步做什么"映射（45011→429 不给 message）。
- **M1-33**：**`session_key` 不是访问令牌，不下发不进业务表**；**`(app_id, open_id)` 联合唯一**（open_id 跨 App 不同）；冲突后**必须重新 find**（否则留下无映射的孤儿会员）；`if (!user) throw 500` 处理用户名碰撞；**微信登录不豁免账号禁用**（否则禁用功能有绕过路径）；`atomic` 用 **`'batch' in client` 探测能力而非读配置**；返回 `changes[]` 是 `changes()=1` 的前提；**D1 batch 内语句不能互引结果**（所以用 `SELECT id FROM users WHERE username=?`）；显式 SQL 是为了看清原子边界，代价写进注释。
- **M1-34**：**`secret list` 只证明上传成功，不证明请求执行过**；**无效 code 探测法**（返回"凭证无效"=请求发出去了；返回 500 = 连微信都没走到）；**类型有 ≠ 运行时支持**（`RequestInit.redirect` 类型含 `'error'`，workerd 不认）；mock 测试边界表（证明业务规则，不证明请求能发出）；新增测试的四条断言各守什么，**`toHaveBeenCalledTimes(1)` 守住"没跟随 Location 再请求"**。
