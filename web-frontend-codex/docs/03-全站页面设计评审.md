## 3. 已确认的统一设计决策

- 公共页采用统一 Header/Footer，内页不重复放首页焦点区和广告。
- 文章类索引保持左主栏、右辅助栏；分类索引和标签索引按内容形态分别设计。
- 正文重视长文阅读，桌面侧边目录，手机目录折叠。互动和评论位于正文之后。
- 登录注册采用两栏，手机上下排列；不加入现有后端未支持的第三方登录和找回密码流程。
- 会员页面统一左侧导航，手机改为六项分组入口，避免照搬管理后台。
- 仅用小面积主题色，内容底色白色、正文深蓝灰，表格和代码区浅色。
- 真实品牌暂以仓库已有“成为全栈开发工程师 / FungLeo”为文案基线，正式实现仍读取站点设置。

## 4. 演示边界

可演示：页面切换、手机布局、栏目层级展开、列表筛选、文章跳转、收藏/点赞视觉状态、回复输入、表单校验反馈、通知已读和加载更多。

本地交互只演示设计，不代表真实 API、分页、权限和数据持久化已实现。不同示例文章可进入同一详情稿；复制和分享仅展示反馈，不操作剪贴板；表单不连接账号服务。不得在设计评审中填写真实密码。

外观可通过设计控制调整文章正文字号、登录状态；这些变更不会自动视为用户对全站的批准。

## 5. 检查与后续确认

设计检查与产品验收分开：本轮检查可视化中的页面切换、渲染和布局，不执行应用构建或后端验收。

本轮实际检查：

- 26 张设计稿分别完成桌面和约 390px 手机容器切换，共 52 次页面渲染检查；每页均有正文内容，未检测到容器横向溢出。
- 查看文章详情、文章列表、手机资料页与手机登录页的浏览器截图，检查排版和颜色。
- 验证通知全部已读、文章待审核筛选的本地反馈；浏览器未记录脚本错误。
- 已核对新项目内文档链接。以上仅为设计预览检查，不等同于真实接口、实际移动设备或应用级可访问性验收。

建议按以下顺序确认：

1. **文章详情**：标题区、正文宽度、目录、代码、评论是否符合阅读习惯。
2. **列表与导航**：文章列表、分类、标签、搜索之间是否有清晰一致的层级。
3. **会员区域**：登录注册、会员导航、列表与表单是否清楚顺手。
4. **手机与状态**：折叠导航、单栏排版、空状态与错误反馈是否合适。

用户反馈按页面编号记录，可先分组修改，再统一确认。用户现已明确确认，P0–P6 已执行完成。
