# 网站前台设计与工程落地方案

日期：2026-09-22  
状态：用户已确认全站设计并授权自主开发；已落地。本文保留设计基线，实施差异见《04-实施记录》，验证见《05-验收报告》。

## 1. 目标与范围

在独立目录 `web-frontend-codex/` 开发传统内容门户前台，保持现有技术方案、业务规则和 API 契约。重点改善首页信息组织、清爽的视觉呈现、文章阅读、栏目导航和会员操作体验。

### 1.1 用户明确确认的要求

1. 原 `web-frontend/` 保留，不修改；新项目在 `web-frontend-codex/` 独立开发。
2. Header 包含 Logo、一级栏目导航、多级下拉菜单、右侧搜索框、登录与注册入口；登录后切换为会员中心。
3. Header 下方分两栏：左侧焦点图，右侧全站最新文章。
4. 焦点区下方放置通栏、高度为 **120px** 的广告图区域。
5. 广告下方分两栏：左侧文章列表，可持续向下浏览；右侧侧栏，展示特殊属性的文章等内容。
6. 底部 Footer 展示版权信息。
7. 采用 A 方案布局与配色：**白色或极浅蓝底、深色但非黑色文字、少量主题色点缀、整体清爽**。以纯白版本为默认。

### 1.2 本文确定的实施默认值

容器宽度、列比例、轮播切换方式、连续加载批次、字号和缓存时间为落地默认值，后续按真实内容和设备表现调优。首页之外的页面沿用同一视觉体系，保持原有业务范围。

本期不新增后台广告管理、推荐位管理、付费内容、关注系统或第三方登录；不因视觉重做扩展后端。发现接口缺口记录差异，不自行修改契约。

## 3. 视觉规范：纯白／晴蓝

### 3.1 色彩令牌

| 用途 | 默认色值 | 使用原则 |
|---|---|---|
| 页面、Header、内容区 | `#FFFFFF` | 白色占主导 |
| 极浅辅助底色 | `#F7FAFD` | 搜索框、轻量分区、Footer |
| 标题 | `#2F4256` | 深蓝灰，禁止纯黑 |
| 正文 | `#34465A` | 长文及列表主要文字 |
| 次要文字 | `#607286` | 日期、摘要、辅助说明；按实际底色检查对比度 |
| 主题色 | `#3277B5` | 链接、选中态、少量按钮和标识 |
| 链接悬停 | `#245D91` | 交互反馈 |
| 浅蓝强调底 | `#EDF5FC` | 当前栏目、轻提示、Logo 辅助底 |
| 分割线 | `#E9EFF5` | 列表和模块轻边界，不用于唯一的输入框识别 |
| 表单边界 | `#8397AB` | 保证输入框可辨识，焦点另设明确轮廓 |
| 焦点区备用背景 | `#F0F7FE` → `#E4F0FB` | 浅蓝，文字保持深色 |
| 广告备用背景 | `#F0F7FD` | 轻量横幅，不使用深色大块 |

首期固定浅色外观，不随设备自动切换为深色。正常正文对比度以 4.5:1 为验收门槛，交互边界与焦点状态按可访问性要求校验；表内值若未达标，向更深色微调。白字仅用于需要强调的实色小按钮，正文和大面积内容采用深色文字。

### 3.2 排版与空间

- 中文优先系统无衬线字体：PingFang SC、Microsoft YaHei 等；不依赖外部字体请求。
- 正文基准 16px，文章正文 17–18px、行高约 1.85；辅助文字 13–14px。
- 列表标题 18–20px；首页焦点标题 28–34px；详情标题 30–36px，移动端相应缩小。
- 常规间距取 4/8/12/16/24/32px。模块之间约 24px，模块内部约 20px。
- 默认圆角 4–6px；弹层可 8px。内容区不用重阴影或多层卡片嵌套。
- 不使用大面积高饱和底色、纯黑正文、厚边框、夸张装饰或以英文作主要导航。
- 文章封面可保留自身颜色；版式底色与配套焦点、广告素材维持清爽。无图片时使用浅色文字式备用呈现，不捏造封面。

## 4. 首页布局

```text
┌────────────────────────────────────────────────────────┐
│ Logo  首页  栏目 ▾  栏目 ▾       搜索框   登录 / 注册  │
├────────────────────────────────────────────────────────┤
│            焦点图（约 5/8）       │ 最新文章（约 3/8） │
├────────────────────────────────────────────────────────┤
│                通栏广告图 · 高 120px                   │
├──────────────────────────────────┬─────────────────────┤
│ 分类切换 + 文章列表（约 7/10）    │ 热门文章             │
│ 文章 / 文章 / 文章……             │ 编辑精选（有配置时） │
│ 持续加载 / 加载更多              │ 标签等辅助入口       │
├──────────────────────────────────┴─────────────────────┤
│               Footer / 版权信息                        │
└────────────────────────────────────────────────────────┘
```

### 4.1 容器和响应式

- 桌面内容最大宽度默认 1200px，居中；Header 背景铺满视窗，内容与主容器对齐。
- 桌面焦点区左右约 5:3，主内容约 7:3，列间距 24px。
- 1024px 以上优先双栏；768–1023px 依据实际导航宽度收起导航、压缩次要内容；768px 以下主内容单栏。
- 手机左右边距 16px，焦点图与最新文章上下排列；侧栏移至文章区后方。
- 所有断点通过内容溢出测试确定，不依赖固定设备名称。重点验证 375、768、1024、1440px，并覆盖 320px 最窄场景。

### 4.2 Header 与多级栏目

- 桌面高度默认约 80px，Logo → 首页/一级栏目 → 搜索 → 会员入口。
- 栏目来自分类树，按接口顺序显示。父栏目名称可进入栏目页；独立展开按钮负责子菜单，避免触屏一次点击既跳转又展开。
- 桌面二级菜单向下，三级及后续菜单向侧面展开；按契约支持最多四级。贴近右边缘时翻转展开方向。
- 菜单同时支持鼠标、点击和键盘；Esc 关闭、焦点可返回触发按钮，打开时有明确展开态。不会因鼠标跨越菜单间隙立即关闭。
- 一级栏目过多时收纳至“更多栏目”，禁止挤压搜索或横向撑破页面。
- 手机采用折叠导航和逐级展开，搜索可独立一行，登录入口保持可见。
- 登录态恢复期间保留等宽占位，避免“登录/会员中心”闪烁。登录后显示头像或昵称、会员中心、退出入口。

### 4.3 搜索

- Header 内保留真正可输入的搜索框；Enter 或搜索按钮提交到 `/search?q=...`。
- 对接 `/api/v1/search`，文章类型为默认，使用 `q` 参数；不要用文章列表的 `keyword` 冒充全文搜索。
- 去除首尾空格，空输入不发送检索请求；URL 保留关键词和页码，刷新、分享可复现。
- 不默认增加自动补全、搜索建议等缺乏接口支持的能力。

### 4.4 焦点图与最新文章

- 焦点区默认高约 320px，与右侧最新文章对齐；手机约 220–260px。
- 默认 3 张，最多 5 张。支持前后切换、序号按钮和明确文章入口；首期默认手动切换，避免自动播放干扰阅读。
- 标题尽量放在浅色独立区域，避免直接压在复杂图片上。封面指定裁切焦点，长标题最多约三行。
- 最新文章按 `-publishedAt` 展示默认 6 条，以标题和日期为主，链接到详情；“全部文章”进入文章列表。
- 焦点素材优先使用本项目显式配置的公开文章及本地图片；无配置时用最新文章候选，有封面优先。没有封面则用浅蓝文字封面，不生成假图片 URL。
- 配置文章已下架、链接无效或候选不足时剔除、补位；单张隐藏轮播控件；全站无内容时展示站点介绍及正常空状态。

### 4.5 120px 广告位

- 通栏指主内容容器通栏，桌面固定高 **120px**，预留高度避免图片加载引起跳动。
- 一处横幅，可配置图片、移动版图片、替代文字、链接及是否新窗口打开。
- 移动端仍保留 120px 高度，优先移动版素材或浅色文字备用横幅，不能直接把桌面文字图压缩到不可读。
- 无商业广告时使用本站系列导读横幅；不展示虚构赞助商或未配置的链接。
- 首期配置存放新项目内，不能宣称可由现有管理后台维护。外部广告素材暂缺不阻塞页面开发。

### 4.6 文章流

- 默认最新排序，每批 10 篇；分类切换只采用真实分类，切换后重置页码及加载状态。
- 默认左侧缩略图、右侧标题/摘要/元信息。无图文章使用纯文字变体，不为每条放重复占位图。
- 标题两行，摘要两行，移动端优先保证标题完整可读；作者、日期、分类使用低强调深灰蓝。
- 首页首批由服务端输出；客户端接续页码加载，按文章 ID 去重、防止并发重复请求。
- 默认连续自动加载两批后暂停，显示“加载更多”；点击后继续下一批。该值是实施默认，可调整。
- 有网络错误时保留已读列表，提供重试；不能将失败显示为“没有更多”。离线、无结果、已到底分别呈现。
- Footer 必须可达，列表底部始终有可操作的加载/暂停位置。手机侧栏不被无止境自动加载推远。
- `/articles?page=N` 保留服务端分页入口供直达、无脚本和搜索引擎使用。返回首页时尽量恢复已加载数据及滚动位置；不能将内存中的多批列表全部转成永久 URL 参数。
- 后端为页码分页：内容并发发布可能产生页间位移，前端去重不等于快照一致性，不承诺动态数据绝对无遗漏。

### 4.7 侧栏与 Footer

- “热门文章”：`sort=-viewCount`，表示累计阅读量排序；不能标为“本周热门”。
- “编辑精选”：仅展示本地显式配置的已发布文章，无配置则隐藏；不能把最新文章误称为编辑精选。
- 标签等辅助入口直接使用真实接口数据。每个模块数量有限，避免侧栏比主内容更抢眼。
- Footer 展示站点配置中的版权及已具备的站内链接；备案号、联系方式等只在真实配置存在时显示，不沿用示意数据。

## 5. 其他页面

| 页面 | 布局与能力 |
|---|---|
| 文章列表 `/articles` | 公共 Header/Footer，列表加侧栏，筛选和分页状态进入 URL |
| 分类 `/categories`、`/categories/[slug]` | 分类树、名称、面包屑、子分类入口与文章列表；父分类包含后代文章 |
| 标签 `/tags`、`/tags/[slug]` | 标签索引及文章列表，使用真实标签名称与 slug |
| 详情 `/articles/[slug]` | 标题/作者/日期、摘要、正文、目录、点赞收藏、评论、上下篇和相关内容 |
| 搜索 `/search` | 搜索框、关键词、结果、分页、无结果/失败提示；保留现有会员搜索能力时提供类型切换 |
| 作者 `/members/[id]` | 公开资料和已发布文章 |
| 登录 `/login`、注册 `/register` | 与本站一致的白底表单、校验反馈及登录后返回路径 |
| 会员 `/member/*` | 资料、收藏、历史、文章、点赞、通知；桌面侧栏导航、移动端折叠或分组导航 |
| 关于 `/about` | 真实站点介绍，不复制示意品牌内容 |
| 加载/错误/404 | 独立状态，适当提供重试、返回和搜索入口 |

首页焦点区和广告位不自动复制到所有内页。详情正文宽度默认 720–780px，桌面右侧目录、移动端折叠目录；文章背景白色，代码块使用浅色高亮。

Markdown 标题与目录使用同一套锚点生成规则，覆盖重复标题、中文、格式化标题、代码围栏。表格和代码在自身区域横向滚动，页面主体不横向溢出；长 URL 可换行。默认不启用未经清洗的原始 HTML；结构化数据输出时正确转义。

会员中心统一保存/提交/删除状态，保持原产品支持的权限与操作，不因“我的文章”导航新增未经确认的编辑器。第三方登录继续不在本期范围。

## 6. 数据、配置与技术边界

### 6.1 数据映射

以下接口均以 `/api/v1` 为前缀，实际参数和响应必须从契约生成类型并联调确认。

| 模块 | 来源 | 注意事项 |
|---|---|---|
| 站名、Logo、版权、SEO | `/site/settings` | 无 Logo 时用站名文本，不替换真实品牌 |
| 多级导航 | `/categories` 分类树 | 深度、排序依契约；建立 id→slug/name 索引 |
| 最新、文章流 | `/articles` | 公开已发布文章；分页读取 `pagination` |
| 焦点与编辑精选 | 本地配置 + 公开文章接口 | 与后台管理能力明确区分 |
| 广告 | 本地配置和素材 | 无新广告 API |
| 热门 | `/articles?sort=-viewCount` | 累计阅读量 |
| 搜索 | `/search?q=...&type=article` | 与列表 keyword 的检索范围不同 |
| 正文与辅助导航 | 文章详情、adjacent、related、breadcrumb | 以契约定义的 ID/slug 参数调用 |
| 登录、会员与互动 | 现有 auth、me、comments、like 等接口 | 私有数据禁止进入公共缓存 |

摘要没有 `categorySlug` 时，通过分类树映射 `categoryId`，不能将数字 ID 直接拼入需要 slug 的分类路由。标签同样核对接口字符串语义，不以显示文字臆造 slug。

本地内容配置建议包含 `focusItems`、`banner`、`editorPicks`，使用类型化结构和可选字段。初期只用合法公开文章标识、受控链接、本地素材路径。正式品牌取站点配置，示意中的“全栈之路”不作为已批准改名。

### 6.2 技术基线

- Next.js App Router + React + TypeScript，保持现有主要版本；现有清单为 Next 16.3.5、React 19.2.8，实施时以旧锁文件核实可复现版本。
- Tailwind CSS 4，样式走类或 CSS 文件；不写 React 内联样式。
- 公开内容 RSC + 服务端 fetch，互动 TanStack Query，轻量会话状态 Zustand。
- react-markdown、remark-gfm、rehype-slug、rehype-highlight / highlight.js 延续实际工程组合。
- openapi-typescript 从冻结契约生成类型；pnpm + Biome。
- Cloudflare Workers + OpenNext，保留现有部署目标，不在设计重做中替换平台。
- 不照旧计划自动追加 shadcn、表单库、Shiki 等未被实际工程采用的依赖。必要新增依赖单独记录用途。

### 6.3 运行、认证与缓存

- 新项目独立依赖、锁文件、环境示例和脚本，不从旧前台目录导入运行时代码；复制复用前检查正确性。
- access token 存内存，refresh cookie 通过同源代理正确转发；保留刷新旋转与并发刷新保护。验证 Set-Cookie 多值、路径及注销行为，禁止 token 落 localStorage。
- 新旧站本地即使用不同端口，同域 Cookie 仍可能共享；联调时使用独立浏览器上下文或独立本地主机名，不能把端口隔离当作 Cookie 隔离。
- 服务端请求必须配置有效 `API_ORIGIN`，缺失时明确报配置错误；不使用 `undefined as T` 假装成功。
- 实施统一将公开内容重新验证周期设为 60 秒，sitemap 路由上限 300 秒（关联数据可能使其提前重新验证）。明确公共 fetch 的缓存时间，不能只写标签而无更新途径。
- 搜索实时获取；会员数据和认证/互动请求不进入共享缓存。第三方服务故障、404 与真实空数据分开处理。
- 初期保留旧工程暂不启用 Cache Components 的配置，不将历史兼容性注释当成当前已验证结论；部署兼容性在实施阶段实际验证。
- Worker 名称、预览地址和缓存资源独立，不覆盖旧站。配置完成不等于发布，本次不进行线上部署。

遵循既有工程约定：箭头函数、严格类型、文件头和必要函数说明，源文件原则上不超过 200 行；生成代码例外，其他例外记录原因。避免为简单页面引入多余抽象。

## 8. 设计验收

- 首页结构与用户确认 A 布局一致，120px 通栏广告位置正确。
- 白底主导、正文深蓝灰，主题色只作小面积强调，焦点与备用广告无大块深底。
- 真实长标题、缺图、空数据、多级分类、接口故障均能保持布局。
- Header、菜单、搜索和会员入口在桌面/触屏/键盘下可用。
- 列表可持续浏览但 Footer 可达，加载错误可重试。
- 内页沿用同一视觉体系，长文、表单与操作反馈可读。
- 所有统计、精选标记、品牌与版权有真实来源；无虚构“周榜”等能力。
