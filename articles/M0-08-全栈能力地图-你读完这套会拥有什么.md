## 维度一 · 数据建模

| 你出发时（前端视角） | 走完系列后（全栈视角） |
|---|---|
| 消费接口返回的 JSON，按字段渲染列表 | 面对一个需求，独立拆出实体和关系，设计表结构 |
| 偶尔用 `useState` 存点临时数据 | 理解「规范化」：一对多、多对多、外键、索引为何存在 |
| 表结构是什么样， backend 给 | 能拍板「这篇文章要不要独立成表」「收藏该挂哪张表」 |

**达标标尺**：拿到「用户能收藏文章并看到自己的收藏列表」这种需求，你能独立拆出 `user / article / favorite` 三张表，定好外键与索引，而不是等后端把表结构甩给你。

对应篇目：{{LINK:M0-04}} 领域建模、M1 数据库系列。

## 维度二 · 接口设计

| 你出发时（前端视角） | 走完系列后（全栈视角） |
|---|---|
| 按文档 `fetch` 接口，遇到字段对不上就找后端 | 自己设计端点、定路径语义、管错误码 |
| 不知道 `4xx` 和 `5xx` 谁该负责 | 清楚哪些错误是客户端问题、哪些是服务端事故 |
| 版本？那是别人的事 | 懂得为什么接口要带版本、怎么平滑升级不炸旧端 |

**达标标尺**：你能设计一套带版本号、统一响应包络、机器可读错误码的 REST 端点，并写进 OpenAPI，让六个端共用同一份契约。

对应篇目：M0-05 契约先行、M1 端点实现。

---

## 维度三 · 服务端编程与请求生命周期

| 你出发时（前端视角） | 走完系列后（全栈视角） |
|---|---|
| 只关心浏览器里的 runtime | 理解请求从 DNS → 服务器 → handler → 数据库 → 响应的全程 |
| `useEffect` 里发请求，黑盒返回数据 | 能写出处理请求的 handler，知道参数从哪来、响应往哪去 |
| 一种并发模型（JS 事件循环） | 理解另一种（Go goroutine），知道它们解决什么不同问题 |

**达标标尺**：你能讲清「我在浏览器点了一下，到数据回来」中间每一步发生了什么，并在 Node 或 Go 里写出一个真正的请求处理函数。

对应篇目：B-15 服务端心智模型、M1 Node 后端、M6 Go 后端。

---

## 维度四 · 鉴权与信任边界

| 你出发时（前端视角） | 走完系列后（全栈视角） |
|---|---|
| 登录拿到 token，存进 `localStorage` 完事 | 理解 token 怎么签发、怎么作废、为什么不能信前端传来的「我是管理员」 |
| 前端路由守卫拦一下就行 | 懂服务端信任边界：每个请求都要重新核验身份与权限 |
| session 和 JWT 分不清 | 能说清两者取舍，按场景选 |

**达标标尺**：你能正确区分「这个请求带着合法 token」和「这个请求确实是这个用户发的」，并在服务端把越权堵死——而不是只在按钮上 `disabled`。

对应篇目：M1-13 鉴权、M3-08 会员认证。

---

## 维度五 · 存储与持久化

| 你出发时（前端视角） | 走完系列后（全栈视角） |
|---|---|
| `localStorage` / 状态库就能应付 | 分得清 SQL 数据库和对象存储各管什么 |
| 没碰过事务 | 知道「要么全成要么全败」为什么重要，会写带事务的写入 |
| 文件？上传组件搞定 | 懂附件该放对象存储（R2）还是本地，知道取舍 |

**达标标尺**：你能设计一次「发文章同时写入内容、记录操作日志、可能还要存封面图」的多步写入，并保证它要么全成要么回滚，不会留半截脏数据。

对应篇目：M1-04 数据库选型、M1-08 事务、M1-12 文件上传。

---

## 维度六 · 部署与运维

| 你出发时（前端视角） | 走完系列后（全栈视角） |
|---|---|
| `npm run build` 丢给平台或运维 | 自己把一个服务跑上线、配域名和环境变量 |
| 出事看控制台报错 | 会看服务端日志、定位「本地好好的上线就炸」 |
| 不知道限流、不知道成本 | 懂基本限流与 serverless 成本意识 |

**达标标尺**：你写的后端服务，从代码到能在公网访问，中间每一步你都能自己走完，出问题时你能从日志里找到线索，而不是干等。

对应篇目：M1-03 部署、M7 Vue3 后台、M8 收官。

---

## 维度七 · 架构权衡

| 你出发时（前端视角） | 走完系列后（全栈视角） |
|---|---|
| 组件怎么拆，是主要架构思考 | 系统怎么拆、端怎么分，才是日常 |
| 听人说「上微服务」就觉得该上 | 面对「要不要 BFF」「Cloudflare 还是自管 Linux」能列权衡 |
| 技术选型靠跟风 | 有方法论：按约束定技术，不是投票 |

**达标标尺**：有人问你「这个项目后端用 Node 还是 Go」，你能从团队、成本、并发特征给出有依据的倾向，而不是甩一句「都行」。

对应篇目：{{LINK:M0-03}} 技术选型、M6 Go 后端、M8 收官。
