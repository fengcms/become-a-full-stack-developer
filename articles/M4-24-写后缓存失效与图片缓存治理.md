# 成为全栈·Flutter App 篇·写后缓存失效与图片缓存治理

点赞成功后，卡片计数变了，收藏列表却仍旧；一次稿件更新也可能同时影响列表、正文、目录和预览。全量清缓存确实能掩盖这类不同步，却会让每次返回页面都重新请求。

这篇跟踪 `ApiClient.onMutation` 到 Repository 的失效标签与 `ImageStore`，展示应用如何只清相关资源，并用实际缓存验收数据衡量收益。

{{IMG:M4-24-封面}}

## 先建立写入与读取的关系表

收藏变更影响收藏索引和会员列表；点赞影响文章按钮状态、互动计数和点赞记录；投稿写入影响稿件列表、详情/预览；资料变更影响会员概览。Mutation hook 将操作映射到关联资源，而不是清除整个应用缓存。

```text
write: favorite(articleId)
invalidate: favorite index + member favorites
preserve: public article body unrelated to favorite
```

写入开始时先隔离相关旧读取，避免旧响应在写请求成功后抵达并把界面回滚。失败后也要按乐观更新策略回退，重新读取时以新代次为准。

{{IMG:M4-24-失效图}}

## 代次防止迟到响应污染

读取 R1 正在进行时，用户触发写操作 W。若 W 成功后仍允许 R1 写缓存，旧数据就可能覆盖刚确认的新状态。每个资源缓存代次增加后，R1 返回时发现它属于旧代次则丢弃。相同机制也用于强制刷新和会话变化。

## 图片缓存要考虑身份、URL 和尺寸

图片按显示尺寸解码，避免原图占用过量内存；公开、无签名 URL 才适合进入公共磁盘缓存。带查询参数/签名 URL、私有图片或草稿图片采取保守策略，避免过期链接和跨用户内容写入公共缓存。容量包含单图上限、总字节预算和过期淘汰。

“清理缓存”只删除可重建文件，不应删除 refresh token、主题偏好、搜索历史或用户尚未提交稿件。缓存目录是系统可回收空间，不是持久文档库。

## 性能数字必须带测量对象

本项目的 Android profile 只读样本测量分类、标签、文章列表和一篇正文/目录的数据读取：首次 4971ms、内存命中 5ms、重建 Repository 后磁盘命中 187ms。样本只在同一模拟器和指定代理网络取得；重建缓存实例不是进程冷启动，network 资源数也不等于 HTTP 次数。不能把这些数字宣传成首帧 SLA 或多机型性能保证。

## 容量预算需要说明统计口径

项目为公开 JSON、图片文件、内存响应和 Flutter 解码缓存分别设置上限。例如图片磁盘文件上限 150MB、单图 10MB，Markdown token 和数据项也有自己的预算。这些数字不可简单相加成“应用最大占用”，因为活跃 Widget、原生 WebView、Dart 堆和平台解码内存另有开销。

清理策略按访问时间淘汰可再生成文件；文件写入使用临时文件再原子改名，索引损坏时允许重新建立。缓存目录重建失败应退回网络读取，而不能导致阅读入口崩溃。验证时分别测文件预算、会话退出清理和内存压力释放。

## 失效策略同时处理成功和不确定失败

POST 超时并不说明服务器没有完成写入。项目在 mutation 开始时 fence 关联缓存，写入结束无论成功还是失败都失效相关资源，因为请求可能已到达服务器；会话代次变化则忽略旧请求事件。成功响应会用服务器返回计数更新互动状态，后续读取再恢复一致视图。

这与纯粹“只有成功才清缓存”不同：如果服务器已写成功但响应丢失，保留旧缓存会让用户看到错误状态。代价是失败请求可能触发一次额外读取，但它比长期展示潜在错误的旧数据更可靠。资源 tag 粒度因此要足够具体，避免过度失效。

## 图片的 HTTP 缓存头是上限而不是建议

ImageStore 为无 query 的 HTTP(S) 公开 URL 才允许磁盘持久化，签名 query URL、私有图片不进入公共磁盘。服务器 `no-store`/`no-cache` 会禁止保留，`private` 会禁止磁盘，max-age 与 Age 共同决定不晚于服务端允许的过期时刻，并设最长七天保护。

图片请求显式移除 Authorization header，即使 Dio 默认 client 有登录状态也不会把 Bearer 发到第三方 host。单图过大时可以返回显示但不放入内存缓存；Memory pressure 到来时 App 清理可再生成的内存图像、Repository cache 和列表快照，不删除用户草稿。


## 贴着工程代码读实现

下面这段节选自 `flutter-app/lib/core/cache/image_store.dart 第 31–100 行`（保留原始实现；为突出主线省略了文件其余部分）。读代码时可以顺着调用链确认：分别请求无凭据公开图片、带 query 图片和私有图片并检查磁盘条目。沿着调用链读下去，才能看清这个选择如何影响实际页面。

```dart
  Future<Uint8List> load(
    String url, {
    required bool public,
    required int epoch,
    bool force = false,
  }) {
    final k = key(url, public, epoch), generation = _generation;
    final existing = _memory[k];
    if (!force && existing != null && DateTime.now().isBefore(existing.$2)) {
      _memory.remove(k);
      _memory[k] = existing;
      return Future.value(existing.$1);
    }
    if (_flights.containsKey(k)) return _flights[k]!;
    late Future<Uint8List> task;
    task = () async {
      try {
        final persist = canPersist(Uri.parse(url), public);
        if (!force && persist) {
          final bytes = await disk.read(k);
          if (bytes != null && generation == _generation) {
            _put(k, bytes, disk.expiresAt(k) ?? DateTime.now());
            return bytes;
          }
        }
        // 图片请求明确移除鉴权头，避免把 API 令牌发送给图片域名。
        final response = await dio.get<List<int>>(
          url,
          options: Options(
            responseType: ResponseType.bytes,
            headers: {'Authorization': null},
            validateStatus: (s) => s != null && s >= 200 && s < 300,
          ),
        );
        final bytes = Uint8List.fromList(response.data!);
        if (generation != _generation) {
          throw StateError('Image request superseded');
        }
        final control = (response.headers.value('cache-control') ?? '')
            .toLowerCase();
        final storable =
            !control.contains('no-store') && !control.contains('no-cache');
        final maxAge = int.tryParse(
          RegExp(r'(?:^|,)\s*max-age\s*=\s*"?(\d+)')
                  .firstMatch(control)
                  ?.group(1) ??
              '',
        );
        final age = int.tryParse(response.headers.value('age') ?? '') ?? 0;
        final seconds = math.max(0, math.min(7 * 86400, maxAge ?? 86400) - age);
        // 使用响应缓存头和 Age 计算绝对过期时间，磁盘命中沿用原时间。
        final expires = DateTime.now().add(Duration(seconds: seconds));
        if (storable && seconds > 0) {
          _put(k, bytes, expires);
          if (persist &&
              !control.contains('private') &&
              bytes.length <= CacheLimits.imageEntryBytes) {
            unawaited(disk.write(k, bytes, expires));
          }
        } else {
          await disk.removeWhere((key, _) => key == k);
        }
        return bytes;
      } finally {
        if (identical(_flights[k], task)) _flights.remove(k);
      }
    }();
    _flights[k] = task;
    return task;
  }
```

## 把容易出错的路径走一遍

我会用这个场景做一次可复现排查：**公开图片缓存把带身份的请求或私有响应落盘**。先分别请求无凭据公开图片、带 query 图片和私有图片并检查磁盘条目；如果把问题定位在“所有图片持久化”，修正方向是“只持久化符合策略的公开 URL，私有图限制在会话内存并可重置”。最后再验证正常路径没有退化，并把边界条件留在自动化检查里。

| 方案比较 | 简化做法 | 当前实现/推荐做法 |
|---|---|---|
| 本文核心选择 | 所有图片持久化 | 公私缓存隔离 |
| 错误处理 | 失败后清空或静默忽略 | 保留可恢复状态，给出明确反馈 |
| 验证方式 | 只检查成功结果 | 注入边界条件并检查回归 |

| 排错步骤 | 要观察什么 | 通过条件 |
|---|---|---|
| 复现 | 公开图片缓存把带身份的请求或私有响应落盘 | 可以稳定触发或明确构造该输入 |
| 定位 | 分别请求无凭据公开图片、带 query 图片和私有图片并检查磁盘条目 | 找到责任层和状态归属 |
| 修正 | 只持久化符合策略的公开 URL，私有图限制在会话内存并可重置 | 失败不污染后续页面或账号 |

## 小结

写后失效应依赖业务资源关系，代次机制阻止旧响应覆盖新数据；图片缓存按 URL 属性、身份和容量谨慎选择。测量结果必须说明设备、网络、对象和路径，才能成为可复核证据，而不是脱离条件的性能承诺。
