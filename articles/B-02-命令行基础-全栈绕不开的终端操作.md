# 成为全栈·基础补充·命令行基础：全栈绕不开的终端操作

> 终端不是程序员的仪式感工具，而是把文件、进程、服务和构建步骤变成可重复命令的工作台。掌握少数核心概念，比记住一长串命令更有用。

## 前言：从“能打开项目”到“知道自己在哪”

刚开始接触全栈项目，常见的卡点不是复杂代码，而是命令在哪个目录执行、服务器进程是否还在运行、构建日志去哪了、命令失败后该看什么。终端把这些动作直接展示出来，也让你能把步骤写成脚本，交给别人重复执行。

本文不追求列出所有命令。先建立三个概念：当前目录决定相对路径；命令的退出状态说明成功与否；进程是一个正在运行的程序。掌握它们之后，`cd`、`pwd`、`ls`、`rg`、`npm`、`go` 和 `git` 就不再像一串魔法咒语。

## 一、当前目录就是命令的上下文

打开终端后，先看自己在哪：

```bash
pwd
ls
```

`pwd` 显示当前工作目录，`ls` 列出当前目录内容。`cd path` 切换目录；`cd ..` 回到上级；绝对路径从根或用户目录开始，不依赖当前位置；相对路径从当前目录开始。很多“文件找不到”不是文件不存在，而是命令运行目录错了。

例如仓库根目录里有 `go-backend/`：

```bash
cd go-backend
go test ./...
```

第二条命令的 `./...` 指当前 Go 模块下的包。若仍在仓库根目录，命令可能报“go.mod 不存在”。执行前先确认路径，必要时使用 `pwd`，比盲目重复安装依赖更有效。

## 二、命令由程序、参数和选项组成

终端命令的基本形态是：

```text
程序 位置参数 --选项 值
```

例如 `git log --oneline -5` 中，`git` 是程序，`log` 是子命令，`--oneline` 和 `-5` 是选项。每个工具自己的参数规则不同，遇到不确定时先看 `command --help` 或项目 README，避免复制来源不明的危险命令。

路径或字符串中含空格时要正确引用：

```bash
cd "My Project"
```

单引号通常阻止 shell 展开变量，双引号仍允许 `$NAME` 等变量展开。shell 会先处理引号、变量和通配符，再把参数交给程序。理解这一点，可以解释为什么文件名里的空格、`*` 和 `$` 会改变命令含义。

## 三、标准输入、输出和退出码

一个命令通常从标准输入读取数据，向标准输出写正常结果，向标准错误写诊断信息。`>` 可以重定向输出到文件，`>>` 追加，`2>` 单独重定向错误；管道 `|` 把前一个命令的标准输出交给后一个命令。

```bash
go test ./... > test.log 2>&1
```

这会把标准输出与标准错误都写到 `test.log`，便于保存完整测试结果。退出码通常用 `0` 表示成功，非零表示失败；自动化脚本依赖它判断下一步能否执行。只看最后一行日志可能错过前面的失败，命令退出状态和完整输出都值得检查。

管道也会隐藏一些失败：shell 默认可能只返回最后一个命令的退出状态。写可靠脚本时启用合适的严格模式，或逐项检查结果；交互排查时不要只看到输出里有“OK”就认定整条管道成功。

## 四、进程、端口和后台服务

运行 `npm run dev` 或 `make run` 后，终端启动一个进程。前台进程持续占据该终端，按 `Ctrl+C` 请求中断；另开终端可以执行其他命令。进程通常监听一个端口，浏览器通过 `http://127.0.0.1:8080` 等地址连接。

如果看到“address already in use”，说明端口可能已被另一个进程占用；不要马上启动第三个副本。先确认已有进程是否就是目标服务，再决定停止或换端口。杀进程命令会造成中断，尤其要确认 PID 和所属程序，不要把复制来的 `kill -9` 当成第一选择。

## 五、环境变量和本地配置

环境变量让同一份代码使用不同的地址和密钥：

```bash
API_BASE_URL=http://127.0.0.1:8080 npm run dev
```

语法因 shell 而异。环境变量适合本地临时覆盖，也常由容器和部署平台注入；密钥不要写进公开仓库。`.env` 文件是否自动读取取决于具体工具，不能假设所有命令都会加载它。项目文档应说明从哪个目录执行、配置来源优先级和缺失时的行为。

## 六、危险命令要先理解再执行

删除、覆盖、递归和权限修改操作可能不可逆。执行 `rm -rf` 前先检查当前路径和目标；避免变量为空时把删除范围扩大；不要把远程脚本直接管道给 shell；不要把含密码的命令复制进公开终端记录。可撤销的操作优先用 Git 或先备份。

一种好习惯是先用只读命令检查目标，再执行写命令。例如删除构建产物前先 `pwd` 和 `ls`；批量修改前先 `git status --short`；迁移前确认 `DATABASE_URL` 指向隔离目标库。安全来自知道命令影响的对象，而不是靠记住一份黑名单。

## 七、终端与图形界面各有优势

图形界面适合观察页面、浏览文件和发现视觉问题；命令行适合重复构建、测试、迁移、搜索和自动化。全栈开发不需要拒绝图形工具，也不能把核心步骤藏在只有自己知道的点击路径里。能写成 README 或脚本的流程，协作成本通常更低。

## 小结：先确认位置、命令结果和影响范围

每次运行前确认工作目录与目标；看清程序、参数和引号；检查退出码与完整错误输出；理解进程及环境变量；对删除、写库和部署命令先核实目标。终端熟练度不是命令数量，而是能解释每条命令会作用在哪里、失败时如何判断。
