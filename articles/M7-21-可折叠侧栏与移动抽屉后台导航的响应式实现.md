# 成为全栈·Vue 管理后台篇·可折叠侧栏与移动抽屉：后台导航的响应式实现

> 桌面用户希望收起侧栏给表格更多空间，手机用户则需要从顶部打开抽屉式导航。把宽度改成百分比并不能完成响应式导航：断点策略、状态持久化、路由后关闭、滚动锁定和键盘语义都要协同处理。

> 本文代码快照：Vue 后台提交 `d3ee41a`。主要参考 `manage-frontend-vue/src/layouts/AdminLayout.vue`、`src/stores/ui.ts` 和 `src/assets/main.css`。

## 前言：三种屏幕需要三种导航行为

后台侧栏占据固定空间。宽屏桌面可以显示完整导航，也可以由用户主动折叠；平板横屏空间有限，可自动切换为窄图标栏；手机则不应把侧栏压到 68px 后强迫用户猜图标，而应完全移出画面，在需要时以抽屉形式覆盖内容。

项目用两个响应状态表达：`desktopCollapsed` 处理桌面窄栏，`mobileOpen` 处理移动抽屉。`viewportWidth` 决定当前断点；桌面用户偏好持久化，手机抽屉状态是临时交互，路由跳转后自动关闭。

## 断点策略如何落实到代码

`AdminLayout.vue` 将屏幕宽度分为：

```ts
const isMobile = computed(() => viewportWidth.value < 1024)
const isTablet = computed(() =>
  viewportWidth.value >= 1024 && viewportWidth.value < 1280,
)
const desktopCollapsed = computed(() => ui.sidebarCollapsed || isTablet.value)
const mobileOpen = ref(false)
```

1024px 以下按移动布局处理；1024–1279px 为平板窄栏；1280px 以上采用桌面默认布局。CSS 与 JS 使用相同断点，避免按钮认为是 mobile、样式却仍显示桌面侧栏。

平板自动窄栏由 `isTablet` 派生，并未覆盖用户保存的 `sidebarCollapsed` 偏好；离开平板宽度后可以恢复用户原有桌面选择。手机状态则另外控制 transform/visibility 和 backdrop。开发时应在断点上下几像素实际测试，避免 1023/1024 之间产生布局闪烁或主内容宽度突变。

## 桌面折叠：保存的是偏好，不是视口推导结果

用户点击顶部的展开/收起按钮时，桌面调用 `ui.toggleSidebar()`。UI store 把 `sidebarCollapsed` 写入 `befull-admin-ui`，刷新后保留。窄栏状态隐藏文字和分组标题、保留图标并给链接补 title/aria-label，主内容左边距同步缩小。

响应式的关键是不要把自动断点结果也写回偏好。如果平板进入时强制持久化“折叠”，用户回到大屏后原本展开的偏好就丢失。持久化的是桌面用户主动设置；视口自动行为由计算属性决定。

## 移动抽屉：遮罩、导航后关闭和滚动锁定

移动端点击顶部菜单按钮，将 `mobileOpen` 设为 true；侧栏从屏幕左侧滑入，背景出现遮罩按钮。点击遮罩、品牌链接、菜单链接、路由变化或视口扩展到桌面时，抽屉关闭。打开期间设置 `document.body.style.overflow='hidden'` 防止背景页面滚动；关闭和布局卸载时恢复为空字符串。

路由变化监听 `route.fullPath`，因此同一菜单项查询参数变化也会关闭抽屉。视口变化时如果不再是 mobile，也关闭抽屉，避免用户横屏或调整浏览器尺寸后侧栏状态残留。

锁定滚动时必须处理组件卸载，否则 body 可能继续无法滚动；也要考虑多个 overlay 同时维护 overflow 的场景，更完整的应用可以使用统一滚动锁管理器，不让各组件互相覆盖恢复值。

## 键盘与辅助技术语义

顶部按钮设置动态 aria-label，例如“打开导航菜单”“收起侧栏”；遮罩是带有“关闭导航菜单”名称的 button；主导航使用 `nav aria-label`，菜单项是真正的 RouterLink，可由键盘聚焦和激活。折叠后链接通过 title 和 aria-label 保留含义，不只剩无名图标。

这些语义是基础，但完整移动抽屉的可访问性交互还可能要求 `aria-expanded`、`aria-controls`、焦点管理、Escape 关闭、焦点返回触发按钮和隐藏侧栏时阻止内部链接进入 Tab 序列。当前实现用 `aria-hidden` 标注未打开侧栏，但如需达到更完整的对话框式 drawer 标准，应进一步实现 inert/focus management 并做键盘实测。不要因为有 aria-label 就宣称焦点管理已全部完成。

移动 drawer 是导航而非 modal 时，也要根据产品语义选择正确 role；不要为通过检查而随意套 `role="dialog"`。语义应与实际键盘行为一致。

## 路由与权限菜单如何配合

侧栏菜单通过 `visibleMenuGroups(auth.user)` 按能力过滤，只有用户有对应权限时才创建链接。当前路径匹配后高亮活动项；点击个人资料后进入 ProfileLayout，退出登录时先调用 logout 再跳转登录页。

隐藏菜单只整理导航，不构成授权安全边界。用户直接输入 URL 时仍由 Vue Router 守卫检查角色能力；API 请求则由后端独立检查。导航布局不应复制另一份角色规则。

## 不能只验证某一个桌面宽度

建议至少检查：

| 视口 | 预期行为 | 关键验证 |
|---|---|---|
| ≥1280px | 完整侧栏或用户偏好折叠 | 主内容边距、tooltip、展开按钮名称 |
| 1024–1279px | 自动 68px 窄栏 | 文字隐藏、图标可识别、无水平溢出 |
| ≤1023px | 侧栏移出画面，按钮打开抽屉 | backdrop、滚动锁定、路由后关闭 |
| ≤600px | 更紧凑的顶栏和内容内边距 | 用户名称省略、操作按钮不挤压标题 |

再使用键盘完成打开菜单、Tab 遍历、激活链接、关闭抽屉和返回焦点的路径；检查 resize、路由跳转和页面卸载后 body overflow 恢复。组件测试可以覆盖状态转换，浏览器视觉 smoke 更适合检查断点和真实布局。

## 小结：响应式导航是状态机

完整导航不是单一 `collapsed` boolean，而是用户桌面偏好、视口断点、移动抽屉开关、当前路由和滚动锁定共同构成的状态机。桌面偏好可以持久化，平板自动窄栏不改写偏好，手机抽屉临时打开并在跳转后关闭。可访问性还需结合焦点行为实测，后端授权始终独立存在。
