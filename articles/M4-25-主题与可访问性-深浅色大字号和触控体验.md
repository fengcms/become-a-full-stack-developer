# 成为全栈·Flutter App 篇·主题与可访问性：深浅色、大字号和触控体验

深色主题不是把背景变黑就结束，大字号也不是把文字缩小到仍能塞进原来的卡片。颜色、触控、换行和内容密度一起变化时，小屏才真正考验设计令牌是否有用。

这篇从 `AppLayout` 的系统字体缩放和 ThemeExtension 开始，结合项目的 320–430dp 检查讨论可访问性取舍，并给出下一轮真机验收矩阵。

{{IMG:M4-25-封面}}

## 用户选择需要覆盖系统默认

项目支持跟随系统、浅色和深色三种模式，并持久化用户选择。跟随系统是默认策略，不等于“永远浅色”。切换主题只影响绘制，不应清空路由、文章、滚动位置或正在编辑的文本。

```text
ThemeMode.system / light / dark
→ ThemeBuilder 选择 ThemeData
→ ThemeExtension 提供产品语义色
→ Widget 使用语义而非硬编码色值
```

## 可访问性要覆盖内容细节

正文链接、引用、代码、表格、错误文案和输入框都要在两种主题可辨识。仅背景变暗而正文仍用浅灰，会让代码注释对比过低；仅凭色彩区分成功和错误，色觉差异用户也可能难以理解。

文字放大后，按钮标签应换行或调整，不应使用固定高度裁切；图标要有语义标签，不能只提供视觉形状。触控目标应考虑手指操作，而非只按图标绘制尺寸计算。

{{IMG:M4-25-主题矩阵}}

## 小屏验证要和大字号组合

项目记录在 320–430dp 宽度和 1.3 字体比例下做过布局检查。它证明这些指定视口/比例经过测试，不代表所有 Android 字体设置、平板折叠态或 iOS 辅助技术都通过。长标题、无头像、无封面、超长分类和表格比理想内容更容易暴露溢出。

Widget 测试适合检查断言和溢出，截图/模拟器检查视觉结果，真实设备与 TalkBack/VoiceOver 才能验证平台读屏和系统控件行为。

## 测试矩阵避免只看“亮/暗”两张截图

可以把验收条件拆为内容、主题、窗口和输入倍率的组合，而不是只截首页：

| 维度 | 至少检查 |
|---|---|
| 内容 | 正文代码、表格、评论、表单错误 |
| 主题 | system、light、dark |
| 窗口 | 320、375、430 dp |
| 字体 | 默认与项目已测的 1.3 倍 |
| 操作 | 触控目标、焦点顺序、语义标签 |

这张表有助于挑选有代表性的组合，并非声称项目已覆盖所有笛卡尔积。优先测试会改变布局结构的边界：窄屏 + 长标题 + 大字体，深色 + 代码块，错误态 + 输入焦点。颜色 token 的单元断言、Widget 溢出测试和真机读屏各自补足不同证据。

## 字体缩放策略不能靠统一压小字

Flutter `TextScaler` 会影响文本高度和换行。项目在 AppLayout 对最大缩放倍率有产品限制，同时测试 1.3 倍字体；这是一种体验取舍，并不等于系统字号完全无限放大。限制应在应用级统一应用，不能由页面分别缩小标题来“塞回原来的高度”。

需要对长按钮文字、字段错误提示、通知卡片和 Markdown 代码检查换行；代码通常保持横向滚动，普通正文则应随字号纵向扩展。图片替代文本和图标语义也应纳入 TalkBack/VoiceOver 真机验收计划。

## 设计令牌中有一项重要取舍：系统字体上限

当前 `AppLayout.maxTextScale` 为 1.3，通过 MaterialApp builder 统一夹紧系统文字缩放。它让原型在目标小屏保持结构，也意味着用户无法获得无限放大。文章应透明讨论这个选择：发布前可结合目标读者的可读性重新评估上限，并优先让容器高度自适应、允许换行，而非继续压低字号。

项目触控目标下限令牌为 44dp，页边距为 16dp；实际控件若图标视觉小，也可用透明 hit area 扩大触控区域。Accessibility inspector、TalkBack/VoiceOver 和键盘焦点路径仍需真实平台验收，不因尺寸 token 存在就宣称自动达标。

## 主题验收还要经过进程重启

用户选择深色后，Session 将 themeMode 存入 SharedPreferences；重启应用再恢复该值，才能证明设置不是仅存在于当前 Widget State。跟随系统模式则要切换 OS appearance 验证，不应被上次显式浅色/深色选择覆盖。

主题截图优先固定内容、模拟器像素密度和系统栏状态，避免不同数据长度造成误判。颜色对比度可以自动计算，但正文图像本身不应被强行反色；代码 token 在主题切换时重新映射样式，而不是沿用旧色值。


## 贴着工程代码读实现

下面这段节选自 `flutter-app/lib/app/theme/design_tokens.dart 第 1–69 行`（保留原始实现；为突出主线省略了文件其余部分）。读代码时可以顺着调用链确认：打开系统大字号并检查长中文、表单、底栏与错误提示。把这几步连起来，才看得到数据如何从服务边界走到界面。

```dart
import 'package:flutter/material.dart';

/// 4 基准间距刻度。移动端页面左右边距统一 [s4]（16dp）。
abstract final class AppSpacing {
  static const double s1 = 4;
  static const double s2 = 8;
  static const double s3 = 12;
  static const double s4 = 16;
  static const double s5 = 20;
  static const double s6 = 24;
  static const double s8 = 32;
  static const double s10 = 40;

  /// 页面左右边距
  static const double page = s4;

  /// 触控目标下限（docs/flutter-app/02 §1 硬要求）
  static const double minTapTarget = 44;
}

abstract final class AppRadius {
  static const double xs = 4; // 徽章、标签、小缩略图
  static const double sm = 6; // 输入框、次级按钮
  static const double md = 8; // 卡片、图片、按钮（默认）
  static const double lg = 12; // 底部面板、抽屉顶部
  static const double full = 999; // 头像、胶囊标签

  static const BorderRadius rXs = BorderRadius.all(Radius.circular(xs));
  static const BorderRadius rSm = BorderRadius.all(Radius.circular(sm));
  static const BorderRadius rMd = BorderRadius.all(Radius.circular(md));
  static const BorderRadius rLg = BorderRadius.all(Radius.circular(lg));
  static const BorderRadius rFull = BorderRadius.all(Radius.circular(full));
}

abstract final class AppDuration {
  static const Duration fast = Duration(milliseconds: 120); // 按下态
  static const Duration base = Duration(milliseconds: 200); // 淡入、展开
  static const Duration page = Duration(milliseconds: 250); // 页面转场
  static const Curve curve = Curves.easeOutCubic;
}

// ---------------------------------------------------------------------------
// 布局与系统字体缩放
// ---------------------------------------------------------------------------

/// 06 §3：字号单位是 sp，Flutter 侧的缩放由 `MediaQuery.textScaler` 承担。
/// 放大到 1.3 倍时正文（`AppType.reading`）不得横向溢出——
/// 这里夹紧上限，配合文本组件的 `maxLines` / `TextOverflow.ellipsis` 兜底；
/// 正文若被截断，应改为整体放大字号而非省略号截断。
abstract final class AppLayout {
  /// 允许的最大系统文本缩放倍数（06 §3 验收值）。
  static const double maxTextScale = 1.3;

  /// 挂在 `MaterialApp.builder` 上：
  /// `MaterialApp(builder: AppLayout.clampTextScale, ...)`
  static Widget clampTextScale(BuildContext context, Widget? child) =>
      MediaQuery.withClampedTextScaling(
        maxScaleFactor: maxTextScale,
        child: child ?? const SizedBox.shrink(),
      );

  /// 需要按缩放自适应间距时使用（缩放越大，留白同步放宽）。
  static double scaledSpace(BuildContext context, double space) {
    final s = MediaQuery.textScalerOf(context)
        .scale(1.0)
        .clamp(1.0, maxTextScale);
    return space * s;
  }
}
```

## 把容易出错的路径走一遍

我会用这个场景做一次可复现排查：**字号放大后按钮文字裁切或点击区变得过小**。先打开系统大字号并检查长中文、表单、底栏与错误提示；如果把问题定位在“固定高度控件”，修正方向是“控制排版缩放边界并保障触控目标，同时验证横竖屏布局”。最后再验证正常路径没有退化，并把边界条件留在自动化检查里。

| 方案比较 | 简化做法 | 当前实现/推荐做法 |
|---|---|---|
| 本文核心选择 | 固定高度控件 | 弹性排版与触控尺寸 |
| 错误处理 | 失败后清空或静默忽略 | 保留可恢复状态，给出明确反馈 |
| 验证方式 | 只检查成功结果 | 注入边界条件并检查回归 |

| 排错步骤 | 要观察什么 | 通过条件 |
|---|---|---|
| 复现 | 字号放大后按钮文字裁切或点击区变得过小 | 可以稳定触发或明确构造该输入 |
| 定位 | 打开系统大字号并检查长中文、表单、底栏与错误提示 | 找到责任层和状态归属 |
| 修正 | 控制排版缩放边界并保障触控目标，同时验证横竖屏布局 | 失败不污染后续页面或账号 |

## 小结

主题选择、语义色、文字缩放和触控体验相互影响。将主题规则沉淀在 ThemeData/ThemeExtension，避免组件硬编码；用多宽度、长内容和大字号验证。已测的设备范围要明确，不能以通过模拟器截图代表无障碍全面验收。
