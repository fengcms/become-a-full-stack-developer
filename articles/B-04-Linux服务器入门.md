# 成为全栈·基础补充·Linux 服务器入门

> 把程序放到 Linux 服务器上，不是把电脑“搬到云上”。你需要理解用户权限、进程、端口、文件、日志和服务生命周期，才能让一个应用安全、可控地运行。

## 前言：服务器也是一台需要维护的电脑

许多前端开发者第一次登录云主机时，会看到一个黑色终端和一堆命令。其实 Linux 服务器仍然是一台电脑，只是通常没有图形桌面，通过 SSH 远程管理，并由服务管理器长期运行程序。开发机上的“运行成功”要变成服务器上的“可持续运行”，中间还要处理进程重启、系统更新、端口、防火墙、文件权限、日志与备份。

本文先介绍最常用的服务器概念，不依赖某一家云厂商。不同发行版命令和服务路径可能略有差异，具体操作要以目标系统文档为准。

## 一、通过 SSH 远程连接

SSH 使用加密连接登录远端主机：

```bash
ssh deploy@example.com
```

这里 `deploy` 是远端用户，`example.com` 是主机名或 IP。首次连接时，客户端会提示确认主机指纹；在重要环境中，应通过可信渠道核对指纹，避免连错主机。身份验证可使用密钥，私钥保存在本机并限制权限，不能上传到服务器或提交到代码仓库。

不要长期用 root 账号运行 Web 应用。为部署建立权限受限的系统用户，只给它读取程序、写入必要目录和管理对应服务的权限。SSH 密码登录、root 登录、密钥轮换和网络访问策略都应根据服务器环境配置，不能假设云主机默认安全。

## 二、文件、权限和目录

Linux 的文件由所有者、所属组和权限位控制。`ls -l` 可以查看权限，`chmod` 修改权限，`chown` 修改所有者。常见权限 `755` 表示所有者可读写执行，其他用户可读和执行；`600` 表示仅所有者读写，适合敏感配置文件。

目录规划应区分程序、配置、日志和用户上传文件。程序发布目录通常由部署账号更新，服务账号只需读取；上传目录需要持久化并只允许服务写入。把所有文件都设置成 `777` 虽然能绕过权限错误，却让本机任何用户都能修改程序或数据。

`/tmp` 通常用于临时文件，不能作为唯一持久化存储；容器重建或系统清理后，临时内容可能消失。数据库文件、附件和用户上传目录要有明确持久化和备份方案。

## 三、进程、服务和日志

直接在 SSH 终端运行 `./server`，退出会话后进程可能停止。生产服务通常交给 `systemd` 等服务管理器启动、停止、重启和开机自启。服务配置应指定工作目录、运行用户、环境变量来源、重启策略和日志出口；更新程序后按流程重启并检查服务状态。

查看服务状态和日志的工具因发行版不同而异。以 systemd 为例，`systemctl status` 查看服务状态，`journalctl -u service-name` 查看日志。不要只在终端看到“started”就离开：检查端口监听、健康端点、数据库连接、文件权限和日志中是否有启动失败。

日志要有轮转或集中收集策略。若日志永远追加到一个文件，磁盘可能被写满；若故障日志没有请求 ID 和错误上下文，排查会很困难。日志中不得出现密码、Cookie、AppSecret 或完整访问令牌。

## 四、端口、防火墙和反向代理

应用监听端口供本机或代理访问。数据库端口通常不应直接对公网开放；服务端口也可以只绑定 `127.0.0.1`，由反向代理在外部接收 HTTPS，再转发到本机应用。

开放端口时先说明谁需要访问、从哪里访问，以及传输是否加密。云安全组和 Linux 主机防火墙是两层不同的控制面；只修改其中一处，流量仍可能被另一处拦截。反向代理还要正确转发 Host、协议和客户端地址，并确保应用只信任指定代理传来的转发头。

## 五、资源与容量的基本检查

部署后至少要知道 CPU、内存、磁盘和文件描述符是否充足。磁盘写满会让数据库无法提交、日志无法写入；内存紧张可能导致进程被系统终止；连接池过大可能耗尽数据库连接。服务“还在运行”不表示它有足够资源处理请求。

升级系统、重启主机和替换二进制前，要确认数据库备份、上传文件和配置不会随着程序目录一起被覆盖。备份不是只生成一个文件，还要定期在隔离环境恢复，确认它能用。

## 六、Linux 主机与 Serverless 的差别

自管 Linux 通常提供稳定进程、文件系统和主机权限，开发者负责补丁、进程管理、反向代理和容量；Serverless 或边缘 Worker 把运行环境、伸缩和部分网络管理交给平台，但会带来执行时长、内存、文件系统、原生模块和绑定方式等约束。

这不是“传统服务器落后”或“Serverless 自动更好”。项目选择取决于团队能力、数据库位置、访问模式和运维预算。即使应用部署在 Cloudflare，理解 Linux 对本地开发容器、数据库服务和未来自管部署仍有帮助；反过来，面向 Linux 设计的程序也不能不经验证就假设能运行在 Worker 环境。

## 七、第一次部署前的核对清单

- 服务器系统版本和架构是否与构建产物匹配？
- 程序由非 root 用户运行了吗？配置和上传目录权限正确吗？
- 服务能否开机启动、失败后有限重启、收到信号时优雅关闭？
- 数据库和附件是否持久化、备份并验证过恢复？
- 公网只开放必要端口了吗？HTTPS 和代理转发已检查吗？
- 日志是否可查看、会轮转、不会泄露秘密？
- 发布失败时，如何停止流量、恢复版本并核对新数据？

## 小结：先把运行边界弄清楚

Linux 服务器入门不只是记几个命令，而是理解 SSH 身份、权限、服务进程、端口、日志、磁盘和备份如何配合。让服务以最小权限运行，公开端口尽量少，部署流程可重复，并在发布前验证恢复路径。具体命令可以查手册，系统边界和数据责任必须先想清楚。
