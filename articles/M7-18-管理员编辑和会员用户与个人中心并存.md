# 成为全栈·Vue 管理后台篇·管理员、编辑和会员：用户与个人中心并存

> 一个“管理后台”不一定只服务管理员。会员也可能需要登录来修改资料、查看通知和收藏；编辑能管理内容，却不能管理用户和站点配置。本文分析 Vue 后台如何在同一工程中承载管理工作区与个人中心。

> 本文代码快照：Vue 后台提交 `d3ee41a`。主要参考 `src/router/index.ts`、`src/layouts/AdminLayout.vue`、`src/layouts/ProfileLayout.vue`、`src/pages/users/UserListPage.vue`、`src/pages/profile/` 与权限模块。

## 前言：用户角色不等于页面身份

用户管理和个人资料听起来都和“用户”有关，却是两种完全不同的业务域。管理员列表里编辑他人角色、禁用账号或重置密码；个人中心里用户只能修改自己的昵称、头像、密码并查看自己的通知、点赞和收藏。前者是管理权限，后者是个人资源权限。

项目有 member、editor、admin 三种角色。member 不能进入控制台，却可以访问 `/profile`；editor 可以处理文章、评论、分类和标签，但不能进入用户管理或站点设置；admin 才有更高权限。若将所有受保护路由都放到“只有 admin 能访问”的总门后，会员个人中心就永远进不来；若只判断“已登录”，编辑又可能访问管理员页面。

## 路由树既共享 App 外壳，也分开业务布局

Vue Router 将管理区放在 `AdminLayout` 下，并把 profile 作为同一路由树中的另一个嵌套布局。profile 的子路由有个人资料、修改密码、通知、点赞和收藏。不同页面共享顶层应用、主题、会话和导航，但可以拥有各自的内部导航。

路由守卫区分 `requiresAuth`、`consoleOnly` 与 `capability`。会员访问 `/profile` 通过身份检查；访问 `/articles` 被引导到 No Access；编辑进入 `/users` 因为缺少 users 能力而得到 403。管理员则可进入管理与个人页面。

这样的边界不需要复制一整套前端工程。共享请求内核、auth store、UI 主题和 API 模块；管理区和个人中心分别负责导航与页面组合。入口共享不代表权限或数据相同。

## 管理员的用户治理工作台

用户列表使用 `GET /users` 服务端分页，可按用户名/邮箱关键字、角色和账号状态筛选。管理者能够编辑用户角色、状态和等级，也可以通过 admin reset endpoint 设置新密码。重置时页面说明所有已登录设备会失效，并提示新密码需要通过安全渠道告知用户；它不会把新密码凭证回显到列表。

权限控制要求更细：用户管理和密码重置属于 admin 能力；editor 即便能够通过后台登录，也不应看到用户管理菜单或直接进入 `/users`。前端过滤入口、路由返回 403、API 后端校验共同构成体验与授权层次。

修改自身或他人的角色可能影响当前会话。若管理员将当前用户禁用，服务端令牌刷新后会拒绝；界面应处理账号禁用错误并清理会话，不能只更新用户表格状态。

## 会员的个人中心工作区

个人中心的页面都以当前登录用户为作用对象：

- **个人资料**：读取/更新昵称、邮箱和头像，用户名只读；成功后同时更新 auth store 中 user 并失效 profile query。
- **修改密码**：要求旧密码、新密码和确认值；服务端更改成功后撤销该用户其他 refresh token，页面提示其他设备退出。
- **通知**：分页展示当前用户通知，可标记单条或全部已读。
- **我的点赞**：读取本人点赞关联的文章列表。
- **我的收藏**：展示并允许取消收藏，成功后失效个人收藏 query。

这些功能的 API 路径使用 `/me/*` 或个人操作端点，由认证用户身份决定资源归属。前端不能让调用者通过普通表单指定别人的 userId 来查看他人私密数据，后端也不应信任这种参数。

## 同一类组件的表单不代表可以共用权限模型

用户管理和个人资料都有表单、保存按钮和错误提示，但业务 payload、校验规则与权限完全不同。`UserUpdate` 允许管理者改 role/status/level；`ProfileUpdateRequest` 允许本人改 nickname/email/avatar；密码修改单独要求 oldPassword 和 newPassword。把这些都包装成一个通用 UserForm 会模糊哪些字段由谁修改。

可以复用通用 UI（表单容器、头像上传组件、toast 约定），但 API 类型和权限规则必须表达真实边界。重置密码和用户自己改密码尤其不能共用一个 endpoint：前者是管理员救援流程，后者是用户证明旧密码后的自助安全流程。

## 数据缓存按主体和用途命名

Vue Query 使用 `['users', page, keyword, role, status]` 缓存用户管理分页，个人资料用 `['me', 'profile']`，通知、点赞、收藏用各自 `me` key。这样 mutation 后可以精确失效用户管理或个人工作区数据，避免把管理表格数据误当成自己的资料。

缓存 key 中的 `me` 也提示其主体是当前会话。如果在 SPA 里切换账号而未清理旧用户缓存，可能短暂显示上一位用户的数据。退出或换账号流程需要清理/隔离相关 query cache；当前应用退出会清 auth 状态，若产品支持无页面刷新切换账号，建议在会话变更时调用 query client 清理用户相关数据并验证。

这是客户端隐私边界，不替代服务端鉴权：即使缓存 key 区分了主体，服务器仍必须根据 token 返回当前用户自己的数据。

## 导航语义：No Access 与 403 的区别

No Access 是角色不属于管理控制台（member），但他仍可使用个人中心；403 则表示用户在控制台范围内，却缺少某一能力（例如 editor 进入用户管理）。404 是路径无匹配页面。登录页则只处理匿名态。

这些页面不只是技术错误码的装饰，而是告诉用户下一步做什么。会员应看到个人中心入口；编辑可继续管理文章而不是误以为账号异常；403 里可以说明需要管理员权限；404 可提供回仪表盘路径。

## 小结：同一应用里分出两个安全域

管理区关注全站资源和他人账号，个人中心关注当前用户的自有资源。两者共享 Vue 应用外壳和会话请求层，但路由要求、API、类型、缓存与可操作字段应保持清晰边界。角色能力函数、`/me` 契约和服务端校验共同支撑这条界线。
