# 成为全栈·Flutter App 篇·投稿状态机：草稿、待审核与已发布

> 投稿编辑器上的按钮并非任意组合。草稿、待审核和已发布文章在后端有不同的状态转换，APP 必须展示后端允许的动作，而不能自己发明“撤回投稿”。

{{IMG:M4-19-封面}}

## 本文目标

梳理会员投稿状态机和 Flutter 客户端动作映射，说明新增、保存、提交审核、发布后修改与删除各自的边界。

## 前置知识

了解 API 鉴权、表单提交和服务端状态机。实现位于 `features/editor.dart`、`features/member/member_articles_page.dart` 与投稿动作组件。

## 状态决定动作，状态不是一个可任意赋值的字段

用户能看到草稿、待审核和已发布稿件。创建草稿或提交审核是显式动作；更新普通内容时不应随手带 `status` 覆盖后端状态。待审核稿件编辑后继续待审核；已发布稿件修改会按后端规则重新进入审核流。

```text
新建 → draft
draft → 保存 draft / 提交 → pending
pending → 继续编辑仍 pending
published → 修改 → 后端转 pending
```

具体合法转换以 OpenAPI 与后端实现为准。APP 当前没有“作者自行撤回 pending”的能力，不能把产品文字写成已有功能。

{{IMG:M4-19-状态机}}

## 动作 API 比状态下拉更安全

界面根据文章状态展示明确按钮：保存草稿、提交审核、继续编辑或删除。动作函数构造最小请求载荷，不把 UI 当前枚举值原样当作权威状态提交。权限和所有权由后端复核；即使客户端检查 owner，也不能代替服务端授权。

## 创建成功后保留稿件 ID

创建请求成功后服务端返回 ID。之后保存和图片关联都使用同一稿件 ID；若上传失败，重试上传而不是再次创建文章。非幂等 POST 的响应丢失问题无法靠客户端猜测解决，应先查询或使用服务端幂等契约。

## 私有预览不调用公开阅读辅助接口

待审核稿件可预览，但它不应被放进公开文章缓存，也不能请求公开目录、上下篇并误以为已发布。私有预览要带会话访问、实时读取，响应不得进入公共磁盘缓存。

## 测试状态转换而非只测按钮颜色

隔离后端集成测试覆盖创建草稿、预览、提交审核及服务端状态变化。还要测试：待审核编辑不被误改为 draft，已发布修改的结果以响应为准，权限拒绝时页面保留输入，网络失败后不重复创建。

## 用动作函数表达允许的转换

可以在 UI 层把“状态判断”收敛为动作表，服务端仍要重新验证：

```dart
Set<ArticleAction> actionsFor(ArticleStatus status) => switch (status) {
  ArticleStatus.draft => {ArticleAction.edit, ArticleAction.submit},
  ArticleStatus.pending => {ArticleAction.edit},
  ArticleStatus.published => {ArticleAction.edit, ArticleAction.delete},
};
```

示例是产品规则示意，动作集合必须与后端实际能力及角色权限核对。关键是没有把 pending 伪装成可由作者撤回，也没有允许客户端直接任意设置状态。服务端返回新 status 后，再更新列表和详情缓存。

若编辑期间稿件在别处改变，提交前可比较更新时间并提示刷新；客户端的比较只是减少覆盖，不替代后端并发控制。

## 状态与本机缓存也需要同步更新

稿件保存成功后不能只关掉 loading。Repository 需要失效对应的 manuscript 列表和私有预览读取；若编辑期间列表还保留旧状态，用户返回后会看到“仍待编辑”或重复的待审核稿件。失败时则不能删除本机恢复副本，也不应把服务器文章标成已保存。

对状态冲突错误（例如后端提示稿件状态已变化），最安全动作通常是重新读取稿件状态，再给出可执行选项，而不是重复发送旧动作。错误码和 field errors 可把用户送回相关字段或状态提示。

## 已发布稿件保存前重新读取以检测冲突

当前编辑流程保存已有稿件前再次请求私有详情，并比较服务端 `updatedAt` 与进入页面时保存的值。不同则提示服务器稿件已变化，保留本机编辑内容并要求用户重新进入核对，避免静默覆盖其他会话的修改。

这是乐观冲突检测，不能保证严格原子性：另一个客户端仍可能在本次 GET 和 PUT 之间再次保存。真正的并发写保护需要服务端版本条件（例如 If-Match/ETag）或更新时比较版本字段。客户端检查减少常见覆盖，却不能承诺分布式锁。

## 小结

投稿是服务端状态机的客户端投影。按钮表达合法动作，载荷只提交需要修改的内容，服务端状态是最终事实。新建、编辑、预览和发布后修改都要分清公开/私有边界，不能把未实现的撤回能力写进界面承诺。
