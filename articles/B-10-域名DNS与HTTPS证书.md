# 成为全栈·基础补充·域名、DNS 与 HTTPS 证书

> 域名让人记住服务地址，DNS 把域名解析到网络目标，HTTPS 保护浏览器与服务之间的连接。三者经常一起配置，却属于不同层，排查时要逐步验证。

## 前言：输入网址到打开网站之间

浏览器输入 https://www.example.com/articles 后，先从 URL 中识别协议、主机名、端口和路径；DNS 查询主机名对应的网络记录；浏览器连接到目标服务并进行 TLS 握手；连接建立后才通过 HTTP 请求 /articles。任何一环出错，页面都可能打不开，但错误原因完全不同。

理解域名、DNS 和证书的职责，可以分辨“域名没解析”“证书不匹配”“服务没启动”“代理路由错误”这些看起来相似的故障。

## 一、域名是名称，不是服务器

域名是可读的名称层级，例如 www.example.com。DNS 中有不同类型的资源记录：

- A：将名称映射到 IPv4 地址。
- AAAA：映射到 IPv6 地址。
- CNAME：将一个名称别名到另一个名称，具体限制因 DNS 规则和服务商而异。
- TXT：保存文本验证或策略信息，例如服务商要求的域名所有权证明。
- MX：指定邮件接收服务。

记录配置错了，域名就会指向错误目标；记录已更新但缓存尚未过期，部分地区仍可能解析旧值。DNS 的 TTL 表示缓存可保留的时间，不是“全球同步倒计时”。

## 二、DNS 解析是逐层查询和缓存

客户端通常会先检查本地缓存，再向递归 DNS 解析器查询。解析器按 DNS 层级找到权威记录，并在 TTL 内缓存结果。浏览器缓存、系统缓存、路由器和公共解析器的刷新时间可能不同，因此刚修改 DNS 后，不同网络看到的结果未必完全同步。

常用诊断工具包括 dig、nslookup 或系统提供的 DNS 查询命令。检查时要明确查询的记录类型和解析器；只在自己电脑看到新地址，不代表所有用户已切换。反过来，DNS 已返回正确 IP，也只说明名称解析完成，目标服务仍可能没有监听或防火墙不允许连接。

## 三、HTTPS 用证书建立受保护连接

TLS 证书用于证明服务器控制某个域名，并协商加密连接。浏览器会检查证书链是否可信、有效期是否正确、证书名称是否匹配访问的域名。证书过期、漏配中间证书或访问别名未被覆盖，都可能触发安全警告。

证书通常由自动化工具或云平台申请并续期。自动续期配置后仍需监控：DNS 验证记录被误删、80/443 端口无法访问、权限变化或服务 reload 失败，都可能让证书最终过期。证书私钥必须受限保存，不能提交到 Git，也不能放入前端代码。

HTTPS 保护传输链路，但不自动证明应用没有漏洞，也不替代账号授权。网页启用 HTTPS 后，登录 Cookie 通常应设置 Secure；跨站和子域场景还需结合 Domain、SameSite 和请求架构验证。

## 四、DNS、证书和反向代理怎样配合

一个传统部署的常见链路是：

    example.com DNS → 公网入口 → Nginx/TLS 证书 → Web/API 服务

DNS 负责把域名引到入口；入口通过 TLS 证书建立 HTTPS；反向代理根据主机名和路径转发请求。DNS 不负责 URL 路径路由，证书也不会替代理启动后端进程。

如果站点经 CDN 或云平台代理，DNS 记录可能指向平台而不是源站 IP。TLS 也可能在边缘终止，再通过 HTTPS 或其他安全连接回源。此时要检查用户到边缘、边缘到源站两段连接，而不能只看浏览器地址栏的小锁。

## 五、排查域名和证书问题

1. 检查 URL 主机名是否拼写正确，是否访问了预期子域。
2. 查询 A/AAAA/CNAME 等记录，确认返回目标与当前部署一致。
3. 检查目标端口是否可连通，服务或代理是否监听。
4. 检查证书有效期、名称和证书链，分别验证根域和 www 等别名。
5. 确认反向代理虚拟主机、Host 头和路径规则匹配。
6. 查看服务商/CDN 状态以及本地、递归解析器缓存，避免只凭一台机器判断。

证书或 DNS 修改后，要等 TTL、清理相关缓存并从外部网络复测。不要同时改 DNS、证书、代理和应用配置，否则故障出现时很难知道是哪一步导致。

## 六、上线前检查清单

- 注册人和 DNS 控制台账号是否有可恢复的访问方式？
- 根域、常用子域、IPv4/IPv6 记录是否有意配置？
- TTL 是否符合迁移窗口，旧记录如何回退？
- HTTPS 证书是否自动续期并有到期提醒？
- 私钥权限和备份方式是否安全？
- CDN、反向代理与源站的 TLS、Host 和真实 IP 信任链是否明确？
- 若站点面向特定地区或接入特定平台，是否满足目标地区和平台的当前接入要求？

## 小结：按 DNS、连接、TLS、HTTP 的顺序排查

域名是名称，DNS 解析到网络目标，TLS 证书建立安全连接，HTTP 再承载请求。一个小锁图标不代表整条部署链路都正确。分别检查解析、端口、证书和代理路由，再结合服务日志定位，问题会更快收敛。
