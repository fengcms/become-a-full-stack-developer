# 原型还原与线上接口调整

日期：2026-10-02。用户反馈首版没有忠实还原已确认原型，并提供线上接口 `api-befull.kao9.com`。

## 数据来源纠正

首版运行环境为 `http://10.0.2.2:11002/api/v1`，数据来自独立本机测试库，不是线上数据。现在应用和 `tool/run_android.sh` 默认使用 **https://api-befull.kao9.com/api/v1**。

线上验证包含公开文章列表、正文、分类树、分类统计、标签、全文搜索、目录与公开作者资料。Android 集成验证直接使用线上 HTTPS，不通过本机后端转发。未在生产注册测试账号或写入验收稿件/评论；完整写流程仍连接显式指定的隔离 11002 环境。

刷新凭据按 API authority 命名，本机稿件恢复键包含 API 环境、账号和稿件，避免同 ID 的线上与本机账号混用。`flutter_reader / Reader123456` 仅为本机测试账号，不能用于线上登录。

## 唯一视觉依据

`prototype/02-高保真可交互原型.html`，直接读取其 CSS、页面结构和 SVG symbol。浏览器工具拒绝打开本地 file 协议，因此未绕过限制渲染该文件，也不将“已读取源码”表述为“浏览器视觉对照通过”。APP 的最终视觉检查基于模拟器测试截图。

- 原型 SVG 路径保存在 `flutter-app/lib/shared/prototype_icons.dart`，保留 24×24 viewBox、1.6 线宽、圆端点与圆转角，通过 flutter_svg 渲染。
- 原型的演示文章、计数、会员姓名与假缩略图不复制到线上。无封面的真实文章使用原型的无图列表样式。

## 模拟器网络问题

本机系统存在 7897 代理，原 AVD 无法解析线上域名。重启 Pixel 8 时设置 `-dns-server 1.1.1.1,8.8.8.8 -http-proxy http://127.0.0.1:7897` 后恢复解析并通过 Android 线上读取验证。该设置解决 DNS，但直连重复回归仍出现偶发连接超时；最终本机 debug 构建显式传入 `DEV_HTTP_PROXY=10.0.2.2:7897`，由 Dio 的标准 HttpClient 代理连接。此参数只在 debug 生效且默认为空，release 忽略；没有硬编码代理、证书放行或 TLS 绕过。

### 最终启动配置

正常入口为 `lib/main.dart`，不是集成测试入口。本机启动命令：

```bash
DEV_HTTP_PROXY=10.0.2.2:7897 ./tool/run_android.sh
```

API 默认线上 `https://api-befull.kao9.com/api/v1`。发布与其他网络正常的环境不需要 `DEV_HTTP_PROXY`。更换主题从「我的 → 设置 → 外观」进入；登录使用已有线上会员账号。
