# M4 原型门禁

第二轮评审 N-2-5 的整改：把原先「只在回复里写了命令、脚本却不在库里」的四道门禁
落成可被第三方复跑的脚本。零第三方依赖（Node 侧只用 Node 22 内置的 `fetch` 与
`WebSocket` 驱动系统 Chrome；Python 侧只用标准库）。

## 一键复跑

```bash
bash docs/flutter-app/prototype/gates/run_all.sh
```

全部通过退出码 0，任一失败非 0。找不到 `node` / `python3` 时脚本会明确报错，
不会静默跳过——**跳过比失败更危险**。

可覆盖的环境变量：

| 变量 | 作用 |
|---|---|
| `NODE_BIN` | 指定 node（默认探测 PATH，其次托管运行时） |
| `PY_BIN` | 指定 python3（默认探测 PATH，其次托管 venv） |
| `CHROME_BIN` | 指定 Chrome/Chromium 可执行文件 |
| `M4_KEEP_SANDBOX=1` | 保留 Chrome 沙箱。**默认关闭**：本机/容器里沙箱初始化失败会连带拖垮网络服务，CDP 端口起不来。仅测试受信任的本地 file:// 页面，风险可接受。 |

### 门禁 6 的存在理由：让「不重复色值」这个选择成立

`07-UI组件标准.md` 为了「改色只改 06 一处」而**不写任何色值**，只引用令牌名。这个选择有一个隐含前提：
**引用的名字必须真实**。名字写错不会报错、只会让开发 AI 凭空造一个不存在的令牌——门禁 6 就是那条前提的机器化。

因此 `§12 差异登记` 一节**豁免**第 ② 项：该节按定义会点名「06 里没有的令牌」（如 `color.skeleton`），
一并扫会误报。其余章节一律在扫描范围内——**正是这个范围让它能发现漂移**。


## 目录锚点：形态要求与回归探测（第三轮 A-1）

产品侧已冻结（`01 §2`、`03 §6`）：**正文标题的可寻址 key 必须用服务端 `/toc` 返回的 `anchor`，
客户端不自行生成锚点、不自行 slug 化**。原型据此把 `SECTIONS[i].anchor` 当服务端返回来用，
`TOC` 与契约 `TocItem` 同形（`level` / `text` / `anchor`）。

`probe.mjs` 为此加了两条断言，用于防止退回旧写法：

| 断言 | 拦什么 |
|---|---|
| 正文标题 id 与 `TOC.anchor` 逐条相等且同序 | 正文与目录各写一份锚点（双源漂移） |
| 锚点不得是本地序号形态 `h-数字` | 退回「客户端自造锚点」——正是 A-1 的原始缺陷 |

### ⚠️ 这两条断言的能力边界（第四轮 A-7，别过度解读）

| 断言 | 构造上的真实能力 | 读成什么会出错 |
|---|---|---|
| 正文 id 与 `TOC.anchor` 逐条相等 | 二者**同源于 `SECTIONS`**，因此**构造上必然成立**。只能拦「两处各写一份锚点」 | 被当成「锚点口径已与服务端对齐」的证据 |
| 锚点不得是 `h-数字` | 只拦 `h-` 加数字这**一种**回退形态；换成 `sec-1` / `heading-1` 等其它本地编号，两条断言都会通过 | 被当成「不会退回自造锚点」的保证 |

**再强化也只能到此为止**：要断言「锚点与服务端一致」，客户端就得知道服务端的 slug 算法，
而契约并未公开该算法（`03 §6` 明确「不自行 slug 化」）。**所以「配对规则成立」的证据
只能来自 Phase 2 用含重复标题 / 代码块内 `#` 行 / Setext 标题的夹具文章实测。**

> **门禁全绿 ≠ 目录可上线**。本原型的 mock 不具备上述三类边界样本，能跳转只说明 UI 交互形态成立。

**已做过注入回归**：把正文模板改回 `id="h-${i+1}"` 后，交互门禁 **50/54**、退出码 1，
精确报出 `命中 ["h-1","h-2","h-3","h-4","h-5"]`；且此时目录点击会**如实提示
「这一节在当前正文里没有对应位置」而不是谎报成功**。还原后 54/54。

第四轮又对 A-8 的新断言做了一次注入（把可选端点塞回主栏）：**54/56、退出码 1**，
两条断言都精确报红；同时暴露出**断言失败信息指错了子句**（实际是 `可选栏存在=false`，
detail 却只打印了 `主栏含 related`），已改为逐条子句打印。还原后 56/56。

## 第五轮：UI 层面调整的回归探测器

本轮响应 owner 的四项 UI 调整（图标变形 / 六入口改 Cell / 资料页与设置页分拆 / 出组件标准），
顺手抓出并修掉三处**原型自身**的缺陷。每一处都配了能复现的断言。

| # | 缺陷 | 怎么发现的 | 证据 | 断言 |
|---|---|---|---|---|
| P1 | 设置页单选项渲染成破图形（勾戳出圆外、圆点吊在圆下） | 目视 + 几何量测 | `.radio` 是 `display:grid; place-items:center`，含 **2** 个子项（勾选图标 14.5 + `::after` 圆点 10）→ Grid 排成**两行** → 内容总高 24.5dp 溢出 22dp 圆框 | `probe`：子元素数 = 0、圆框 22×22、选中/未选中 `::after` 的 `scale` 取值；`check_ui_standard` F6 拦「又塞了子元素」 |
| P2 | 次级按钮边界用了 `color.line.strong`，而 06 §6.1 与 `app_theme.lineButton` 都指向 `color.line.button`；原型**根本没有** `--line-button` 变量 | 令牌对齐核对 | 见 `07 §12-D3` | `probe`：`.b.sec` 计算边界 === `var(--line-button)` 计算值 **且** ≠ `var(--line-strong)`；`check_ui_standard` F2/F3 拦「令牌无消费方 / 用错令牌」 |
| P3 | 06 §5 已声明 `duration.fast/base/page`，原型却把 6 处时长写成 `.2s/.18s/.24s` | 令牌消费面盘点 | 见 `07 §12-F4` | `check_ui_standard` F1/F4 拦「时长裸写」「令牌定义位置不符作用域」 |

### 踩坑记录（这两个坑值得单独说）

1. **`.radio` 的 Grid 溢出：`place-items:center` 不代表"都叠在中间"。**
   两个子项会被排成两行，容器高度不变、内容溢出到边框外。**多子项一律不要指望 Grid 居中叠放**——
   要叠就用 `Stack` 或单伪元素。这条已写进 `07 §11-A2`。

2. **断言「A ≠ B」时必须先确认 A、B 在当前取样环境里本来就不等。**
   门禁 6 第一次跑，P2 的断言报红，值却是三个相同的 `rgb(58,71,84)`——那是**深色主题**的值。
   原因是上一节测试结束时主题停在「跟随系统」，而无头 Chrome 解析成了深色；而
   **深色下 `color.line.button` 与 `color.line.strong` 本来就同值**（06 §2.4 未给 lineButton 深色取值）。
   断言没错，是**取样时机**错了。修法是先把主题切到浅色再量，并额外加一条
   「取样前确实是浅色」的前置断言——否则这条断言在深色下会**恒真或恒假**，等于没测。

## 设计约定（踩过的坑，别再踩）

1. **期望值能程序化推导就绝不手写。** 路由表、字段表、端点表一律从被测对象自身抽取。
   手写清单最坏的结果不是报错，而是**把「清单写错」伪装成「测试通过」**——
   第一轮就发生过：手写路由清单虚高为 21/21，其中 2 条路由根本不存在。
   （第三轮又抓到一处漏网的：目录锚点曾被写死为 `['h-1'…'h-5']`，改锚点方案后直接失效，已改为从 `TOC` 派生。）
2. **测真行为，不测提示文案。** 目录跳转要看 `scrollTop` 有没有变，不能只看
   toast 说了什么；复制链接要看失败时报的是不是失败。
3. **断言「某文本已消失」必须先排除 `<script>` 源码。** `<script>` 就在 `<body>` 里，
   用 `body.textContent` 断言会恒为真。
4. **源码级 `grep` 断言要防止被「注释里复述旧代码」救活。** 验收 `grep -c 'id="h-'` 期望 0 时，
   注释里若写了 `id="h-N"` 就会命中。改注释措辞使关键词不出现在文中，而不是放宽断言。
5. **`grep` 的或运算一律用 `-E`。** macOS 是 BSD grep，`"a\|b"` 不是或运算而是字面量，
   会给出假阴性（第二轮排查 N-2-3、第三轮排查锚点表述时都踩到）。
6. **模板字符串里的断言不能带具体的运行时插值结果。** 源码写的是 `` id="h-${s.n}" ``，
   数字在运行时才插值，所以 `grep -E 'id="h-[0-9]'` **恒不命中**——是无效断言，
   会制造假绿。要断言就得用不含插值的字面前缀（`id="h-`），或改在运行时断言。
   加完新断言**先跑一遍确认它会红**，否则等于没加。**失败信息必须能指出是哪一条子句不成立**：
   第四轮我把三条子句用 `&&` 串起来、detail 只打印了其中一条，注入回归时就出现了
   「报的原因不是真正不成立的那条」——多子句断言的 detail 要逐条打印。
7. **本阶段 Dart 侧只有 `dart format --output=none` 可用。** 没有 `pubspec.yaml` 时
   `dart analyze` 会报几百条未解析符号，那是环境缺失，不是文件缺陷——别被 374 条吓到。
8. **结构化字段里不塞说明文字。** `api:[...]` 的元素必须严格是 `<方法> <路径>` 两段，
   解析按第一个空格切分，路径带尾巴去比对契约就成幽灵端点。第四轮实测：给
   `GET /articles/{id}/related` 加个「（本阶段不实现）」后缀 → API 门禁立刻 FAIL。
   要做语义区分请用**独立字段**（如 `apiOptional`），并让门禁一并扫它——
   否则「可选」就成了幽灵端点的后门。
9. **测不到的断言宁可不加，也别加恒绿的。** 目录层级断言在 mock 只到 2 级时无法证伪
   `level ≥ 3` 的行为；硬加一条只会制造虚假安全感。**能力边界写进注释，比假装覆盖到更诚实。**
10. **手搓解析器必须用「完整命令表」，不能按需处理。** 审图标弧线时我的临时脚本连错三次
    （`a` 命令参数下标错、`M`/`L` 不更新当前点、漏了 `s` 命令导致误报 `i-heart`）——
    每次都表现为「报出一个看起来很真的缺陷」。正式门禁里给每条 SVG 命令写明参数个数
    （`ARITY` 表）并展开隐式重复，才收敛。**临时脚本的结论一律不可信。**
11. **改令牌/时长这类"全量替换"必须带命中次数断言。** 本轮替换 6 处动效时长时，
    第一版脚本假设 `transition:background .2s;` 出现 2 次，实际是 1 次（另一处紧跟 `}`）。
    断言当场拦住、脚本整体未写盘——**先断言再写盘**的顺序救了一次。

## 已知例外与待办（脚本会打印，不做静默放过）

- `GET /files/{key}`：附件静态中转挂根路径、不带 `/api/v1`，不在契约 `paths` 中（M1 部署实测）。
- `06-UI设计规范与设计令牌.md` 未在 §2.1~2.4 写明的 Dart 字段：`codeBg`、`codeFg`、`skeleton`
  ——属规范缺口（规范没写的，不算 Dart 的错），脚本单独列出提醒补规范。
- `color.line.button` 的**深色取值** 06 §2.4 未定义，Dart 侧暂沿用深色 `lineStrong`，待确认。
- **目录失败态是否进产品侧口径**（第四轮 A-5）：真实实现里 `/toc` 是独立请求，产品侧 `02 §3`
  的状态枚举当前只有「图片失败 / 404 / 离线」。原型**刻意不新增**这个冻结口径里没有的状态，
  只在注释里声明假设。属跨侧待决项。
- **目录最多支持几级**（第四轮 A-6）：契约 `TocItem.level` 是 1-6，但页面只有 h2~h6 五格可落，
  `level=6` 会派生出非法标签 `h7`。原型正文只演示 1-2 级，`level ≥ 3` 的取法未冻结，待 owner 定。
- `GET /articles/{id}/related` 在 `apiOptional` 里，**本阶段不渲染相关文章模块**，仅登记契约存在。
