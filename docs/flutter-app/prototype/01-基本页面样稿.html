一套后端双部署：适配层如何让一份代码跑在两套运行时

全 成为全栈 2026-09-30 · 2.4k 阅读 · 128 赞
Cloudflare Workers 与普通 Linux 的差异不在语法，而在请求、存储与生命周期的边界。这篇文章把适配层拆开讲清楚。

同一份 Hono 代码，要同时跑在 Cloudflare Workers 和一台普通 Linux 机器上。硬编码运行时判断会让代码迅速腐烂，正确的做法是把差异收敛到一层薄的适配接口。

一、差异从哪里来

运行时差异集中在三处：环境的读取方式、文件存储的位置、以及后台任务的调度能力。把它们列成一张表，适配层的边界就清楚了。

能力WorkersLinux
环境变量env 绑定process.env
对象存储R2 绑定本地磁盘目录
定时任务Cron Triggers外部调度器

二、把差异收敛成一个接口

适配层只暴露能力，不暴露实现细节。调用方永远拿到的是一组稳定的函数签名。

storage.tsTypeScript
// 两种驱动，一个契约
export interface Storage {
  put(key: string, body: ReadableStream): Promise<void>;
  get(key: string): Promise<ReadableStream | null>;
}

export const createStorage = (driver: "r2" | "local"): Storage =>
  driver === "r2" ? r2Storage() : localStorage();
适配层不是抽象层。它只解决"同一件事在两套运行时怎么做"，不解决"以后可能换别的什么"。

代码块与表格的移动端折行策略

桌面端可以横着铺开的代码块和表格，到了 393dp 宽度上必须换一种活法：代码块整体横向滚动、不折行，行号才能对齐；表格则包一层可横滑的容器，超出的列不给省略号，避免把数据藏起来。

两者都不能撑破正文宽度——一旦撑破，整页跟着横向滚动，正文的阅读节奏就断了。

错误码到用户文案的映射

同一个失败在两套运行时下的表现并不一致：一方抛结构化错误码，另一方可能直接抛底层异常。适配层的职责是把它们压成同一组错误码，页面只认这组码。

映射表集中在一个文件里维护。页面上不允许出现「按错误消息文本判断分支」的写法——那等于把后端文案当成了契约。

三、收敛成本

把差异收敛之后，业务代码里不再出现任何运行时判断。部署到 Cloudflare 只是换一个环境变量，而不是换一份代码。
