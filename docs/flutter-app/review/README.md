### 门禁版本说明（重要：三代尺子都保留）

| | v1 `check_code_quality.py` | v2 `check_code_quality_v2.py` | v3 `check_code_quality_v3.py` |
|---|---|---|---|
| 函数解析 | 逐行正则，**只认单行签名** | 从 `{` / `=>` 回溯 | 从 `{` / `=>` 回溯 + **括号深度感知** |
| 多行签名 | ❌ | ✅ | ✅ |
| 箭头表达式体 | ❌ | ✅ | ✅（且终止符深度感知，不被内层 lambda 的 `;` 截断） |
| **命名参数组长函数** | ❌ | ❌ | ✅ |
| 嵌套口径 | 花括号深度（虚高） | 花括号深度（虚高） | **仅控制流分支块** |
| `lib/app/theme/` 长函数 | 计入 | 计入 | 排除（配置型，单独登记） |
| 量程后果 | 报「>80 行 8 个」，真实 **13** 个 | 报「最大 79 / 0 个」，真实 **6** 个（`eda7860` 基线真实 **11** 个） | 整改前 `PASS=13 / FAIL=2`，整改后 15/15 |
| 定位 | **保留**，第一轮基线可比 | **保留**，第二轮基线可比 | **第三轮起的验收依据** |

> 三代尺子的差异本身就是最大发现：**每修掉一个盲区，真实数字就往上跳一次**。
> - v1 → v2：第一轮报告「>80 行 8 个」低估（真实 13 个），详见第二轮报告 §6；
> - v2 → v3：第二轮报告「4 个」同样低估（`eda7860` 真实 11 个），根因是**命名参数组 `{...}` 的 `}` 被误当语句边界**，详见第三轮报告 §4。

第三轮增加 [Dart AST 独立检查](check_dart_ast.dart)（作者实现，评审方独立复跑），复核声明长度；运行方式和口径见第三轮回复。评审提供的 v1/v2/v3 脚本保持原样。

> **结项时的三法交叉验证**：我的 v3（括号深度感知词法）、我的宽网探针（括号配对）、作者的 AST（Dart analyzer 真语法树，含匿名闭包，908 个声明为最宽的一张网）三种实现路径同报「非主题 >80 行 = 0」。三法一致后，该指标方可判定成立——详见 [结项确认](M4-开发AI代码审阅结项确认.md) §3。
