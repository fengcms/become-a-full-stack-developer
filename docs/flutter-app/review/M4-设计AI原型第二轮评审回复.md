## 1. 逐项处置

### N-2-1 🔴 目录点击不滚动却报「已定位」

**复现方式与报告一致**：正文标题无 `id` 锚点、全文件无 `scrollIntoView`/`scrollTo`，`case 'toc'` 的非 `panel` 分支只做 `render()` + 报成功。这是**功能缺失 + 谎报成功**，和 B-1 举报 toast 同族。

**我没有做「最小补丁」，而是先解决一个更根子上的问题。** 补锚点时查了正文结构：

```
TOC 条目 5 条  ←→  正文标题只有 3 个 <h2>   →  条目 3、4（两个二级标题）根本没有对应标题
```

也就是说，**即使我按报告的最小建议给现有标题加 id，5 条目录里仍有 2 条点不动**——而这 2 条恰好是 TOC 里标注 `lv2:true` 的那两条。旧版之所以没暴露，是因为点了也只弹 toast，看不出差别。

**所以我把「目录」和「正文」改成同源派生：**

```js
const SECTIONS = [{n:1, t:'一、差异从哪里来', html:`…`}, …, {n:3, t:'…', lv2:true, html:`…`}];
const ARTICLE_BODY = SECTIONS.map(s => {
  const tag = s.lv2 ? 'h3' : 'h2';
  return `<${tag} id="h-${s.n}">${s.t}</${tag}>${s.html}`;
}).join('');
const TOC = SECTIONS.map(s => ({n:s.n, t:s.t, lv2:!!s.lv2}));
```

标题 `id` 由 `n` 生成，目录也由同一份 `SECTIONS` 生成——**二者在构造上不可能再不同步**。同时补上第 3、4 节的正文内容与 `.prose h3` 样式，`h2`/`h3` 层级现在与目录标注的「一级/二级标题」真正对得上。

**滚动实现**（`scrollToSection`）：不做 `scrollIntoView`，而是直接算 `#screen` 的相对位移后赋值 `scrollTop`——`#screen` 是本原型的滚动容器（`render()` 里就是用它做 `scrollTop = 0`），显式赋值在无头环境下也可确定性断言。

**不谎报**：拿不到锚点时返回 `false`，调用方改报「这一节在当前正文里没有对应位置」，并**不滚动**。与 B-5 复制链接同一原则。

> 顺带说明：`02 §4` 要求「目录优先使用 `GET /articles/{id}/toc` 返回的服务端目录」。`SECTIONS` 的注释里已写明它是该接口返回结构的 mock，`notes.api` 也一直标注着 `GET /articles/{id}/toc`——开发 AI 照抄时不会以为目录要在客户端硬编码。

## 2. 我在本轮额外发现的两项

### 2.1 🟡 「删除评论」在原型里完全不可达（评审与我上一轮都漏了）

**是新的门禁脚本把它抓出来的。** 写 `probe.mjs` 时我按「测真行为」写了一条断言——「我发的评论都有可点的删除入口」——结果它红了。

**根因**：`cmt-del` 按钮的渲染条件是 `c.userId === ME.id`，但**只写在顶级评论**的模板里；回复的模板只有「回复」按钮。而种子数据里 `ME.id = 1`：

- 顶级评论的 `userId` 是 7 / 9 / 11 —— **都不属于「我」**；
- 「我」唯一的一条评论是 id:2，它是一条**回复**。

→ 两条路都断：顶级没有我的评论，回复不渲染删除按钮。**「删除评论」这个流程在原型里没有任何入口**，与第一轮 B-2「复核中徽章不可达」是同一类缺陷。

**修法**：按契约语义补在自己的**回复**上也渲染删除入口（`DELETE /comments/{id}` 级联删除，作者有权删自己的评论，回复也是评论）。措辞与顶级一致：「删除后其所有回复会一并删除，不可恢复」。

**并把它固化成断言**（防止再退化）：

```
我发的评论都有可点的删除入口（删除流程必须可达）  — 我的评论 1 条 / 删除入口 1 个
```

> 教训：**「不可达的 UI」这类缺陷，靠肉眼审 UI 很难发现，靠断言很容易。** 本轮它能被抓出来，是因为写断言时被迫先回答「这个按钮在什么条件下会出现」——一回答就发现条件永远不成立。建议后续评审把「每个可交互控件的最小达成条件是否真的可达」也列成一项（用种子数据代入验算）。

### 2.2 🟡 `color.line.button` 规范有、Dart 无 —— B-6 实际是 3 项不是 2 项

写 `check_dart_tokens.py` 的 D 项（与 `06` 规范逐值比对）时发现的。第一轮 B-6 判定「Dart 令牌缺口 2/2」已闭环，但把 `06 §2.1` 里**写明的每一个色值**拿去和 Dart 侧比，发现：

## 3. 关于「自陈与实测不一致」——不辩解，给机制

- **B-7.2 那次**：我把「加了入口」当成了「解决了痛点」。实际上痛点是「想跳章节要先滚到文末」，入口做出来但点不动，**收益是 0**。这是典型的「交付了动作、没交付结果」。

所以本轮我做的不只是改这两处，而是**把这两类错误各自变成一条机器断言**：

| 自陈失效的类型 | 现在由谁兜住 |

| 「我加了入口」≠「功能生效」 | `probe.mjs` 断言 `scrollTop` 位移 > 100，而不是断言 toast 文案 |

| 「字段都对」≠「每个展示字段都有 schema 支撑」 | `check_dart_tokens.py` D 项逐值比对 + 报告建议的 schema 审计维度 |

这样下一个接手的人不需要相信我的自陈——**跑一遍就知道**。这也是 N-2-5 我全力支持入库的原因：门禁入库的价值不在于「更方便」，而在于**把「可选相信」变成「可被推翻」**。

## 4. 本轮的坑（都写进了 `gates/README.md`）

1. **BSD grep 的 `\|` 不是或运算。** 复核 N-2-3 时我用 `grep "a\|b"` 得到 0 命中、一度误判报告写错。macOS 上是 BSD grep，`\|` 是字面量；或运算必须 `grep -E`。**这是同一个坑的第二次**（第一轮评审侧记过，我这轮又踩），已写进 README 的「设计约定」。
2. **探针自己的断言写错两次**（都是我的问题，不是原型的）：
   - 假设「评论一定有删除按钮」→ 实际种子数据下不可达，**但这次假失败反而暴露了真缺陷**（§2.1）；
   - 把「被拒反馈条」自身的文案「评论**未通过**审核」当成了审核态徽章 → 断言要排除反馈条本身。**提醒：断言「某文案不存在」时，先确认它没被另一处合法文案命中。**
3. **`f-string` 里引号嵌套写错导致 SyntaxError。** 三处 `f'… {x or "无"}'` 被我写成了以 `"` 收尾。教训：**f-string 里少用同型引号**，这类错误会以「unterminated f-string」的形式报在别的行上，排查费时。正则里也有同类：`docstring` 内的 `"""` 与 `'''` 混用要留意。
4. **沙箱与代理。** 无头 Chrome 在本机需要 `--no-sandbox` + `--no-proxy-server` 才能起 CDP；这两条不写，脚本会在「Chrome 启动」这一步静默卡死（表现为 Node 的 `unsettled top-level await` 警告 + 退出码 13）。
