## 2. 本轮新发现

### 🔴 2.1（P1）原型自造锚点 `h-N`，与产品侧**刚冻结**的「锚点值采用服务端 `anchor`」直接冲突

**事实链（双侧取证）：**

**设计侧**（`02-高保真可交互原型.html`）：

- L1132-1136 注释：
  > 真实实现里目录来自服务端 `GET /articles/{id}/toc`（见 `02 §4`），本原型用同一份 `SECTIONS` 同时生成「正文标题」与「目录」…**每个标题的锚点 id 固定为 `h-N`**，目录点击即滚到该锚点。
- L1170-1173 实现：
  ```js
  const ARTICLE_BODY = ARTICLE_LEAD + SECTIONS.map(s => {
    const tag = s.lv2 ? 'h3' : 'h2';
    return `<${tag} id="h-${s.n}">${s.t}</${tag}>${s.html}`;
  }).join('');
  ```
- 我实测：`proseHeadings = ["H2#h-1","H2#h-2","H3#h-3","H3#h-4","H2#h-5"]` → **锚点值是自造的序号，不是服务端值**

**产品侧**（已冻结 `18da8b9`）：

- `01-技术方案与工程边界.md:18`：
  > 「…正文渲染器为标题建立可寻址的 Widget key，**key 值采用服务端 `anchor`**；客户端不自行生成目录数据，**也不自行 slug 化**」
- `03-接口映射与数据约束.md:13`：
  > 「渲染器为标题生成锚点、**锚点值采用服务端 `anchor`**，客户端不自行 slug 化（契约未公开 slug 规则）」
- `03-接口映射与数据约束.md` §6「目录锚点配对规则」行：
  > 「…**锚点值采用服务端返回值，不自行 slug 化**」

**契约**：`TocItem.anchor` = 「锚点 id（**slug 化标题**）」。

**为什么这是 P1 而不是措辞问题：**

产品侧 N-18 刚刚把这条链闭合了三段：**数据源统一**（都读 `/toc`）→ **定位算法统一**（顺序配对）→ **锚点值来源统一**（用服务端 `anchor`）。
原型的演示代码**前两段是对的**（`SECTIONS` 同时派生正文与目录，天然顺序配对），**第三段反了**：它示范的是「客户端自造锚点」。

**具体后果**：开发 AI 照抄 `id="h-${s.n}"` 这个模式，在 Flutter 里就会给标题挂 `Key('h-1')` 之类的自造 key，而服务端返回的 `anchor` 是 slug 化标题 → **两者永不匹配 → 目录点击定位失效**，且**在原型里看不出来**（原型的锚点是自己生成的，当然能对上）。

**这与设计 AI 自己的声明有关**：回复 §1 N-2-1 写：
> 「`SECTIONS` 的注释里已写明它是该接口返回结构的 mock…**开发 AI 照抄时不会以为目录要在客户端硬编码**」

这个判断**对了一半**：注释确实覆盖了「目录**数据**」的来源，**但没有覆盖「锚点**值**」的来源**——反而用「锚点 id 固定为 `h-N`」把错误做法**固化成了明确说明**。加上产品侧冻结口径晚于/同期于该注释，这一处属于**跨侧未对齐**（非设计 AI 单方过失）。

**低成本修法见 §4 调整清单 A-1（推荐方案 A，约 5 行）。**

### 🔴 A-1 · 收 P1 · 锚点值改为取自服务端 `anchor`（演示正确做法）

**落点**：`prototype/02-高保真可交互原型.html` L1132-1136（注释）+ L1137-1168（`SECTIONS`）+ L1170-1174（`ARTICLE_BODY`/`TOC`）+ L2014-2021（`scrollToSection`）

**推荐方案 A（演示正确做法，约 5 处改动）**

1. **`SECTIONS` 每项增加 `anchor` 字段**，值取 slug 形态（模拟 `/toc` 返回值），例如：
   ```js
   {n:1, anchor:'yi-cha-yi-cong-na-li-lai', t:'一、差异从哪里来', html:`…`},
   {n:2, anchor:'ba-cha-yi-shou-lian-cheng-yi-ge-jie-kou', t:'二、把差异收敛成一个接口', html:`…`},
   {n:3, anchor:'dai-ma-kuai-yu-biao-ge-de-zhe-hang-ce-lue', t:'代码块与表格的移动端折行策略', lv2:true, html:`…`},
   {n:4, anchor:'cuo-wu-ma-dao-yong-hu-wen-an-de-ying-she', t:'错误码到用户文案的映射', lv2:true, html:`…`},
   {n:5, anchor:'shou-lian-cheng-ben', t:'三、收敛成本', html:`…`}
   ```
2. **正文用 anchor 作 id**（不再用 `h-${n}`）：
   ```js
   return `<${tag} id="${s.anchor}">${s.t}</${tag}>${s.html}`;
   ```
3. **`TOC` 带上 anchor**，与契约 `TocItem` 的 `level/text/anchor` 三字段对齐：
   ```js
   const TOC = SECTIONS.map(s => ({n:s.n, t:s.t, anchor:s.anchor, lv2:!!s.lv2}));
   ```
