## 2. 本轮新发现（1 个 P2 + 3 个 P3）

### 🟡 2.1（P2）辅助子资源的**失败态缺席**：目录面板没有加载/失败分支

**问题**：详情页把 `/toc` 声明为会用到的端点（`L1261-1262` 的 `api` 列表），并在 `notes.states` 里枚举了：

```
['长文 / 代码 / 表格','图片加载失败','404','离线','评论列表空态','评论加载失败','发帖被拒即时反馈']
```

**图片失败、评论失败都枚举了，唯独没有「目录加载失败」。** 而 `/toc` 在真实实现里是一个**独立请求**，目录面板是一个**有入口按钮的可见 UI**（顶栏 `L1250`）。原型里 `TOC` 直接由本地 `SECTIONS` 派生 → 演示出的是「**目录永远可用、永远即时**」——这一形态在真实实现中**不存在**。

**为什么这是问题（且与 A-1 同类）**：A-1 的教训是「原型是给开发 AI 照抄的，演示形态必须与真实数据形态一致」。一个独立网络请求的失败路径，在原型里被"消失"了，开发 AI 照抄就会写出「打开面板一定有内容」的 UI。**同类：A-1 演示"客户端自造锚点"；本条演示"目录不会失败"。**

**证据**：
```bash
grep -nE "stateBlock|三态" 02-高保真可交互原型.html | grep -iE "toc|目录"   # 空 → 目录面板无任何加载/失败态
```

**跨侧说明（重要）**：产品侧 `02:21` 的详情页状态枚举是「长文、代码、表格、**图片失败**、404、离线」——**同样没有目录失败**。产品侧已冻结在 `18da8b9`，因此**不宜单方面给原型加一个冻结口径里没有的状态**。建议按 A-1 的同款处置：**先在原型注释里声明假设**（成本最低），把「是否补该状态」作为跨侧项提给 owner。

### 🟢 2.2（P3）层级口径只覆盖 1–2 级，且 `level = 6` 会产出非法标签

**先说清楚：原型`L1173` 已经有半句正确声明**——`level 1 落到页面级 h2（h1 留给文章标题），level 2 落 h3，**与契约 level(1-6) 一一对应**`。所以本项**不是"没声明"**，而是这半句声明**覆盖不到它自己派生出来的值域**：

| 落点 | 写法 | 后果 |
|---|---|---|
| 目录面板标签（`L2109`） | `t.level > 1 ? '二级标题' : '一级标题'` | 3 级及以上的标题**全部**被标成「二级标题」 |
| 标题标签派生（`L1174`） | `'h' + (s.level + 1)` | `level = 6` → **`h7`**，非法 HTML 标签（`L1173` 说"与 1-6 一一对应"，但这条公式只对 1–5 成立） |
| 门禁断言（`gates/probe.mjs:245`） | `headingTags[i] === 'H' + (lv + 1)` | **断言的是这个假设本身**（自洽），不是契约；`level=6` 时会比较 `'H7' === 'H7'` 而**通过** |

**可及性**：mock 正文最高 2 级，**当前不可达**，故不构成实际缺陷；但这是「给开发 AI 照抄的出现形态」，且门禁**无法**发现它（断言验证的是假设本身）。

**建议**：把 `L1173` 那半句补全——声明「本原型只演示 1–2 级；`level ≥ 3` 的标签口径与 `'h'+(level+1)` 的派生（`level=6` → `h7`）未验证」。或明确「产品侧只支持两级目录」并在两侧登记。**不要求**在本轮改渲染逻辑。

### 🟢 2.3（P3）两条锚点断言的**性质**需写明限定（与 §4.4 呼应）

**问题**：新增的两条断言很正确，但它们的**能力边界**没写出来，容易被读成「配对规则已验证」：

| 断言 | 真实能力 | 读成什么会出错 |
|---|---|---|
| `idsMatchToc`（正文 id 与 `TOC.anchor` 逐条相等且同序） | 因正文与 `TOC` **同源派生**（`SECTIONS.map`），**构造上必然成立**。它只能拦「两处各写一份锚点」，**不能**证明「锚点与服务端一致」 | 被当成"锚点口径已对齐服务端"的证据 |
| `localSeqAnchors`（`/^h-\d+$/`） | 只拦 **`h-数字` 这一种**回退形态；换成 `sec-1`、`heading-1` 等其他本地序号方案，**两条断言都会通过** | 被当成"不会退回自造锚点"的保证 |

**这两条恰恰与它自己 §4.4 的论断相互印证**：原型**无法**证明配对规则成立（需要 Phase 2 的夹具文章）。所以建议在 `gates/README.md`（或断言名）加一句限定，避免下游把"原型门禁全绿"当成"目录已可上线"。

**同一处小自洽问题**：`gates/probe.mjs:94` 的注释里写了 `['h-1'..'h-5']`——正是它本轮新增的 README 规则 #4「**源码级 grep 断言要防止被『注释里复述旧代码』救活**」所警告的形态。当前没有任何门禁对这个文件做源码 grep，所以**不产生假阳性**；但与它自己刚立的规则不自洽，建议改措辞（如「写死成 h-数字序列」），成本 1 行。

### 🟢 2.4（P3）「涉及接口」栏语义混合：`related` 无消费方且不在冻结范围内

**问题**：`notes.api` 在原型右侧渲染为「**涉及接口**」。详情页该栏列出 13 个端点，其中：

```bash
grep -n "related" 02-高保真可交互原型.html
# → 1262:  'GET /categories/{id}/breadcrumb','GET /articles/{id}/related','POST /articles/{id}/view',
```

**`GET /articles/{id}/related` 全文件仅此 1 处、零消费方**（`relatedBlock=false`、`relatedEls=0`，探针实测）。同时产品侧冻结的详情页内容（`02:21`）是「标题、作者、正文、目录、互动、评论」——**不含相关文章**。

**先澄清我自己的责任**：这个端点是**我第一轮 B-4 要求它补登的**（当时注明「PS-05（可选）」），它照做了。**所以本项不是它做错，而是清单语义需要补一个标记。**

**为什么仍值得处理**：`api` 栏混合了两种语义——①「本页会调用/已渲染」②「本阶段不实现的可选登记」。开发 AI 看到「涉及接口」里写着 `/related`，会以为详情页要有"相关文章"模块。**建议给它加「本阶段不实现」标记（1 行），不建议删除**（删除会与我第一轮 B-4 的登记要求冲突）。

**顺带澄清一处我的误判**：我一度以为 `breadcrumb` 也无消费方——**错**。`02:1201` 实际渲染了 `<div class="crumb">首页 › …`，`01:564` 也画了。`breadcrumb`、`view`（非视觉上报类）在此栏都**合法**，不必动。

## 3. 值得肯定（不是客套，是有具体证据的）
