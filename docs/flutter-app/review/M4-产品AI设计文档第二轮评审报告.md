## 3. 新发现问题

### 🔴 N-1（本轮最高价值）· 「撤回」被移除，但**替代机制的契约依据未定义 → 后门仍在**

**这是 A-1 修复的残留缺口：文档层删掉了「撤回」这个词，但没有把替代机制（保存时不得下发 `status`）写清。**

**契约事实（脚本取证）：**

| 事实 | 契约原文/依据 |
|---|---|
| `status` 在 `ArticleCreate` 中是**可选**字段 | `required: [title, content]`（`status` 不在必需列表） |
| `status` 的权限约束**只覆盖 `published`** | 「权限约束：member 传入 published 时后端忽略并降级为 pending（会员无法直接发布）；editor 与 admin 可直接置为 published。」——**未提及 member 传 `draft`** |
| `PUT /articles/{id}` 的状态副作用**只定义了一种前态** | 「**状态副作用（显式定义，避免两实现分歧）**：member 编辑自己已 published 的文章，保存后状态自动退回 `pending` 需重新审核；editor 与 admin 编辑不改变状态。」——**未定义 member 编辑 draft / pending 时的结果** |
| `pending → draft` 在矩阵中合法，但只有 admin 端点承载 | `Article.status.x-allowed-transitions` 含 `{from: pending, to: draft}`；`POST /admin/articles/{id}/status` 为 `minRole: admin` |

**文档事实：**

- `02:45`「底部操作为：预览、**保存草稿**、提交审核。」——**未按稿件状态区分**。
- `02:47`「待审核可继续编辑」——但**没说「编辑保存时按钮该是什么」**。
- `04:55`「保存草稿、提交审核、重新送审和删除；待审核稿件可继续编辑」——同样未区分。

**风险推演**：开发 AI 照 02:45 实现编辑器，对一篇「待审核」稿件也会显示「**保存草稿**」；用户按下 → `PUT /articles/{id}` 带 `status: draft` → **这就是「撤回」**，而契约对该组合**未定义**：Node 实现可能保持 pending，Go 实现可能真的转 draft——**正是契约要消灭的分歧，也正是 A-1 要消灭的功能**。

**建议（三件事，均不改契约语义）：**

1. **`02 §5` 补「按稿件状态的底部按钮矩阵」**（把 02:45 的无条件表述改为分状态）：

   | 稿件状态 | 底部按钮 |
   |---|---|
   | draft | 预览 / **保存草稿** / 提交审核 / 删除 |
   | pending | 预览 / **保存**（保持待审核，**不提供「保存草稿」**） |
   | published | 预览 / **保存**（保存后转待审核，需明示影响） |

2. **`03 §5 内容约束` 补一条**：「**更新（`PUT`）时客户端不得下发 `status`**，或必须回传当前状态原值——契约只定义了 member 编辑 published → 退回 pending 一种状态副作用，其余组合未定义。」
3. **登记一条契约澄清请求**（描述层补全，非语义变更）：「member 更新 draft / pending 时状态保持原值；更新 published 时退回 pending；请求体中的 `status` 一律忽略（创建时传 `draft` 合法，对应『保存草稿』）。」——这样两实现不会分歧，且不必给 member 新增任何端点。

> ⚠️ 这条须在 **Phase 4（投稿）开工前**闭环，否则开发 AI 会照着 02:45 把「保存草稿」按钮带到待审核状态上。

### 🟡 N-2 · 错误码映射漏 3 个「正常运行时必撞」的码

契约 `ErrorCode` 非零枚举共 **12** 个；`03:39` 只映射了 **9** 个。缺：

| 缺的码 | 契约语义 | 为什么必撞 |
|---|---|---|
| **3001** | 「资源不存在」（契约 1154 原文），用于文章/评论等详情与操作 | 文章不存在、评论已删、通知已清——**列表、详情、评论、通知处处会撞**；不映射则落到未处理异常 UI |
| **3003** | 「状态转移非法」（契约 1315 / 1360 / 2452） | `POST /articles/{id}/submit` 非 draft 前态即返回 **409/3003**——**Phase 4 投稿流程必撞** |

## 4. 方法学更正（如实留痕）

本轮初期我做残留核验时，用了 `grep -n "line.button\|C7DBEA"` 这类**含 `\|` 的 BRE 写法**，在 macOS 的 BSD grep 下 `\|` **不构成或运算**，导致「无匹配」的**假阴性**——我一度误判 `color.line.button` 与 `heroWash` 两侧都没落地。改用 `grep -E` 重跑后更正：**`line.button` 已在 06 落地、`heroWashFrom/To` 已在 `app_theme.dart` 落地**（§1 判定已按更正后结论给出）。

> 复跑口径（本项目可复用）：**涉及或运算的 grep 一律用 `grep -E` 或 `grep -e A -e B`**；`\|` 只在 GNU grep 下有效。
