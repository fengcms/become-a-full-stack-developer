# 接口映射与数据约束

## 1. 单一事实源

接口、字段、错误码和状态转换以 [OpenAPI v1](../api/openapi.v1.yaml) 为准。网站已经证明后端接口可以支撑主要前台能力，但 Flutter 仍需重新生成或校验客户端模型，不能复制网站中的手写假设。

## 2. 功能映射

| APP 能力 | 端点族 | 客户端策略 |
|---|---|---|
| 登录/注册/恢复/退出 | `/auth/*` | 安全存储 refresh、内存 access；单飞刷新；退出清缓存 |
| 首页/列表/详情 | `/articles`、`/categories`、`/tags` | 公开短缓存；分页游标/页码按契约；只展示 published |
| 搜索 | `/search` | 搜索提交后请求；防止每个按键都请求；无结果不当成错误 |
| 作者主页 | `/members/{id}` | 只显示公开资料和 published 文章 |
| 点赞/收藏 | `/articles/{id}/like`、`/me/favorites` | 幂等写入；账号切换后清理状态 key |
| 阅读历史 | `/me/history` | 阅读进度和历史写入节流；私有 no-cache |
| 评论 | `/articles/{id}/comments`、`/comments/{id}` | approved 列表、parentId 组楼、回复/删除、审核反馈 |
| 投稿 | `/me/articles`、`/articles`、`/articles/{id}`、`/submit` | draft/pending/published 状态机，保存与投稿分开 |
| 上传 | `/upload`、`/files/{key}` | 类型/大小前置校验，上传队列，失败保留正文 |
| 通知 | `/me/notifications` | 未读数、标记已读、深链到具体资源 |
| 站点信息 | `/site/settings` | 只读配置短缓存；缺字段使用明确默认显示 |

## 3. 认证细节

需要确认后端对移动端的 refresh token 载体是否允许原生客户端使用。网站依赖 HttpOnly Cookie，而 Flutter 原生请求没有浏览器 Cookie 语义；开发第一阶段必须在 API 验证中确认：

1. 移动端登录返回的 refresh token 是否允许安全存储并提交刷新接口。
2. refresh/logout 是否需要 Cookie、Authorization，还是支持请求体 token。
3. token 轮换失败时旧 token 的处理方式。
4. 后端 CORS/BFF 是否只针对网站域名，移动端是否需要独立 API origin。

如果契约只允许浏览器 Cookie，必须先登记后端兼容方案，不能在 Flutter 中把 Cookie 当作普通字符串随意保存。

## 4. 内容约束

- 公开文章列表和详情只接受 published。
- 会员投稿不能由客户端直接伪造 published；会员保存已发布文章后会进入 pending。
- 投稿正文上限 65,535 字符，标题 200，摘要 500；客户端提前校验，服务端仍是最终裁决。
- 评论 parentId 必须属于同一文章；隐藏父评论时不泄露其内容。
- 图片类型和 10MB 限制与后端保持一致；SVG 处理遵循后端下载安全策略。
- slug、作者、发布时间、审核原因等字段不能由客户端自行补造。

## 5. 需要在编码前确认的差异表

| 项目 | 当前已知 | 开工前动作 |
|---|---|---|
| Refresh 认证载体 | 网站使用 Cookie + 内存 access | 用 Flutter 原生请求做登录/刷新/退出最小联调 |
| 文件下载 | 网站有同源 `/files/{key}` | 确认移动端 API origin 和图片 URL 拼接规则 |
| 推送通知 | 当前只有站内通知接口 | 第一版只做站内通知；推送另立需求 |
| 草稿本机恢复 | 网站已有策略 | Flutter 使用账号+稿件 ID 的本地草稿键 |
| Markdown 目录 | 网站从解析结果生成 | 选择 Flutter 解析库并做中文/重复标题快照 |
| API 分页 | 主要是 page/pageSize | 不把 APP 滚动状态误当成后端游标；按接口返回分页字段实现 |
