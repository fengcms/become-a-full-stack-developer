# Flutter APP 开发准备包

这组文档是 Flutter 移动端开始编码前的基线，服务于“成为全栈开发工程师”内容站 APP。

APP 与网站前台共享后端和业务语义，主要差异是移动端的信息组织、手势、导航和本地体验。本文档不授权修改现有网站、管理后台或后端；发现接口能力不足时，先登记差异，再决定是否进入后端变更流程。

原型使用方式：直接用浏览器打开 `02-高保真可交互原型.html` 即可。左侧是页面导航树，中间是 393×852 设备视图，右侧是该页的「要完成什么 / 必须状态 / 涉及接口 / 注意点」。顶部工具条可切换主题（浅色 / 深色 / 跟随系统）、注入列表状态（正常 / 加载中 / 空 / 错误）、切换登录态。

`app_theme.dart` 在 M4 工程创建后应移动到 `lib/app/theme/`，它是原型与实现之间的令牌契约。


## 已确认的产品方向

- 传统内容门户的信息架构：首页、分类、搜索、文章阅读、会员中心。
- 白色/浅蓝色为浅色模式；深色模式使用深蓝灰背景、浅色文字和低亮度蓝色强调。
- 文章阅读是 APP 的核心场景，正文优先，目录、点赞、收藏、阅读历史和评论围绕正文展开。
- 会员可以投稿：草稿、预览、提交审核、重新送审、本机恢复和 Markdown 图片上传；待审核稿件可继续编辑，撤回为草稿属于管理员动作。
- 评论采用叠楼：回复显示直接回复对象和上下文，跨页加载后仍归入原楼，深层回复限制视觉缩进。
- 第一阶段只做账号密码登录；第三方登录后端虽有契约占位，但当前不作为 APP 主线。

## 开发前的完成定义

开始写 Dart 代码前，应完成：Flutter SDK 与目标平台选择、包版本锁定、OpenAPI 生成方案、环境配置、图标/字体/图片策略、测试设备清单、后端测试地址和本地账号准备。以上条件没有完成时，只能做设计或技术验证，不能把页面开发标记为正式开始。
