# Flutter APP 工程架构与实施记录

2026-10-02。用户授权自主裁决并进入实际开发。

## 工程决策

- 工程：`flutter-app`，包名 `com.yingzhou.fullstack_reader`，应用名“成为全栈”。Flutter 3.47.1 / Dart 3.13.1；Android 为本机验收平台，iOS 工程同时保留。
- Riverpod 注入 API、会话与主题；go_router 管理四个主入口和私有路径回跳；Dio 统一处理信封、错误、超时与单飞刷新。表单输入保留在页面，服务端内容经模型适配后显示。
- access token 仅内存，refresh token 安全存储；退出与切换账号递增会话代次，丢弃旧响应。私有页面以会话代次重建，不持久化私有接口缓存。
- Markdown 使用 flutter_markdown_plus/GFM。服务端目录为唯一数据源，按渲染标题的层级与文本顺序核验匹配；不能匹配的条目不跳到错误标题。正文 Widget 使用服务端 anchor 建立 key，不自行 slug 化。
- 投稿显式创建 draft/pending，更新不传 status；编辑器保存本机恢复副本，按账号与稿件隔离；离开保护、上传状态、失败保留输入和服务端状态冲突检查必须实现。
- `tool` 保存契约模型生成器、本地后端准备脚本和联调脚本；生成文件可重建，依赖锁定在 pubspec.lock。
- API 通过 `--dart-define=API_BASE_URL=...` 配置。开发使用独立 SQLite（`flutter-app/.local`）和 11002 端口，Android 模拟器访问宿主 `10.0.2.2`；不写生产环境。

## 2026-10-03：第一轮代码审阅后的组织方式

- `features/article/`、`features/comment_widgets/`、`features/editor/`：页面内部的私有展示组件与辅助操作，使用 `part` 保持库内私有，不向其他功能暴露页面状态。
- `features/discovery/`、`features/member/`：每个公开页面独立文件；原 `discovery.dart`、`member.dart` 保留导出入口，已有路由和测试无需同时迁移。
- `shared/widgets/`：列表、异步状态、图片、卡片、设置项分别维护；库内部使用明确导入，`shared/widgets.dart` 仅作为兼容导出入口。
- `features/data/`：`ReaderRepository` 组合文章正文读取、收藏分页索引、互动状态、会员概览和统一缓存策略。`CachePolicyTable` 的资源分类共用于读取策略、响应校验和写后失效。
- `core/network/endpoints.dart` 只管理 API 地址；应用导航仍由 go_router 路由管理。`CacheKey` 封装 v1 格式并容错解析，`CacheLimits` 集中定义容量预算。
- `app/theme/`：颜色定义、语义尺寸、组件主题、状态文案分别维护，入口仍是 `app_theme.dart`；细分字号按已经确认的实际 UI 数值提取，避免机械换成相近字号造成视觉变化。

这仍是实用的分层，而非强制单向依赖的纯领域架构：例如 Markdown 展示会使用共享图片组件和内部网页页面，共享列表会使用仓库。第一轮报告所述“core 不依赖 features”不能作为当前工程的严格保证；缓存与网络基础设施本身不依赖 Flutter 页面。详细处理与实测结果见 [第一轮审阅回复](review/M4-开发AI代码第一轮审阅回复.md)。

## 2026-10-03：第二轮代码审阅后的组件边界

| 情况 | 组织方式 | 状态与测试边界 |
|---|---|---|
| 仅当前页面使用的私有展示组件 | 页面库的 `part` 文件，私有类名 | 页面拥有控制器、请求、校验提交和状态生命周期；组件只接收必要字段、控制器与回调，不接收整个 State |
| 跨页面复用，或需要独立公开接口 | 独立 Dart 库，明确 `import`，公开组件类型 | 明确输入和依赖；可以直接通过公开接口编写 widget 测试 |
| 页面私有组件的交互验证 | 从宿主页面的公开入口测试 | `part` 与宿主共享库、导入和隐私边界，不单独 import 私有类；这不妨碍经宿主验证行为 |

`part` 拆分用于降低页面阅读负担，不等于新增架构模块，也不意味着独立依赖边界。后续出现真实跨页面复用时再提升为独立库。

本轮为资料、认证、通知页面提取私有展示组件；表单控制器、请求和状态仍留在页面。删除没有任何引用的 `features/member.dart` 导出桶，取代上节第一轮的保留状态。`features/discovery.dart` 和 `shared/widgets.dart` 仍有测试使用，保留并在文件头说明用途；业务实现继续导入具体组件。

缓存 `_fetch` 保留请求编排与并发版本栅栏，响应头处理、保存、失败事件分别为私有方法。`CacheKeys.articlePrefix` 是客户端虚拟资源命名空间，不是后端端点；值与 v1 磁盘键保持兼容。`Endpoints` 的认证、文件、浏览量路径常量用于排除普通写操作的缓存通知，不代表清理会话。

## 2026-10-03：第三轮代码审阅后的分解与验证

路由工厂只组合私有重定向、错误页、两组路由和底部导航组件；每个 Router 创建自己的分支对象，保留四入口 IndexedStack。首页、搜索、焦点与标签卡按展示职责拆分，页面仍拥有输入与轮播控制器，不把整个 State 交给子组件。

API 请求将刷新资格、限流重试与信封解码分开；异步辅助方法返回后继续核对会话代际。列表首屏比较只保留一份实现，私有列表立即同步、公共列表提示更新的差异保持原样。会员概览键统一为 `CacheKeys.overview`。

验收使用评审 v3 与独立 analyzer AST 检查互相核对；主题 copyWith 单列豁免。具体度量、42 项测试和未覆盖的运行时验证范围见 [第三轮回复](review/M4-开发AI代码第三轮审阅回复.md)。
