# 页面地图与交互规格

## 1. App Shell

底部导航固定四项：`首页`、`分类`、`搜索`、`我的`。文章详情、登录、注册、投稿编辑器属于二级页面，不替换底部导航的语义；编辑器可以隐藏底部导航以保护写作空间。

深链统一使用 HTTPS Universal Links/App Links，例如 `/articles/{slug}`、`/member/articles/{id}/edit`；开发期可保留 `app://` 测试 scheme。go_router 负责解析深链；未登录进入私有路径时保存原始 URI，登录成功后回跳，无法识别或无权限的资源进入明确错误页。

顶部按页面类型变化：普通内容页显示站点标识和菜单；文章页显示返回、标题上下文和更多操作；投稿页显示返回、保存状态和预览入口。

手机端所有主要触控目标至少按 44dp 设计。弹层、抽屉和键盘出现时，底部操作不能被遮挡。横屏不是第一阶段核心目标，但页面不应因固定宽度崩溃。

## 2. 页面清单

| 页面 | 路由意图 | 主要内容 | 必须状态 |
|---|---|---|---|
| 首页 | `/` | 焦点、最新文章、热门、广告/导读 | 首屏加载、刷新、空态、网络错误 |
| 分类 | `/categories` | 使用 `GET /categories/tree` 获取整棵多级分类树；`GET /categories` 仅为平铺列表 | 展开/收起、空分类、加载失败 |
| 标签 | `/tags` | 标签索引与文章数 | 搜索/浏览、空态 |
| 搜索 | `/search?q=` | 文章/分类/标签结果 | 输入中、提交、无结果、失败 |
| 文章详情 | `/articles/:slug` | 标题、作者、正文、目录、互动、评论 | 长文、代码、表格、图片失败、404、离线 |
| 会员公开主页 | `/members/:id` | 公开资料和已发布文章 | 禁用会员、空文章、分页 |
| 登录/注册 | `/login`、`/register` | 账号密码表单 | 校验、失败、恢复回跳 |
| 会员首页 | `/member` | 个人概览和快捷入口 | 未登录、空数据、刷新 |
| 收藏/点赞/历史 | `/member/favorites` 等 | 文章列表与分页 | 删除、末页、错误、账号切换 |
| 我的文章 | `/member/articles` | 草稿/待审/已发布筛选 | 操作确认、状态变化、空态 |
| 投稿编辑 | `/member/articles/new`、`/:id/edit` | 标题、摘要、Markdown、设置 | 未保存、上传中、保存失败、冲突 |
| 投稿预览 | `/member/articles/:id/preview` | 使用带 Bearer 的 `GET /articles/{idOrSlug}` 读取本人未发布稿件；契约没有 `/me/articles/{id}`；不显示目录与上下篇（未发布资源的子端点口径未定义，见 `03 §6`） | 未登录、非本人或稿件不存在统一按不可见/不存在处理 |
| 通知/资料/密码 | `/member/notifications` 等 | 私有信息和设置 | 未读、保存失败、会话过期 |

## 3. 首页

首页采用单列移动门户：焦点卡片 → 最新文章流 → 热门阅读 → 底部导航。横幅广告不强行复制桌面 120px 高度，移动端按素材比例设置最小可读高度；没有真实广告数据时显示站内导读，不伪造商业广告。

焦点支持左右滑动/指示点，但不自动抢夺用户阅读；最新文章支持上拉加载并去重，连续失败保留已读内容和重试按钮。

## 4. 文章详情

文章页把正文放在第一优先级。已发布文章目录数据使用 `GET /articles/{id}/toc` 返回的 `level`、`text`、`anchor`；Flutter Markdown 渲染器为标题建立可寻址的 Widget key，key 值采用服务端 `anchor`，客户端不自行 slug 化。契约没有声明 anchor 算法或数组顺序保证，因此 Phase 2 前必须用重复标题、代码块内 `#` 行和 Setext 标题的样稿验证目录项与渲染标题的配对；验证不通过时先澄清契约，不上线目录跳转。文章详情路由可用 slug，但须先通过详情取得整数 `Article.id`，再请求目录和上下篇。目录用可折叠底部面板或顶部抽屉，点击目录后关闭面板并滚动到标题。点赞、收藏和分享放在正文末尾或浮动操作条，不能遮挡正文。

已发布详情加载后调用 `POST /articles/{id}/view` 递增阅读量；登录用户有 token 时必须带 Bearer，以用户身份去重。登录用户另行调用 `POST /me/history` 更新阅读历史；两个端点职责不同，不能互相替代。

评论采用叠楼：主评论是楼，回复进入楼内；回复显示“回复某某”与原文摘要，深层回复最多视觉缩进一档，更多内容用展开按钮。跨页加载时保留已经加载的楼，父评论暂不可见时只提示状态，不展示裸 parentId。

## 5. 会员投稿

编辑器使用“编辑 / 预览”切换，手机默认编辑模式，预览时使用和文章详情相同的 Markdown 样式。底部操作按稿件状态区分：

| 稿件状态 | 底部操作 |
|---|---|
| 新建（尚未创建） | 预览、保存草稿、提交审核；预期分别以 `status: draft` / `status: pending` 创建，接受性须先通过 `03 §6` Phase 4 前置验证 |
| `draft` | 预览、保存草稿、提交审核、删除 |
| `pending` | 预览、保存（预期保持待审核；仅在 `03 §6` 状态副作用澄清通过后实现）、删除；不显示“保存草稿” |
| `published` | 预览、保存（保存后进入待审核）、删除；保存前明确提示影响 |

稿件状态行为：草稿可编辑/删除/投稿；待审核可继续编辑；已发布可修改并重新送审。会员端不提供“撤回为草稿”，因为当前契约没有会员撤回端点，管理员退回才会进入草稿状态。`PUT` 更新请求不得携带 `status`。pending 保存预期保持 pending，但该状态副作用须先完成 `03 §6` 契约澄清并通过 Phase 4 前置检查；未澄清前不得把该行为视为已由契约保证。保存已发布稿件前明确说明会进入待审核，不能把“保存”误解为只保存私有版本。

离开编辑页、切换账号、网络失败和图片上传中都要保护输入；本机恢复副本必须按账号和稿件隔离，并让用户选择是否恢复。

## 6. 会员中心

“我的”首页提供身份卡和六类入口：收藏、历史、点赞、我的文章、通知、个人资料。列表页面不把未发布文章链接到公开详情；草稿和待审核稿件进入编辑或私人预览。

## 7. 空态、错误态和可访问性

每个页面都定义加载、空数据、网络失败、权限失败和资源不存在的状态。错误页面要提供具体的重试或返回动作。

语义标签、读屏文本、焦点顺序、动态提示和较大字体模式需要在组件层统一处理。颜色不是唯一状态信号，待审核、错误、选中和未读要同时使用文字/图标/结构表达。
