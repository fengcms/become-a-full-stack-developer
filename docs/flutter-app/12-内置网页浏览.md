# 内置网页浏览（2026-10-02）

文章和投稿预览中的 HTTP/HTTPS 链接通过原生 WebView 在 APP 内打开。复用原型返回、更多图标及 APP 主题；顶部标题居中、单行省略，网页加载后及单页应用更新标题后同步显示。标题栏下方为完整网页区域，底部避开系统手势区。

返回按钮、菜单“关闭网页”、Android 系统返回均关闭当前 APP 网页路由，直接返回来源页面并保留原页面状态。网页内部历史不参与 APP 返回行为。菜单“在系统浏览器打开”读取当前 WebView 地址，显式使用 externalApplication，保留 APP 内网页供用户返回后继续阅读。

实现：`lib/features/web_page.dart`，文章入口：`lib/core/markdown/reader_markdown.dart`。采用 Flutter 官方维护的 [webview_flutter 4.14.1](https://pub.dev/packages/webview_flutter)。HTTP 网页允许加载，业务 API 的 HTTPS 限制维持原逻辑；iOS 对 Web 内容启用 ATS 例外。网页不会获得业务 API 的认证头，也不注入会员令牌。非网页协议不会因网页跳转自动唤起外部应用；文章中的 mailto 邮件链接保留原处理。

加载失败显示重试入口；网页标题不可用时使用域名。标题同步定时器在网页路由关闭后释放。

验证：
- `flutter analyze` 无问题。
- `flutter test` 14 项通过。
- Android 模拟器 `integration_test/web_page_test.dart` 通过：从实际 Markdown 链接打开原生 WebView，通过测试 HTTP 页面内 JavaScript 自动跳转到第二页，验证新标题、长标题省略、返回、关闭菜单及系统返回都直接回到原文章。该测试不访问生产写入接口。
- 系统浏览器菜单使用平台启动 API；本次自动化未实际切换外部浏览器。iOS 配置已更新，本机无完整 Xcode，未做 iOS 运行验收。
