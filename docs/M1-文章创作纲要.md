## 一、M1 三十一篇逐篇纲要

### M1-01 Node 后端工程从零搭建：TypeScript、目录与热更新 · P0
- **命题**：工程初始化、目录约定（`src/{routes,services,shared,types}`）、热更新调试体验。
- **前置**：无。
- **骨架**：① 为什么 TypeScript 是后端底线；② 目录约定（routes 薄 / services 领域 / shared 基础设施 / types 纯类型）；③ 热更新与调试；④ 门禁雏形（tsc/biome/vitest）。
- **引用**：`tsconfig.json`、`package.json` scripts、`node-backend/README.md` 目录树。
- **穿插**：P-01（`@/` 路径别名 TS7 坑）、P-02（类型纪律）、P-05（别名是重命名保险丝）。

### M1-02 框架选型：Express / Koa / Fastify / NestJS 的差异与取舍 · P0
- **命题**：四框架定位差异 + 本项目选 **Hono** 的依据（边缘运行时友好、handler 可返回原生 `Response`、轻）。
- **前置**：M1-01。
- **骨架**：① 四框架一句话定位；② 关键维度对比表（中间件模型/TS 友好/边缘部署/体积）；③ 为什么 Hono——`handler 返回 Response 合法`让 lib 零框架依赖（呼应 M1-08）；④ 适配层让 Hono 同时跑 Node 与 CF（钩子留 M1-24）。
- **引用**：`src/index.ts`（Node 入口）、`src/worker.ts`（CF 入口）、`app.ts` 工厂。
- **穿插**：Q5（是否补 `wrangler.toml`，结论选 A 真可部署）；P-14（Hono handler 返回原生 Response 的妙处，提前埋点）。

### M1-03 分层架构：Controller、Service、Repository 的边界 · P0
- **命题**：每一层该做什么，前端 MVC 经验如何迁移；水平分层 routes/services/shared/types。
- **前置**：M1-01/02。
- **骨架**：① 前端 MVC → 后端分层的映射；② routes 薄（解析参数/调 service/包信封）；③ services 承载领域+DB；④ shared 基础设施（storage/jwt/config/db-error）；⑤ types 纯类型。
- **引用**：`src/routes/*`、`src/services/*`、`src/shared/*`、`src/types/*`。
- **穿插**：**P-03（routes 禁碰 getDb，分层破产判据）**、P-04（循环依赖提前解）、P-06（200 行软硬）、P-07（分拆应激回收）——这篇是结构调优踩坑的主舞台。

### M1-04 数据库选型：关系型还是文档型 · P0
- **命题**：关系型定调；Cloudflare D1(SQLite) 与自管 Linux(SQLite/PG) 取舍；**全栈大多从关系型起步**。
- **前置**：M1-01。
- **骨架**：① 关系型 vs 文档型本质差异；② 本项目选关系型（强一致/关联查询/生态）；③ D1 vs 自管 Linux 兼容；④ SQLite FK 默认不强制，父存在性由应用层保证（钩子 M1-16）。
- **引用**：`src/db/*`、`schema.ts`、`getDb()`。
- **穿插**：P-08（better-sqlite3 优于 node:sqlite）、P-09（DB 适配层边界，受控转换只一次）。

### M1-05 ORM 为什么选 Drizzle：类型安全与 D1 适配 · P0
- **命题**：Drizzle 相对 Prisma/TypeORM 取舍；同一份 schema 跑 D1 与普通 SQLite/PG。
- **前置**：M1-04。
- **骨架**：① ORM 解决什么；② Drizzle 的"贴近 SQL"哲学与类型安全；③ 同一 schema 跨 D1/SQLite/PG；④ 迁移机制。
- **引用**：`schema.ts`、`drizzle.config.ts`、`src/db/migrate.ts`。
- **穿插**：**P-10（`.run()`/`.all()`/`.returning().all()` 分野，运行时才爆）**、P-11（JOIN 歧义列 500，钩子 M1-17）、P-12（迁移不靠多语句 exec）。

### M1-06 数据迁移：schema 变更如何不弄脏线上数据 · P1

- **引用**：`drizzle.config.ts`、`migrations/`。
- **穿插**：P-12（单条 `run` 按 `;` 拆循环）、P-41（better-sqlite3 `transaction` 同步回调血泪坑，U-R3 完整版可在此展开或留增补）。
