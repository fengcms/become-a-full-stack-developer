## 后续小程序接入流程

1. 用户主动选择微信登录后，调用 wx.login 获取临时 code，将 code 发送至 `POST /api/v1/auth/wechat/callback`。
2. 后端向微信验证；首次创建 member，后续返回同一 userId。返回现有 AuthResult，业务请求继续使用现有 JWT/刷新协议。
3. `user.canSetCredentials === true` 时展示“设置用户名和密码”入口；缺失按 false。此步骤可以稍后完成，不影响已登录会员使用业务功能。
4. 使用 Bearer 调用 `POST /api/v1/me/setup-account`，正文为 username、password。用户名 1–32 字符，密码至少 8 字符；确认密码由客户端校验。
5. 成功后整体替换本地 AuthResult；账号 ID、昵称及内容归属保持不变。APP、网站可直接使用这组凭据登录，不新增微信快捷入口。

用户名占用或已完成设置返回 409/3002，不自动绑定或合并现有用户。已有网站账号可以继续密码登录；若另行微信建号，两者是独立账号。网络失败不要自动重放旧微信 code，应重新 wx.login。设置提交成功但响应丢失时，可用新密码或重新微信登录恢复，再读取资格。

## 后端边界

仅单个小程序 AppID；身份表唯一约束 app_id + open_id。旧账号默认凭据已配置。未配置凭据的微信用户禁止密码登录；随机内部密码原文不保存。设置成功原子撤销旧刷新令牌，旧访问 JWT 沿用既有到期策略。退出行为也沿用原契约。

不实现手机号登录、绑定、合并、解绑、自助密码找回、onboarding ticket。不新增 /auth/wechat/mini/*、/me/auth-methods 或 /me/set-password，也不将 password_hash 改为可空。

## 配置与验收边界

服务端需 WECHAT_MINI_APP_ID、WECHAT_MINI_APP_SECRET，通过 Cloudflare Secrets 配置。AppSecret/session_key/OpenID 不传给前端，不写日志、示例或 Git。前端只配置自身 AppID。

目前线上缺少这两项配置，真实微信登录尚未验收，调用返回 500/5000。后端自动化中的微信测试桩、线上合成身份夹具均不能代替真实微信验证。待小程序开发阶段补齐配置后，在开发者工具关闭域名校验，验证真实 code 首次建号、重复登录、设置凭据、APP/网站密码登录同一账号即可；正式上架不作为当前验收条件。
