## 技术实现与关键判断

1. 沿用 Taro 4.3.0、React 18、TypeScript、Webpack5。业务集中于 `core`、`hooks`、`features` 和 `components`，页面负责组合；不是将 Flutter 代码或桌面编辑器搬入小程序。
2. 公共缓存 80 项、私有缓存 60 项，默认 60 秒内存 TTL；同一请求合并。页面返回优先复用，主动刷新强制回源。私有键包含接口环境、userId 和会话代际；退出清私有数据，不清公共阅读缓存；迟到响应不能填回已失效缓存。阅读历史上报不驱逐公共文章缓存。
3. 会话持久化按接口环境隔离；401 仅在确认认证失败后刷新并重放一次。普通网络失败不自动重试写入，避免重复评论和投稿。刷新失败与账号切换不能将旧数据写入新账号。
4. 点赞/收藏先更新界面，失败还原；点赞成功使用后端返回计数。收藏状态查询遍历必要分页，避免仅检查第一页的漏判。
5. 评论在现有平铺分页接口上归并父链，不增接口。若父楼不在已加载分页中，显示缺失父楼占位；继续加载后重新归楼。这是当前分页契约下的明确表现，不伪造父评论内容。
6. 投稿先创建并固定文章 ID，再提交审核。第二步失败仍可对同一稿件重试。创建结果不确定时保留本机稿并提示先检查“我的文章”，避免再次创建。保存前检查云端 updatedAt，有变化需要用户明确选择覆盖；这是客户端冲突提醒，不等同服务端原子条件写入。
7. 本机草稿按环境、账号、稿件隔离，600ms 自动保存，并在离开时保存；清理阅读缓存不删除草稿。图片上传期间禁用服务端保存/提交，避免尚未拿到 URL 就提交。跨账号图片选择结果不能上传到新会话。
8. 开发工具回归发现文字容器的点击不稳定，主要操作改为原生 Button；编辑预览、主题选择等实际操作随后通过。目录分类 ID 转 slug、通知 body/link 字段等均以已有后端契约校正。
9. 保留用户配置的 AppID；AppSecret 不进客户端。账号流程严格使用已增补的 callback 和 setup-account，没有复活早期 ticket、绑定或合并方案。

## 自动化验证

最终执行并通过：

```sh
pnpm typecheck
pnpm test
pnpm test:integration
pnpm build:weapp
```

本机环境 Node 24.19.0、pnpm 11.25.0。测试证据：

- [11 项逻辑测试结果](../evidence/implementation/unit-tests.txt)：缓存复用/合并/有界/失效代际、权限错误驱逐、并发 401 单飞、账号切换、网络写不重试、历史缓存、草稿隔离、Markdown 安全与目录、叠楼循环/缺失父楼、退出隔离。
- [真实后端集成结果](../evidence/implementation/integration.json)：小程序请求层接入真实 Hono 业务和临时 SQLite，验证注册/资料、固定 ID 保存/提交/撤回、点赞计数/收藏/历史、评论回复/级联、双账号越权拒绝和密码登录/退出。
- [类型与构建结果](../evidence/implementation/build.json)：14 页面、4 Tab，构建产物约 759 KB；已检查使用线上接口且不包含本地验收端口或测试密码。

集成测试只监听 `127.0.0.1:13997`；临时建库、临时身份和测试发布夹具只存在于测试进程，退出清理。没有向生产发布测试文章或写入测试评论。测试脚本需要相邻后端已安装依赖；可在本机重复执行，本轮没有新增 CI 工作流。

## 尚未实测的边界

- **真实微信登录全流程**：前端接线完成，但未获得并验证后端匹配的 AppID/AppSecret 与真实 code。此前后端交付记录明确密钥未配置；用户本次只确认前端 AppID。不能据此宣称真实微信建号/首次设置凭据已通过。入口在后端未配置时明确报错，可继续密码登录。
- 微信选择相册并上传真实图片、原生分享实际接收、真机键盘行为和弱网长时间使用尚未逐项人工验收。上传/预览/分享代码已实现；不把编译或本地 API 测试写成平台能力实测。
- 草稿存储/隔离逻辑已测试；开发工具内“退出再进入恢复弹窗”尚未完成独立操作证据。头像上传也没有上传用户真实照片进行验证。
- 图片上传遇到访问令牌过期会显示错误，用户可在完成会话刷新后重试；图片上传不自动重传。
- 当前测试已覆盖关键逻辑和业务路径，但不是所有页面、设备和异常条件的穷举验收。正式发布差距继续见 [演示环境说明](../05-演示环境限制与正式发布差距.md)。
