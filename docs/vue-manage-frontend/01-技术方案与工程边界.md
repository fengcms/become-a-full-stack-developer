## 1. 目标与边界

本项目在 `manage-frontend-vue/` 中新建一套 Vue 管理后台，复刻 React 管理后台已有的页面、角色能力、操作流程和 API 行为。它是前端实现的重写，不是产品改版：不修改原 React 项目，不修改 Node/Go 后端，不修改已经冻结的 OpenAPI 契约，也不以 Vue 组件改造为理由改变业务规则。

Vue 版本的完成标准是：同一账号、同一后端和同一契约下，用户能够完成原管理后台支持的工作；受限角色看到一致的菜单与路由结果；关键编辑、上传、批量操作和错误恢复行为均有验证。

## 2. 开发基线与版本选择

工程实际安装 Vue 3.5.43、Vite 8.3.4、Naive UI 2.45.3，解析版本固定在 pnpm 锁文件中；Node 运行时下限为 22.12.0，项目声明为 `>=22.12.0`。版本选择未使用预发布版。

Vite 官方当前要求 Node.js 20.19+ 或 22.12+。新工程应使用符合要求的 LTS 版本，并在 `.nvmrc` 或等价工具配置、`engines` 和 CI 中保持一致。Vue 官方推荐通过 `create-vue` 创建 Vite 项目；构建工具负责转换与打包，SFC 的完整类型检查另由 `vue-tsc` 完成。

参考： [Vue Tooling](https://vuejs.org/guide/scaling-up/tooling)、[Vue TypeScript](https://vuejs.org/guide/typescript/overview)、[Vite Getting Started](https://vite.dev/guide/)、[Vite Releases](https://vite.dev/releases)、[Naive UI](https://github.com/tusen-ai/naive-ui)。

## 3. 技术栈决策

| 层 | 建议 | 职责与约束 |
|---|---|---|
| 应用与构建 | Vue 3、Vite、TypeScript、`<script setup lang="ts">` | 采用 Composition API；页面和组件使用 Vue SFC；开启严格类型检查。 |
| UI | Naive UI | 作为管理端通用组件的唯一主 UI 库；通过 `NConfigProvider` 集中配置主题、中文语言和日期语言；差异化样式用设计令牌与局部 CSS。 |
| 路由 | Vue Router | 路由懒加载；守卫只负责登录、后台角色、能力校验和跳转，不承载页面数据请求。 |
| 客户端状态 | Pinia | 仅保存会话、启动恢复状态和少量界面状态；不把服务端列表/详情复制进 store。 |
| 服务端状态 | `@tanstack/vue-query` | 管理请求缓存、加载/错误状态、重试、失效和变更后的刷新；query key 按资源与参数稳定组织。 |
| HTTP | 基于 `fetch` 的薄请求层 | 保留统一响应信封、错误码、Bearer token、刷新并发合并、原请求最多重放一次、FormData boundary 等行为。 |
| 契约类型 | `openapi-typescript` | 从仓库内唯一契约 `docs/api/openapi.v1.yaml` 生成类型到 Vue 项目；禁止手工复制一份“事实源”。 |
| 表单 | Naive UI 表单 + 独立纯校验函数 | 表单组件负责交互，领域校验可独立测试；避免同时引入多套表单状态系统。 |
| Markdown | `md-editor-v3` | 提供 Markdown 编辑、预览和工具栏；以 `on-upload-img` 接入认证上传请求，显示上传状态并关联文章；文章页负责预览和未保存保护。线上附件写操作需具备管理账号后验证。 |
| 图表/图标 | ECharts（若仪表盘需要）与 Naive UI 兼容图标包 | 仅按需加载；图表组件与统计请求分离。 |
| 质量工具 | Biome、Vitest、Vue Test Utils、`vue-tsc` | Biome 统一承担格式化与 lint；`vue-tsc` 负责 SFC 类型检查；单测、类型检查和生产构建构成基础门禁，关键用户路径增加浏览器级 smoke。 |

Naive UI 是本次 UI 基础，沿用 React 项目的 Tailwind/Radix 组件体系会形成两套视觉和交互系统，不纳入 Vue 工程。可以保留项目级 CSS 变量和少量定制样式，但应先使用 Naive UI 提供的组件能力。

Biome 作为唯一的 lint/format 工具，不引入 ESLint 或 Prettier。Biome 对 Vue SFC 的处理仍有实验性支持和部分规则限制；搭建时应核对当前官方语言支持说明，打开所需的 HTML/Vue 支持选项，并用真实 `.vue` 文件验证格式化与 lint 结果。对已知误报做有范围的规则配置，不能把这些检查当成 Vue 模板语义或类型检查的替代品；模板/SFC 类型仍由 `vue-tsc` 检查。参考 [Biome language support](https://biomejs.dev/introduction/language-support/)。

Markdown 编辑器依赖是唯一保留的技术验证项。React 版使用的 `@uiw/react-md-editor` 不能直接用于 Vue。验证未完成前，不要把上传行为简化成仅能选择文件：现有上传流程涉及编辑器图片上传、认证请求、文章上下文和失败反馈。

## 4. 参考实现盘点

### 页面和路由

以 React 路由为迁移清单，至少包括：登录、仪表盘、文章列表/新建/编辑/预览、评论审核、分类树、标签、用户、站点设置、个人资料、密码修改、通知、点赞、收藏，以及 403、无后台权限、404 页面。个人资料子路由是普通登录会员可访问的区域，不能错误地套用后台角色门槛。

权限判断分为三层，必须保持不同结果：

1. 未登录：等待会话恢复完成后跳转 `/login`，用路由 state 保存回跳地址。
2. 已登录但角色不能进入管理后台：跳转 `/no-access`。
3. 能进入后台但不具备某项能力：跳转 `/403`。

菜单显隐和直接访问路由必须调用同一组能力判断。后端仍是最终授权边界，前端守卫只提供一致的导航体验。

### 请求和会话

现有请求层的语义属于需要保留的业务行为：

- 解析 `{ code, message, data }` 信封并映射 API 错误。
- Access token 只放内存状态，不写入 localStorage/sessionStorage。
- Refresh token 兼容请求体传值与同源场景下的 HttpOnly Cookie。
- 并发 401 共用同一个刷新 Promise，适配后端旋转刷新令牌。
- 刷新成功后原请求最多重放一次；禁用账户、刷新失效等情况清理会话并通知路由。
- FormData 不手工设置 `Content-Type`，让浏览器生成 boundary。
- 应用启动期间先静默恢复会话，守卫在恢复完成前展示启动状态，不误跳登录页。

Vue 的 Pinia store 与请求层应通过一个明确的 session adapter 连接，避免在 Pinia 尚未安装时调用 store，或让 request、router 和 store 互相循环导入。

### 数据与页面交互

React 端使用 TanStack Query 管理服务端状态，Vue 端采用对应的 Vue Query 适配器，保留列表筛选、分页、详情加载、操作后失效刷新、失败重试等行为。文章、评论、分类、标签、用户、站点、个人中心和附件 API 都从现有模块与 OpenAPI 生成类型中盘点，不改写成另一套 API 契约。

文章编辑器有独立的保存/发布/下架状态、内容与设置分页签、图片上传、未保存离开保护。分类支持树形层级操作；文章和评论列表支持分页/筛选及权限相关操作；批量操作需要展示部分失败结果。迁移时要保留这些流程，不能只以静态页面“看起来齐全”作为完成依据。

## 5. 工程组织

建议以业务域为主组织代码，避免按技术类型堆出超大目录：

```text
manage-frontend-vue/
├── src/
│   ├── app/                 # 应用入口、路由、全局 provider、启动恢复
│   ├── layouts/             # 管理端、个人中心和裸页布局
│   ├── features/
│   │   ├── auth/            # 登录、会话恢复、守卫策略
│   │   ├── dashboard/
│   │   ├── articles/        # 列表、编辑器、预览、附件
│   │   ├── comments/
│   │   ├── categories/
│   │   ├── tags/
│   │   ├── users/
│   │   ├── site/
│   │   └── profile/
│   ├── shared/
│   │   ├── api/             # 请求内核、错误、契约生成类型
│   │   ├── components/      # 跨域通用组件
│   │   ├── composables/     # 可复用交互逻辑
│   │   ├── permissions/     # 能力判断与角色规则
│   │   └── utils/
│   ├── stores/              # Pinia 的客户端状态
│   ├── styles/              # 全局 token 与 Naive UI 主题覆盖
│   └── types/
├── tests/
├── package.json
├── pnpm-lock.yaml
└── vite.config.ts
```

业务域内允许有自己的 API、query、组件、表单 schema 和单测。只有被多个域真正复用的代码才进入 `shared/`。每个组件/模块保持单一职责；页面负责组合流程，不承载整个域的请求、校验和表格逻辑。

## 6. 关键工程约束

- **类型检查**：`vite build` 不替代 Vue SFC 类型检查；CI 必须运行 `vue-tsc --noEmit` 或等价脚本。
- **契约生成**：提供 `pnpm gen:types`；生成结果可重复，CI 可检查生成类型与契约是否同步。
- **会话安全**：不持久化凭证，不在错误日志、URL、埋点中输出 token；避免多个标签页各自制造并发刷新风暴，跨标签协调若要加入必须另行验证必要性和安全边界。
- **API 纯度**：后端路径、方法、字段及状态值来自 OpenAPI；遇到缺项时记录为契约问题，不在 Vue 层“猜”字段或扩充契约。
- **列表性能**：大表格启用服务端分页/筛选；避免一次加载全部文章、用户或评论；Vue 组件不要因对象引用变化反复发出重复请求。
- **可访问性**：对话框、菜单、表单错误和键盘操作应具备可读标签及焦点管理；Naive UI 组件的默认行为也要在真实页面验证。
- **配置**：仅通过 `VITE_` 公开非秘密配置；生产 API 地址由环境提供，密钥不得进入前端 bundle。
- **部署**：SPA 静态部署需配置深层路由 fallback；保留现有反向代理/API base 约定，开发代理与生产来源分开配置。

## 7. 完成定义

Vue 后台满足以下条件后才算功能完成：

1. 页面清单和路由均实现；必要页面能按角色正确显示或拒绝访问。
2. 与现有 React 后台使用同一 API 契约，关键写操作在本地 Node/Go 后端环境均可验证。
3. 登录恢复、刷新令牌并发、过期退出、禁用账号和回跳有单测覆盖。
4. 文章创建/编辑/预览、图片上传、保存/发布/下架、未保存提示都完成实测。
5. 列表分页筛选、树形分类、批量部分失败、评论审核、用户管理、站点设置及个人中心通过验收清单。
6. `biome check`、类型检查、单元测试、生产构建通过；核心路由有浏览器级 smoke。
7. 与 React 版至少完成关键页面和窄屏/常用桌面视口的人工视觉回归；差异记录为有意设计或修复项。

## 8. 已知风险与处理

| 风险 | 处理方式 |
|---|---|
| 只搬组件导致业务状态机丢失 | 以页面行为和业务操作清单迁移，不按 JSX 文件逐文件机械翻译。 |
| refresh token 旋转导致并发请求互相登出 | 在 Vue 请求层复刻单飞刷新机制，并对并发 401 做确定性测试。 |
| Markdown 编辑器能力与原版不一致 | 在实现表单前做编辑器 spike；使用真实 API 验证粘贴/上传、失败和文章上下文。 |
| Naive UI 表格/表单默认样式与旧版差异 | 建立主题 token 和可复用页面模式，先验收登录、列表、编辑器三种典型页面。 |
| 查询缓存和 Pinia 双重保存 | Pinia 只保存客户端状态；API 数据只进 Vue Query cache。 |
| 同时支持 Node、Go 后端时开发环境配错 | 用同一 OpenAPI 与可切换 API base 验证，不在前端分叉 API 代码。 |
