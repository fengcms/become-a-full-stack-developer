## 完成范围

新建的 Vue 项目覆盖 React 管理后台的主要页面和用户路径：登录与会话恢复、仪表盘、文章列表/编辑/预览、Markdown 图片上传、评论审核和回复、分类树、标签、用户管理、站点设置，以及个人资料、改密、通知、点赞和收藏。编辑器支持草稿保存、发布、下架、分类/标签选择、封面和正文图片上传、未保存离开提醒。文章批量软删除会报告部分失败；分类、标签的删除也检查关联限制。

角色边界按现有三角色能力表实现。普通会员登录后可进入个人中心，但后台路由去 `/no-access`；编辑可管理文章、评论、分类和标签；用户与站点管理仅管理员可用。菜单显隐与路由守卫共用 `src/lib/permission.ts`。

原 `manage-frontend/` 保留为对照项目。请求接口和类型来源于现有 API 模块及冻结 OpenAPI，不更改后端或契约。

## 关键实现决策

- 使用 Vue Query 管理服务端数据，Pinia 只保存登录用户、访问令牌和启动状态。访问令牌只保存在内存中。
- 请求层解包标准响应信封，统一映射错误码；多请求同时收到可刷新的 401 时共享一个刷新 Promise，成功后每个原请求最多重放一次。FormData 不设置 `Content-Type`，交由浏览器写入 boundary。
- 应用先尝试恢复会话，再挂载路由。退出、刷新失效和禁用账号均清理本地会话并转至登录页。
- Naive UI 负责表单、表格、弹窗、通知和全局中文主题。样式基于浅色工作区、深蓝侧栏和克制的蓝色强调色；宽屏为固定侧栏，窄屏切换为横向导航。
- Biome 是唯一格式化和 lint 工具。因 Vue SFC 支持仍属实验能力，显式启用了 HTML 全量支持；另以 `vue-tsc` 检查模板类型。
- Vite 开发代理将 `/api/v1` 和 `/files` 指向 `API_TARGET`，默认 `http://localhost:11000`，可通过 `.env.local` 切换 Node 或 Go 后端。公开变量不包含凭证。

## 验证结果

以下命令均通过：

```text
pnpm check
pnpm typecheck
pnpm test       # 3 个测试文件，9 个测试通过
pnpm build
```

额外验证包括：

- 本地浏览器能够渲染登录页，未登录直接访问文章编辑路由会回到 `/login`。
- 使用本地 Vite 代理请求线上 Node API 的公开站点设置和统计端点，返回符合契约的成功信封。
- `vite preview` 对 `/articles/123/edit` 返回生产构建 HTML，确认 SPA 深层路由 fallback 生效。
- Vitest 覆盖成功信封解包、并发 401 合并刷新、刷新后重放、FormData boundary、member/editor/admin 权限边界、资源所有权，以及匿名/member/editor 的路由守卫结果。
- GitHub Actions 工作流对项目变更运行冻结安装、Biome、类型检查、单测和生产构建。

## 尚需真实账号/服务的验收

当前机器没有监听 `localhost:11000` 的本地后端，也没有本地 Go 服务；本次未获取或写入管理账号凭证。因此没有向线上服务提交登录、文章变更、评论审核、用户管理、站点设置或附件上传请求，也无法宣称 Node 与 Go 两套后端的受保护写操作已经端到端实测。

获得可用的本地测试后端和管理账号后，应在 `.env.local` 设置 `API_TARGET`，分别对 Node 和 Go 完成登录/刷新、文章保存与图片上传、评论审核、权限拒绝、用户/站点设置等回归。该工作是运行环境验收，不需要改 Vue 页面或冻结契约。

## 复现

```sh
cd manage-frontend-vue
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm dev
```

通过 `API_TARGET` 指向可用后端。完整命令和目录说明见 [Vue 项目 README](../../manage-frontend-vue/README.md)。
