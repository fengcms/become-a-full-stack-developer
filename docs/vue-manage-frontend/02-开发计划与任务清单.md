## 1. 推进原则与实施状态

本计划按可运行、可验证的交付阶段推进。每阶段先让一条真实用户路径闭环，再扩展页面数量。页面实现以 `manage-frontend/` 的行为和 API 模块为参照，数据结构以 `docs/api/openapi.v1.yaml` 为唯一契约来源。

阶段完成时应运行对应质量门禁并提交一个聚焦的 Conventional Commit，例如 `feat(vue-admin): 建立 Vue 后台工程骨架`。若阶段拆成多个独立变更，应分别提交；提交前检查差异，保留工作区里与本任务无关的修改。

截至 2026-10-08，阶段 1–5 的页面和主要交互已经落地，阶段 7 的 README、构建和深层路由验证已完成。`manage-frontend-vue/` 是独立目录；原 `manage-frontend/` 未改动。阶段 6 已完成契约、公开 API、权限和请求层测试；还没有管理账号来验证线上写操作，当前机器也没有本地 Node/Go 服务监听，因此双后端登录后的真实写操作验收保留为环境依赖项。这不影响前端实现完成，接入 Node 或 Go 后可用 `.env.local` 中的 `API_TARGET` 切换服务地址。

## 3. 页面与权限矩阵

| 页面/功能 | 主要 API 领域 | 访问边界 | 关键验收 |
|---|---|---|---|
| 登录 | auth | guest | 登录成功、失败反馈、回跳、已登录分流 |
| 仪表盘 | site/stats、articles、comments | 已登录且可进入后台；局部卡片随能力显示 | 统计、近期动态、角色入口 |
| 文章列表/编辑/预览 | articles、attachments、categories、tags | 文章管理能力；预览按现有规则 | 筛选分页、保存/发布/下架、图片上传、未保存保护 |
| 评论审核 | comments | 评论管理能力 | 状态筛选、上下文、审核和回复 |
| 分类/标签 | categories、tags | 各自管理能力 | 树形限制、增删改、关联选择 |
| 用户 | users | 用户管理能力 | 列表、编辑、重置密码及错误状态 |
| 站点设置 | site | 站点设置能力 | 读取、校验、保存 |
| 个人中心 | me/notify | 任意已登录会员 | 资料、改密、通知、点赞、收藏 |
| 错误页 | — | 按登录和角色上下文 | `/no-access`、`/403`、404 明确区分 |

## 4. 主要风险和阶段门

- **Markdown 编辑器**：阶段 4 的编辑器 spike 是内容页面继续开发前的门。以实际上传 API 和用户流程验证候选库；若候选库缺少关键能力，补一层 Vue 包装/自定义上传适配，仍不能满足时才评估另一个 Vue 编辑器。
- **认证刷新**：阶段 3 的并发 401 测试通过前，不扩展全站依赖该请求层的页面，避免复制有缺陷的认证逻辑。
- **契约问题**：凡 OpenAPI 无法表达但 React 版正在使用的行为，先对照 Node、Go 实际响应和已有契约，整理证据；前端准备阶段不擅自改冻结契约。
- **视觉偏差**：阶段 2 先验收导航壳，阶段 4 验收列表与编辑器，避免最后才发现全局组件风格或尺寸需要整体返工。
- **覆盖面**：以页面矩阵逐项清零，不用“主流程跑通”替代全部路由和权限验收。
