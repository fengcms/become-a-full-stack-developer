# M3 Next.js 网站前台（含会员中心）·文章创作规划提案

> 日期：2026-09-24  
> 状态：owner 已确认，已回写 `docs/prd/01-内容路线图.md` 与 `ARTICLES.md`。  
> 实现依据：`web-frontend/` 最终项目；`web-frontend/docs/` 实施与验收记录；`docs/web-frontend-codex/` 工程决策和问题复盘。  
> 写作标准：延续 M2 的真实问题进入、证据论证、取舍边界和发布辅助信息规范。

## 一、审视结论

原路线图的 20 篇覆盖了 App Router、渲染模式、RSC、缓存、文章、SEO、认证、会员、评论、性能和部署，主干方向正确，但与最终实现存在四类偏差。

### 1. 已经落地、但原路线图没有独立承接的内容

- 传统内容门户首页的信息架构：焦点区、最新文章、横幅、持续加载、热门侧栏与 Footer 可达性。
- 同源 BFF 代理：`/api/v1/[...path]`、`/files/[key]`、刷新 Cookie 改名隔离、Set-Cookie 转发和跨站写入来源校验。
- 会员投稿完整工作流：新建草稿、编辑、预览、投稿、撤回、重新送审与本地恢复。
- 叠楼评论：树构造、父评论上下文、回复、删除和内容审核后的失败恢复。
- 错误与空内容的区分，以及错误边界 reset 不等于重新获取服务端数据。
- Next 标准运行时与 OpenNext Worker 的双环境验证、R2 增量缓存和重新验证行为。

### 2. 原路线图存在但不再适合独立成篇的内容

- “微信/微博等第三方登录”没有进入本期实现范围，也没有对应契约与验收证据。继续写成实现教程会脱离项目事实。第三方登录只适合在认证篇的扩展边界中讨论账号归并原则。
- “第三批复盘”位于 M3-14，实际发布顺序中复盘应放在系列末尾，否则后续公开主页、站点信息、导航辅助、搜索、通知和 Next 服务端能力都成了“复盘后的新增内容”。
- “文章列表与详情页”合在一篇过宽：列表涉及分类、标签、URL 分页和持续加载；详情涉及 Markdown、目录、辅助导航、互动和评论，应该拆开。
- “部署：自托管还是平台托管”过于抽象。当前项目已有 OpenNext + Cloudflare Worker 的真实构建与缓存验证，应以实际部署链为主，再比较自托管边界。

### 3. 原编号顺序不符合教学依赖

渲染策略应在 RSC/Client 边界之后结合真实页面讲解；站点设置、首页和分类导航应先于文章列表；认证基础应先于所有会员互动；质量验收应在部署前；复盘必须最后发布。

### 4. 建议规模

建议从 20 篇扩充为 **24 篇**。增加的四篇并非拆字数，而是补齐四条独立论证链：门户首页、同源代理安全、会员投稿工作流、质量与故障恢复。

## 五、每篇共同质量标准

- 默认约 2500～3200 中文字；复杂文章可更长，不靠概念罗列凑篇幅。
- 每篇只证明一个核心命题，并至少包含一个实际失败方案、一段真实代码或配置、一项验证证据和明确适用边界。
- Next.js 版本事实以 `web-frontend/node_modules/next/dist/docs/` 和当前源码为准，不能依赖旧版 App Router 记忆。
- 区分 `web-frontend/` 当前实现、`web-frontend-trae/` 历史实现和 `web-frontend-codex/` 设计资料；正文以最终采用项目为事实源，历史项目只用于解释取舍。
- 不把本地验证写成线上 SLA，不把构建成功写成已部署，不把客户端守卫写成安全边界。
- 每篇包含可整体删除的发布辅助区：6 个 Tag、250 字以内简介、分类建议、封面短标题、2～4 张 AI 配图提示词、发布核对项。
- 正文订阅区固定包含“成为全栈专栏订阅”宣传图片。
- 发布内链先用 `{{LINK:M3-xx}}`；M0/M1/M2 已发布链接从 `ARTICLES.md` 核对，不凭记忆填写。

## 六、最值得保留的真实踩坑

- 会话恢复清空整个 QueryClient，误伤仍挂载的公共文章流。
- 错误边界只 reset 客户端状态，没有真正重新请求失败的服务端内容。
- 直接 API 测试能退出，但页面封装因 `skipAuth` 导致真实退出失败。
- 多个失效请求并发刷新、刷新期间退出、切换账号后旧响应回写。
- 新旧前端端口不同但 Cookie 仍共享，必须在代理边界改名隔离。
- Origin 校验初版误伤本地合法写请求，安全校验必须同时验证允许与拒绝。
- Markdown 目录和正文分别解析，重复中文标题锚点容易失配。
- 首页文章流的持续加载必须去重、区分错误与到底，并保证 Footer 可达。
- Cloudflare 构建通过不代表重新验证可用，必须实际改变数据并等待缓存更新。
- 生成类型工具与 TypeScript 7 不兼容，通过隔离工具环境解决，而不是降级整个应用。

这些问题应分配到最能解释根因的文章中，不按开发日期写流水账。
