# 产品与设计决策

## 先明确这次重做解决什么

用户已经有产品、后端和管理后台，主要不满意的是原前台的设计和使用体验。同时明确要求技术方案保持不变，旧前台目录保留。因此，项目的成功标准包括两部分：新前台要有实质性的体验改善，也要能继续使用现有业务能力。

这使本次实现的重点落在信息组织、阅读体验、响应式、交互反馈和真实接口衔接上。重做数据库、升级框架、顺手补一个运营后台，都不能仅凭“可能更完整”就进入本次范围。

独立目录不仅方便比较新旧页面，也让用户可以保留旧方案、选择接入时机。这里的可回退性是产品交付的一部分。

## 设计确认的粒度决定开发边界

用户最初描述了传统门户首页，随后明确指出“只看到首页就推进全站”不合适。这个纠正很关键：首页确认不能代表文章阅读、登录注册、会员列表、错误状态都已经获批。

后续形成了 26 张页面及状态设计稿，用户再明确确认并授权自主开发。开发阶段因此可以自行处理常规实现选择，不需要每完成一个页面就重新询问；但这种授权仍受已确认布局、配色、技术方案和目录边界约束。

后续协作时，类似“所有页面确认了”应当对应明确的页面范围，而不是一句笼统的“风格没问题”。

## 清爽来自密度和层级，也来自颜色

已确认方向是白色或很浅的蓝色背景，深色但非黑色文字，少量蓝色点缀。实现中采用白色为主要内容底色，深蓝灰为正文和标题色，晴蓝用于链接、选中状态和主要动作，浅蓝用于焦点及导读区域。

保留传统门户的好处是入口可预测：顶部找栏目和搜索，首页看最新与推荐，正文页专注阅读，会员页集中处理个人记录。没有为了“现代感”把它改成大面积宣传落地页，也没有把会员中心做成管理后台。

同一套视觉规范不等于每页必须套同一张布局。首页有焦点和广告，文章页应把空间还给正文，登录页需要清晰的表单，分类索引需要表现树形关系。统一的是排版、颜色、间距与交互习惯。

## 首页几项具体取舍

焦点区域使用公开文章作为内容来源，支持显式配置，没有配置时从最新文章中选择候选，优先使用有封面的文章。这样新站接上现有 API 就能运行，不依赖一个并不存在的焦点管理接口。

焦点保留手动切换。读者可以控制阅读节奏，单篇时不显示多余切换控件。本次没有把自动播放视为必需能力。

广告区域按用户要求保持 120px 高。桌面与手机可以配置不同图片；没有素材时呈现浅蓝的站内系列导读。这比把一张宽幅桌面图压到手机上、让文字变得不可读更符合原需求。

文章流首屏由服务端输出，每批 10 篇，自动追加两批后转为手动继续。用户要求“可以一直往下刷”，同时页脚和手机侧栏也需要能到达，所以没有使用永不停下的自动追加。另保留正常分页入口，照顾直接定位和无脚本访问。

侧栏的“热门”明确使用累计阅读排序。没有时间窗口数据，就不称作“本周热门”。精选没有配置时隐藏，避免为了填满版面造出推荐依据。

## 设计稿里的示例字段不是后端承诺

设计稿表达页面意图，正式实现必须重新核对数据能力。

本次最典型的差异是收藏时间、点赞时间和作者额外介绍。现有端点没有提供的字段，没有从文章发布时间猜测，也没有把示例人物介绍直接留在页面上。收藏与点赞列表使用真实文章信息；阅读历史则使用端点实际提供的最近阅读时间。

同样，焦点、广告和精选暂时使用新项目的类型化配置。这个决定保留了所需展示，也遵守了不改后端和后台的边界。代价是运营调整需要改配置并重新发布；它不是已经具备后台编辑能力的运营系统。

如果今后编辑频率提高，才值得把运营位作为独立需求设计契约、后台和发布流程。

## 手机适配不能只是把桌面缩小

实际做了栏目折叠、多级菜单触摸展开、正文目录折叠、双栏改单栏、会员六项导航重排。广告高度仍保持 120px。

320、375、768、1024、1440px 的检查确认了主体没有横向溢出。这个证据说明这些视口下布局可用，不等于已经覆盖真实手机、所有浏览器、所有文章内容。

后续真实内容很重要：极长标题、不同封面比例、深层栏目、长代码和大表格，都可能使同一套样式出现不同表现。本次测试内容包含无图文章、四级分类、代码、表格和重复标题，但不是内容规模的完整代表。

## 自主开发与需要再次沟通的分界

这次可以自主决定组件拆分、接口封装修正、加载批次、缺图处理、测试账号和本地验证。它们服务于已经确认的目标，且没有改变业务范围。

如果下一步需要新增账号规则、扩展共享契约、修改原项目、创建远程资源、发布线上或切换域名，就应重新判断授权范围。用户说“自主完成开发”，并不自动等于“把生产站点换掉”。
