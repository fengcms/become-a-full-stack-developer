## 2. N10 整改（四审头号 TODO）

### 问题
7 个内联 401（like / favorites / notifications 系列）的 `code` 仅 `{1002}`，缺共享组件里的 `1004`（未携带令牌）分支；与 N7「线协议完全统一」目标内部不一致。

### 修复（廉价且彻底）
- 将 7 个内联 401 全部改为 `$ref: '#/components/responses/Unauthorized'`，与另外 39 个端点同款，现在 **46 个 `x-authz` 端点统一引用共享组件**，401 响应 `code` 集合均为 `{1002, 1004}`。
- **未误伤 login / refresh 的专用 401**：这两个端点的 401 是**有意区分**的鉴权错误（`1001` 密码错误、`1005` 账号禁用、`1003` 刷新令牌失效），保持内联不动——四审也认可其设计合理性。

### 顺带清理
修复过程中发现 N7 脚本遗留的**重复 `Unauthorized` 组件**（同一 key 在 `components.responses` 出现两次，YAML 后者覆盖前者、功能无碍但属脏数据），已删除冗余副本，现仅 1 个 `Unauthorized` 组件。

### 语义门硬化（回应 N6 盲区）
将三审遗留的 N7c「NOTE」升级为 **N10 断言**：任何内联 401 若 `code` 集合仅为 `{1002}`（即 N10 那种回归）立即 FAIL；并新增对共享 `Unauthorized` 组件 `code ∈ {1002,1004}` 的规范性守护。双门从 31 升 **33 条 OK**。

## 3. N9 残留整改（四审次要点）

四审指出契约仍非 100% 自包含：全文 23 处 02 引用中，3 处是**行为约束未机器化**。

### ✅ N9-2 状态转移矩阵 → 已机器化
- `Article.status` 新增 `x-allowed-transitions`，把 02 §2.3 的**六条合法有向转移**下沉进契约：
  `draft→pending`、`draft→published`、`pending→published`、`pending→draft`、`published→draft`、`published→pending`。
- 语义门新增 **N9-2 断言**：`x-allowed-transitions` 必须存在、状态值合法、且覆盖 02 §2.3 全部六条边。
- **角色条件仍由端点 `x-authz` 承载**（已机器化，四审已确认），不在 `x-allowed-transitions` 重复——这是有意的边界划分：状态图（哪些转移合法）机器化进契约，角色门槛（谁能发起）由端点授权判定。两道约束正交、互不冗余。

### ⏸ 另两处行为引用 → 留作非阻塞 TODO
- **§2.2 无限级树环检测**（不能挂到自身子孙下，否则 409/code 3002）
- **§3.3 阅读量去重算法**（SHA256 去重 + 24h 冷却）

二者均为**需约定才一致的实现细节**，不是「七端授权行为」这类核心分歧源；且过度下沉会侵入契约对算法实现的表述权，与「文章是产品、代码是素材、契约只定接口边界」的项目铁律相悖。四审亦判定其「不构成权威模糊」。故登记为 TODO，M1 动手时由对应后端篇目（M1-15 状态机 / M1 分类 / M3 阅读量）在 PRD 层落地，不污染 JSON 契约。
