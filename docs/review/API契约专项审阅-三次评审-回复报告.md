## 2. 逐条处理

### 🟠 N7（中·必做）16 个 `minRole:member` 端点缺 401 响应声明

**处理**
- 新增共享组件 `components.responses.Unauthorized`：401 + `code 1002`（令牌无效/过期）/`code 1004`（未携带令牌），以 `examples` 双样例结构化呈现。
- 脚本为**全部 46 个 `x-authz` 端点**挂 401（其中 38 个此前缺失：原 16 个 member 端点 + 23 个 editor/admin 端点原仅挂 403）；editor/admin 端点同时保留 403（403 = 已认证但无权限，401 = 未认证）。
- 修复脚本一处边界 bug：某端点 `description: >` 折叠块内含**真正空行**，被误判为顶层边界导致操作块提前截断、漏挂 401；修正边界逻辑后复跑，46 端点全覆盖。

**证据（语义门 N7a/N7b 实测）**
```
OK  全部 46 个需登录端点均声明 401（Unauthorized 组件，授权失败线协议完整）
OK  editor/admin 受限端点均声明 403（Forbidden 线协议完整）
```

**价值**：第 4 铁律要求未认证返回 401，共享组件使线协议统一，消除了「授权*决策*自包含、但授权*失败响应*未统一声明」的内部不一致；严格 linter（Spectral `owasp:security` / `operation-4xx-response`）不再对这 16 个端点报错。

### 🟡 N8（低·可选）`/me/*` 端点 `ownerOverride` 表征不一致

**处理**
- 为 `/me/favorites/{articleId}` 与 `/me/history/{articleId}` **显式声明** `ownerOverride{param: articleId, ownerField: userId}`（二者 path 参数 `articleId` 已声明、ownerField `userId` 为真实字段，语义门 R1c/R1d 通过）。
- 将第 4 铁律规则⑤改写为**机器可读表述**：`/me/*` self-scoped 等价于 `ownerOverride{ownerField: userId}`；含子资源路径参数的操作（如 `/me/favorites/{articleId}`）额外显式声明 `ownerOverride{param: 子资源参数名, ownerField: userId}` 以断言子资源归属当前用户。

**证据（语义门 N8 一致性实测）**
```
OK  /me/* 子资源端点均已显式声明 ownerOverride（表征一致）
```

**说明**：集合类 `/me/*`（GET/POST favorites、history、profile 等**无子资源 path 参数**）依规则⑤隐式归属即正确；强行声明 `ownerOverride` 会因「无真实 path 参数」触发 R1c 失败，故不声明——这是有意为之，非遗漏。

### 🟡 N9（中低）契约仍含 02 引用，「无需再读 02」言过其实

**处理**
- 硬规则导语「详见 02 文档」→「**已在本契约内逐条定义**，溯源细节见 02 文档」（三条规则本就写在契约内，无需外置）。
- 新增权威声明：「本文档中『见 02 §x / 详见 02 文档』均为**溯源注**，契约语义与约束以本 OpenAPI 契约为准」。
- 可选鉴权配置「见 02 §3.3」→「实现细节见 02 §3.3（以本契约为准）」。

**收敛措辞**：授权求值确已自包含（第 4 铁律 + 02 反向引用闭环，二审已确认）；其余 02 引用为域名语义溯源注，已明示「以本契约为准」，不再构成权威模糊。评审点名的两条**行为性**引用（硬规则导语、可选鉴权配置）均已下沉/标注；余者作为溯源注可接受。
