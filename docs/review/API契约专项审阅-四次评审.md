## 3. 独立挖出的新点（全在双门盲区）

### 🟡 N10（低危·非阻塞·N7c 强化）7 个内联 401 的 `code` 未与共享组件对齐

作者脚本 N7c 仅 NOTE"风格不一致"即放过，未验 `code` 集合相等。穿透脚本证实：

- 共享 `Unauthorized` 组件：`code ∈ {1002, 1004}`（双样例：未携带令牌 1004 + 令牌无效/过期 1002）。
- 7 个内联 401（like / favorites / notifications 系列）的 `code` **全是 `{1002}`**，缺 `1004` 分支。

**后果**：对"未携带令牌"这一最常见未认证场景，这 7 个端点在契约里**没有 `1004` 示例**。两实现若照各自 example 生成客户端，对相同输入可能返回 1002 vs 1004 分歧。严格说 1002（令牌无效）在宽松语义下可覆盖"未携带"，故属"口径不严格一致"而非"错误"，但既然 N7 的目标是"线协议完全统一"，应一并清零。

**修复（极廉价）**：将这 7 个内联 401 改为 `$ref Unauthorized` 共享组件，或将各自 example 补成 `{1002, 1004}` 双样例。

### 🟡 N9 残留（低危·非阻塞）契约仍非"100% 自包含"

回复称"授权求值确已自包含……无需再读 02"。授权*结果*确可仅凭契约 + 第 4 铁律推出（N1 真达成），但全文仍有 **23 处**指向 02，其中 3 处是**行为约束未机器化**的溯源：

- `状态转移合法性矩阵（02 §2.3）`——"当前 draft/published 时返 409/code 3003，不静默幂等"。
- `无限级自关联树环检测（02 §2.2）`——"不能挂到自己的子孙下，否则 409/code 3002"。
- `阅读量去重算法（02 §3.3）`——SHA256 去重 + 24h 冷却的细节。

这些是"需约定才一致的实现细节"，非七端分歧的*核心授权行为*，且已明示"以本契约为准"，故不构成权威模糊。但"唯一自包含地基"的措辞对其言过其实。建议：状态转移的"哪些转移合法"可下沉为机器可读（如 `Article.status` 加 `x-allowed-transitions` 或从 §2.3 矩阵提取枚举），把最后一截缺陷也斩断。

### ⚠️ 一处存疑叙事（不影响结论）

回复 §2 N7 称"脚本空白行误断操作块导致漏挂 401"的边界 bug。但现 `check_contract.py` 用 `yaml.safe_load` + dict 遍历，**不存在空行截断问题**——疑为旧版文本解析残留叙事。不影响 N7 有效性（独立穿透脚本已确认 46 端点全覆盖）。
