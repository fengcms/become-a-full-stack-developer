# 发布维护工具

「成为全栈」系列**发布后机械维护**的脚本目录。维护范围：镜像 URL、回填内链、链接审计。

## check_links.py — SOP-C 全量链接审计

一次运行覆盖三类缺陷，是**每轮维护的收尾标准动作**。

### 用法

```bash
# 默认路径（索引取 blog AI 目录，文章与 ARTICLES.md 取本仓）
python3 docs/publish-maintenance/check_links.py

# 只跑幽灵链 + 错链（跳过占位残留）
python3 docs/publish-maintenance/check_links.py --no-placeholder

# 机器可读（便于二次处理 / 留档）
python3 docs/publish-maintenance/check_links.py --json
```

仅依赖标准库，托管 venv 与系统 `python3` 均可运行。

### 检测项

| 代号 | 缺陷 | 定义 |
|---|---|---|
| A | **幽灵链** | 正文链接的 CSDN ID 在索引中**不存在**（多为手工录入的编造 URL） |
| B | **真错链** | ID 在索引中，但**文案指向的其实是另一篇**（严格口径判定） |
| C | **占位残留** | 正文仍留 `{{LINK:Mx-yy}}`，而其目标篇**已发布**（应已回填） |

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 全绿（幽灵 0 / 错链 0 / 残留 0） |
| `1` | 存在缺陷，需修复后复跑 |
| `2` | 输入文件缺失（索引 / 文章目录 / ARTICLES.md） |

### 两个真相源

| 源 | 文件 | 回答的问题 |
|---|---|---|
| 索引 | `/Users/fungleo/Documents/Blogs/materials/csdn-已发布链接.md` | 「线上**什么已发布**」（blog AI 生成，只读消费） |
| 清单 | 本仓 `ARTICLES.md`（🟢 已发布 行） | 「本地源**已发布范围**」→ 用于 C 项占位残留判定 |

两者滞后方向不同，故 A/B 用索引、C 用清单。

> ⚠️ C 项的「已发布」判定**只看表格行的状态单元格**（最后一列），不做整行子串匹配。
> 否则标题里的字面「已发布」会骗过判定——例：《投稿状态机：草稿、待审核与**已发布**》（M4-19）
> 曾被误判为已发布，连带把指向它的 2 处占位报成「残留」（2026-10-08 修复）。

### 「严格口径」为什么必要

正文链接文案常是**改写式**。例如《阅读量防刷：去重、冷却与计数写分离》被写作
「阅读量：时间桶去重与原子计数」——字面不相等，但指向正确：
字面比对会**误报 12 条**，严格口径为 **0**。

判定法：对每条链接取「文案 ↔ 目标标题」相似度，再取「文案 ↔ 全索引其余标题」的最高分，
**只有当别的标题明显更吻合（差值 > 0.28 且绝对值 > 0.55）才算错链**。
阈值定义在脚本顶部 `WRONG_GAP` / `WRONG_ABS`。

### 脚本生效前的手工流程（历史备查）

脚本落地前，SOP-C 靠手工分片 grep 完成，有两个坑：

- **超长行陷阱**：Grep 的 content 模式对超长行只输出 `[Omitted long matching line]`，
  被省略的行必须逐一 Read——错链恰恰藏在其中（实例：19 处省略行里藏着 2 处错链）。
- **沙箱 SIGTERM**：单次读取约 10 个文件即被截断，须分片落盘再合并。

脚本一次性读全量文件、逐行正则匹配，两个坑都不再存在。
