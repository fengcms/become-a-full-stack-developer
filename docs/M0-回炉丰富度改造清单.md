# M0 八篇回炉丰富度改造清单

> 本文是 M0（开篇/产品侧）八篇草稿回炉的**事实源与验收清单**。
> 背景：用户定调「文章是产品、代码是素材；设计主导+陪练语气；读者=初中级前端；标题=`成为全栈·产品篇·xxx`；基于 CSDN 评分规则需加丰富度（图/表/码/内链）；文末统一订阅 CTA 图」。
> 八篇目前仅停留在 `articles/` 草稿、未发布 CSDN。本清单逐篇列出「缺什么、加什么、怎么验收」，执行时照单施工、照单复验。

---

## 0. 全八篇通用规则（先对齐，再逐篇）

1. **标题改名**：每篇加前缀 `成为全栈·产品篇·`（见 §2 各篇新标题）。改后同步更新 `ARTICLES.md` 标题列。
2. **内链占位化**：所有「系列内」互链改用 `{{LINK:Mx-yy}}` token（附录 A 全量映射）。发布后由 blog AI 索引一次性注入真实 CSDN URL。
3. **仓库内文档链接保持真实**：指向 `docs/prd/00~02`、`docs/api/openapi.v1.yaml` 的相对链接**不** token 化，保留为普通 markdown 链接（读者在 GitHub 看得到）。
4. **配图占位化**：每篇需 2–4 张图，用 `{{IMG:图名}}` token 占位（§2 各篇指定图名与内容要点）。图资产清单见附录 B；**对应中文生图提示词（豆包专用）见《docs/M0-配图中文提示词包.md》**，发布前用其出图并托管后替换 token。
5. **文末 CTA**：八篇文末统一追加订阅图 `{{IMG:CTA-订阅专栏}}`。该图由订阅 Banner 单独生成（生成后替换 token 为 CSDN 托管地址；本次未生成，待你确认后再出图）。
6. **排版多样性体检**：每篇确保「表 / 码 / 图 / 引用块 / 列表」至少三类交替出现，避免连续大段纯文字。
7. **不注水铁律**：丰富度只服务于理解，不为了凑 CSDN 分灌水；密度优先（单篇约 2500 中文字 ±300）。
