## 1. 目标结构（规范 §1，摘要）

```
src/
├── config/          # 不变
├── db/              # 不变：client(getDb)/schema/migrate
├── middleware/      # 不变：auth/cors/error/validate
├── routes/          # 薄路由：校验 → 调恰好一个 service → 返回（文件按资源分，保持现状）
├── services/        # 领域服务：业务规则 + 所有 DB 查询
├── shared/          # 基础设施/纯工具：无领域概念、不依赖 services
└── types/           # 仅跨模块共享类型（被 ≥2 方引用）
```

要点：
- `routes/` 文件命名与现状一致（`articles-read.ts` 等），**不重命名**，只瘦身。
- `lib/` 的 27 个文件按规范 §3 映射表整体迁出：`领域相关` → `services/`，`基础设施/工具` → `shared/`。
- `db/`、`middleware/`、`config/`、`app.ts` / `worker.ts` 聚合方式**不动**。

---

## 2. 分层职责铁律（规范 §2）

| 层 | 允许 | 禁止 |
|----|------|------|
| **routes/** | 输入校验（委托 `middleware/validate` + zod）；调用**恰好一个** service 函数；用 `shared/response` 格式化返回 | 出现 `.select/.insert/.update/.delete`、`getDb()`、业务规则、手工序列化 |
| **services/** | 领域逻辑 + 所有 DB 查询；调用 `getDb()`、`shared/*`、其它 service、`types/*` | 直接拼 HTTP 响应（返回领域对象，交给 routes 格式化） |
| **shared/** | 跨领域基础设施/纯工具；可被任意层引用 | 引入领域概念、依赖 `services/*`、直接查库（`db-error` 仅做异常判定不查） |
| **types/** | 仅放被 ≥2 方引用的共享类型 | 放领域专属类型（如 `ArticleStatus` 留在 `services/article.ts`） |
| **db/ middleware/ config/** | 不变 | —— |

## 4. 批次计划（规范 §4）

- **B-试点（小资源，先跑通流程）**：`likes` / `comments` / `favorites` / `history` —— 体量小、风险低，先验证「抽逻辑 + 门禁复绿」回路。
- **B-主体**：`articles-*` / `categories-*` / `users*` / `auth` / `tags` / `site` / `upload` / `members` / `notifications` / `search` / `related` / `stats`。
- **B-收尾**：`lib/` 整体迁空并删除；`shared/` 更名收口；`types/` 抽取共享类型。

---

## 5. 每资源关键动作

1. 把 `routes/<res>.ts` 中的裸 `getDb()` / 查询 / 业务规则抽进 `services/<res>.ts`（同名或规范映射名）。
2. `routes` 仅保留：validate → 调恰好一个 service → `shared/response` 格式化。
3. `lib/*` 全部按 §3 映射表迁到 `services/` 或 `shared/`。
4. `AuthVars` 上提 `types/auth.ts`。
5. 删除空 `lib/` 目录。
