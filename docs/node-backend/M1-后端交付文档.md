## 二、技术栈与运行目标

| 维度 | 选型 |
|---|---|
| 运行时 | Node.js ≥ 20（推荐 22） |
| Web 框架 | Hono 4.x（跨 CF Workers / Node） |
| ORM | Drizzle（schema 即类型） |
| 数据库 | Cloudflare D1（SQLite）/ 本地 SQLite（better-sqlite3），经 `getDb()` 适配层 |
| 对象存储 | Cloudflare R2（主）/ 本地磁盘兜底（R2 分支 Node 测试抛错，D10/B10 deferred） |
| 校验 | Zod（信任边界最外层校验） |
| 测试 | vitest + Hono `app.request()`（不引 supertest） |
| 语言 | TypeScript strict 全开（零 `any`、`verbatimModuleSyntax`、`noUncheckedIndexedAccess`） |

**适配层（双部署基石）**：DB 访问收敛到 `getDb()`，文件存储收敛到 `StorageProvider`（`STORAGE_DRIVER=r2|local`）。业务代码不直接 `new D1Database()` 或硬编码 bucket；模块顶层零副作用（`app.ts` 仅导出工厂 `createApp`，实例在 `index.ts`/`worker.ts` 构造）。

## 三、工程纪律（统筹 AI 评审改动时务必遵守）

1. **契约只读**：`docs/api/openapi.v1.yaml` 已冻结（v1.11.0）。任何实现缺陷 → 在批次 NOTES 登记并回流总把控改契约，**绝不擅自改契约**。
2. **单一事实源**：Drizzle `schema.ts` 表/字段名 = 契约 JSON / `02-领域模型与API契约.md` §二；DB snake_case，响应 camelCase，在序列化层转换。
3. **统一信封**：成功 `{code:0,message,data,requestId,timestamp}`；错误同信封、明细放 `data`（4001 的 `data.errors`）。**不**套 `error` 包裹层。
4. **错误码集合**：仅实现契约列出的 `code`（1002/1003/1004/1005/3002/3003/4001/5000 等），不自造。
5. **鉴权角色**：`member`/`editor`/`admin`；令牌角色是登录快照（提权须先改库再签发）。端点门槛以契约 `x-authz`（minRole + ownerOverride）为准。
6. **状态机**：`Article.status` 转移受契约 `x-allowed-transitions` 机器约束；`Comment.status` 未机器化，按 02 §二 语义（会员投稿默认 `reviewing`，`approved` 才公开可见）。
7. **行数铁律**：单文件 ≤200 行；超限须抽共享 lib 或拆分（已有 `articles-read/write`、`categories-read/write`、`comments-read/write`、`users/users-admin/me/members/upload/files`、`favorites/history/likes/notifications` 等先例）。
8. **读写分野**：Drizzle 写 `.run()`、读 `.all()`、要回读 `.returning().all()`。
9. **路径别名**：跨目录一律 `@/`（相对引用仅限 `./` 同目录）。
10. **契约一致性门禁**：每批除 tsc/biome/vitest 外，须逐端点核对响应字段、`error.code` 与契约一致。

## 六、已知留口 / 待办（非阻塞，跨端协调时留意）

以下均为**非缺陷、按审阅裁定留作后续**，统筹 AI 安排其他端或后续批次时留意：

1. **`MemberProfile.articles` 可选未返回**（B7 P3-3）：契约 `MemberProfile` 该字段可选，当前 `search`/`members` 不返回会员文章列表；若前端依赖需增量补。
2. **toc 锚点去重极端边界**（B7 P3-4）：超长标题（近 100 字）且大量重复时锚点可能 >100 字符，极边缘，未防护。
3. **adjacent 同 `publishedAt` 无 tie-breaker**（B7 P3-5）：多篇同 `publishedAt` 顺序不稳定，实际近似唯一，低风险。
4. **契约层不一致（B6 P3-3/P3-4）**：`GET /me/likes` 响应为裸数组但声明 page/pageSize 参数（契约矛盾），后端按契约返裸数组+limit/offset 截断；`schema.ts`(357 行) 超限沿用「全表单一事实源」先例不拆。**这两项属契约维护批次统一整改，非代码问题。**
5. **通知生成端未落地**（B6 禁止项）：文章发布 / 评论审核通过 → 写 `Notification` 的触发逻辑不在后端本批（任务包禁止），留对应业务批次或后续补。
6. **R2 双存储 Node 测试抛错**（B5 D10/B10 deferred）：`STORAGE_DRIVER=r2` 时 Node 测试环境不服务真实 R2，本地预览走 `local` + `files.ts` 直出。
7. **nullable 唯一索引「假唯一」**（B1-R5 / B2-R6）：`email`、`slug` 可空唯一索引对 `NULL` 不冲突（部分唯一索引特性）——B5/B2 已就位，跨端实现者勿误判为缺陷。
