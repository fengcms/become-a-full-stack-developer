## 四、已确认的良好实践（给开发 AI 的 credit）

- **刷新旋转 + 重放家族作废闭环正确**：`rotateRefreshToken`（`refresh.ts:59`）先查哈希 → 已作废则 `revokeUserTokens(row.userId)` 连带作废整个家族（`refresh.ts:73`，对应契约"重放 → 须重新登录"）→ 过期 1003 → 校验用户禁用 1005 → 作废旧行 `revokedAt` 并签发新值。逻辑顺序严谨，无 TOCTOU 漏洞（先判定失效再作废旧行）。
- **刷新令牌仅存哈希**：`issueRefreshToken`（`refresh.ts:38`）明文令牌只返回一次，库内仅 `sha256` 摘要（`refresh.ts:28`），即便 DB 泄露也无法还原明文。
- **密码哈希到位**：`password.ts` 用 `bcryptjs`（零原生编译，契合双端），cost 12，注册/登录低频可接受；`hashPassword` 异步且被 `await`。
- **Cookie 安全属性正确**：`auth.ts:57` `HttpOnly; SameSite=None; Secure; Path=/`。`SameSite=None` 配 `Secure` 符合规范；`Max-Age` 与 `REFRESH_TTL_MS`（7d）一致。
- **脱敏严格**：`toPublicUser`（`user.ts:39`）`passwordHash` 绝不外泄；`email` 仅存在时返回（契约"仅本人/ admin 可见"）。
- **统一错误模型沿用 B0**：全部业务错误经 `ErrCode` + `HttpForCode` 双层码，编译期漏配即报错；`me` 的防御性 404（3001）合理。
- **测试覆盖扎实且针对性强**：16 个鉴权测试显式断言每个专用码（1001/1003/1004/1005/3002/4001/5000），并覆盖"重放→家族作废""登出→刷新失效"等闭环行为，远超 B1 任务包验收门禁的最低要求。
- **复用 B0 纪律**：`@/` 别名、零 `any`、箭头函数、`verbatimModuleSyntax`、`noUncheckedIndexedAccess` 全保留（biome 34 文件 0 问题佐证）。

## 五、发现的缺陷（按严重度）

### 🟡 P2 — 建议改进（全部非阻塞，不阻 B2）

#### P2-1 · 并发重复注册返回 500 而非 409（TOCTOU 未兜底）
- **证据**：`auth.ts:73-78` 先 `select` 查重，再 `insert`；两个并发同用户名请求可同时通过查重，其一 `insert` 命中 `uniq_username`/`uniq_email` 唯一约束抛错，未被捕获 → 顶层 errorHandler 归为 `INTERNAL/500`。
- **影响**：理论竞态（测试库同步、低频注册，实际罕见），但语义上"真实的唯一冲突"返回了 500 而非契约约定的 409/3002。
- **建议**：`insert` 包 try/catch，捕获唯一约束冲突（或 `better-sqlite3` 的 `SqliteError` code `SQLITE_CONSTRAINT_UNIQUE`）后改抛 `CONFLICT/409`；或在查重与插入间以事务/UPSERT 收敛。低优先，B2 前可顺手修。

#### P2-2 · 契约内部自相矛盾：refresh "缺失令牌" 的 code 描述与示例不一致
- **证据**：契约 `POST /auth/refresh` 描述写"两者皆无 → 401 / code **1003**"（`openapi.v1.yaml:864`），但其 401 `examples` 中 `token_missing` 明确为 **1004**（`openapi.v1.yaml:906-913`），且 `Unauthorized` 共享组件定义 1004=令牌缺失。
- **代码处理**：`auth.ts:137` 抛 `TOKEN_MISSING/401`(1004)，**与示例、与共享组件一致**，故代码正确；不一致的是契约**描述散文**。
- **影响**：纯契约文档瑕疵，代码无偏离。但"描述说 1003、示例说 1004"会误导后续端（Go/M3）实现者。
- **建议**：把描述改为"两者皆无 → 401 / code 1004（令牌缺失）"，与示例、共享组件、代码三方对齐。在 B1 不动契约的大前提下，可登记 TODO 由契约维护批次统一修；当前不阻塞。

#### P2-3 · 测试注释 stale（"501 占位" 实为 500）
- **证据**：`test/routes/auth-flow.test.ts:146` 注释写"合法 provider → 501 占位（500 + code 5000）"。B0 复批已将契约 `callback` 由 501 修正为 500，`Unauthorized` 亦无 501，断言 `res.status).toBe(500)` 正确；仅注释文字沿用了旧口径。
- **影响**：无功能影响，仅阅读困惑。
- **建议**：注释改为"500 占位（B0 已将契约 501→500）"。

#### P2-4 · `GET /me` 二次查库（轻微冗余）
- **证据**：`auth.ts:154-163` `me` 已从 JWT 拿到 `user.id`，仍 `select` 全行。设计上合理（取最新资料 + 防御性 404），非错误。
- **影响**：每次 `/me` 多一次查询，鉴权高频端点下略有开销；当前规模可忽略。
- **建议**：若后续要压测可改为"JWT 直返已签发用户信息 + 按需查库"，但**不要求改**。
