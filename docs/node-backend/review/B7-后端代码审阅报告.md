## 三、P2-1（阻塞）：PATCH site/settings 的 `logoUrl` 漏 `.nullable()`

### 契约机器字段（openapi.v1.yaml）
- `SiteSettingUpdate.logoUrl`（606 行）：`{type: string, nullable: true, maxLength: 512}` —— **允许传 `null` 清空**。
- `SiteSettingUpdate` 其余 nullable 字段：siteTitle / siteKeywords / copyright 均 `nullable: true`；siteName / siteDescription 不可 null。

### 代码（src/routes/site.ts）
- `updateSchema`（49-56 行）：`logoUrl: z.string().max(512).optional()` —— **缺 `.nullable()`**。
- 对照同 schema 其余字段：`siteTitle / siteKeywords / copyright` 都正确写了 `.nullable().optional()`；唯独 `logoUrl` 漏掉。
- 中间件 `v.json(updateSchema)` 对 `null` 的反应：zod `.optional()` 不接受显式 `null`（等价于 `union([string, undefined])`）→ 抛 ZodError → **4001 VALIDATION**。
- 后果：契约承诺「`PATCH` 传 `logoUrl: null` 清空 Logo」，实际任何 admin 想清空 Logo 都会收到 400，功能不可达。

### 自陈矛盾（红线触发）
NOTES §二.7 明写「`null` 显式清空（如 `siteTitle`、`logoUrl`）」——与代码（logoUrl 不能 null）直接矛盾。**自陈与磁盘不符**，正是「压缩记忆导致细节丢失」的典型症状。

### 修复（一行）
`src/routes/site.ts:54` 改为 `logoUrl: z.string().max(512).nullable().optional()`。修复后 `if (patch.logoUrl !== undefined)` 对 `null` 为 true → `set.logoUrl = null` → DB 清空，行为正确。并补一条「`logoUrl: null` 清空」回归测试（当前 `aux.test.ts` PATCH 段 354-399 未覆盖该路径，与实现漏项同源）。

### 判别
满足 P2「破坏契约机器字段（requestBody schema 不一致）+ 自陈不实」。收尾冻结批次，契约一致性须清零，故**阻塞放行**。

## 四、P3 非阻塞（不阻放行，但需修正陈述）

1. **P3-1（NOTES 事实错误）**：`related.ts:6-7` 注释 + NOTES §二.3 称「`article_tags` 关联表按 B3 禁止项暂未回填，故用 denormalized 列」。事实是 **B3.5 已回填 `article_tags`**（B3.5 审阅 78/78 全绿）。更重要的是：`related` 读的是 `articles.tags` 去规范化 JSON 列（`schema.ts:87` 注释「JSON 字符串，B2 去规范化」），B2 创建文章即填充，**与 junction 是否回填无关**——逻辑本身正确。问题仅在 NOTES/注释的事实陈述错误，会误导后续接手者。建议修正陈述，不阻塞。
2. **P3-2（operationId 笔误）**：NOTES §一 表列 `getAdminSiteSettings`，契约该端点 operationId 为 `adminGetSiteSettings`（3124 行）。纯文档命名笔误，代码不绑定 operationId 字符串，无功能影响。
3. **P3-3（MemberProfile.articles 未返回）**：契约 `MemberProfile`（261 行）含可选 `articles`（该会员 published 文章列表），代码 `search.ts` 的 `MemberProfile` 仅返回 `{id, nickname, avatar, level, articleCount}`（不含 `articles`）。因 `articles` 在契约 `required` 之外（可选），缺省合法；但契约确有该可选字段，后续若前端依赖需补。
4. **P3-4（toc anchor 极边界）**：`toc.ts` `slugify` 截断 100 后追加 `-n` 去重，超长标题 + 多次去重可能使锚点 >100 字符。极端边缘（标题近 100 字且大量重复），可忽略或后续防护。
5. **P3-5（adjacent 同 publishedAt 无 tie-breaker）**：`related.ts:57-70` 仅按 `publishedAt` 先后取 prev/next，多篇同 `publishedAt` 时顺序不稳定。实际 `publishedAt` 近似唯一（创建时间），低风险。
