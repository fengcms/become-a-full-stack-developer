## 四、安全与正确性重点核查

1. **脱敏双路正确**：私有路径走 `toPublicUser`（剥离 `passwordHash`），公开路径 `members.ts` 手搓对象（剥离 email/role/status）。`toPublicUser` 全项目仅用于 admin/self 上下文（users/users-admin/me/auth），从不返回给匿名或他人 → 无越权泄漏。✅
2. **ownerOverride 矩阵正确**：`DELETE /attachments/{id}` —— member 删自己（resolver 命中）→ 200；member 删他人 → 403；editor/admin 绕过 resolver 直接放行（角色达标）→ 删；缺失附件 → resolver 抛 404（member 路径）/ `changes===0` 兜底 404（editor/admin 路径）。测试 `删他人附件→403；删自己→200` 直钉。✅
3. **disabled 会员防枚举**：`members.ts:21` `!user || user.status==='disabled' → 404`，与契约 2316 描述一致。✅
4. **上传信任边界**：`parseUpload` 校验 MIME 白名单（png/jpeg/gif/webp/svg+xml/pdf）+ `MAX_BYTES=10MB`；不合法 → 400 code 4001（`data.errors=[{field:'file',...}]`），与契约一致。✅
5. **双存储真实边界**：`upload.ts:137-143` 行删除后尽力删底层对象，`storage.delete` 失败 catch 记日志、不阻塞行删除 —— 与契约 2270 描述一致，也契合主计划"适配层"题材（M1-24）。✅ `storage.ts` 的 `resolveKey` 用 `SAFE_KEY` 正则（B04 裁定）防路径遍历。✅
6. **密码安全**：`change-password` 校验旧密码（`verifyPassword`）→ 更新哈希 → `revokeUserTokens` 强制重登；`admin reset-password` 同样 `revokeUserTokens`。复用 `lib/password.ts` bcrypt 封装（cost 12），哈希不可逆。✅
7. **邮箱冲突**：`PATCH /me/profile` 改 email 撞唯一约束 → `isUniqueConstraintError` 收敛 409/3002（B1 工具跨批复用）。✅

## 六、P3 非阻塞观察（均不阻放行）

**P3-1（本地预览缺口）**：`POST /upload` 返回 `/files/{key}` URL，但 `app.ts` 无 `/files/*` 静态路由；本地磁盘文件写入 `node-backend/uploads/` 却无法经本后端访问。生产走 R2+CDN 不受影响，但**本地开发（编辑器素材库）预览会 404**。建议：本地环境加 `serveStatic('/files', './uploads')` 兜底路由（仅 dev），或文档明确"本地预览需切 R2"。非阻塞（生产无影响）。

**P3-2（成员文章列表未分页）**：`members.ts:23-47` 用 `.all()` 取该会员**全部** published 文章，无分页上限；`articleCount` 取 `rows.length`（因无 limit，计数正确）。高产作者响应体积随文章数线性增长。建议加 `pageSize`/`page` 分页（与公开列表一致）。非阻塞（当前数据量小）。

**P3-3（upload 双 `parseBody`）**：`upload.ts:63` `parseUpload(c)` 内部已 `parseBody({all:true})`，`:64` 又 `parseBody` 取 `articleId`，重复解析。功能因 Hono `bodyCache` 正常，但浪费一次 IO；biome 已标 2 info（风格 `form['articleId']`→`form.articleId`）。建议 `parseUpload` 一并返回 `articleId`，或只在 `upload.ts` 解析一次后传入。非阻塞。

**P3-4（锁定保护缺失）**：`PATCH /users/{id}` 允许 admin 将任意用户（含其他 admin、自己）置 `status=disabled` 或晋升/降职 `role`。无"最后 admin 保护"与"自我降级/封禁阻断"。属 MVP 运维风险，建议后续加护栏（last-admin 守卫 + 自我 status 变更确认）。非阻塞（admin 操作）。

**P3-5（SVG XSS 面）**：白名单含 `image/svg+xml`。SVG 可嵌脚本，若 CDN 以 `image/svg+xml` 内联提供有 XSS 风险。建议：存储层对 SVG 做 content-sniff 净化，或强制 `Content-Disposition: attachment` / `X-Content-Type-Options: nosniff`。非阻塞（生产由 CDN 策略决定，且本地未服务该文件）。
