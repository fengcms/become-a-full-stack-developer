## 二、逐条复批取证（不采信自陈）

### ✅ P2-1 · 并发重复注册 500→409（真缺陷，确证清零）

**核验 1 — `src/lib/db-error.ts`（全新文件，全量读）**
```ts
const UNIQUE_CONSTRAINT_CODES = ['SQLITE_CONSTRAINT_UNIQUE', 'SQLITE_CONSTRAINT'] as const;
export const isUniqueConstraintError = (err: unknown): boolean => {
  if (!err || typeof err !== 'object') return false;
  const code = (err as { code?: unknown }).code;
  return typeof code === 'string' && (UNIQUE_CONSTRAINT_CODES as readonly string[]).includes(code);
};
```
- 结构化类型判定（`'code' in err && typeof==='string'`），**零 `any`**，符合 biome `noExplicitAny` 铁律。
- 识别 `SQLITE_CONSTRAINT_UNIQUE`（唯一约束专用码）+ `SQLITE_CONSTRAINT`（父码兜底），跨驱动兼容。
- 设计上是**可复用工具**，B2 文章 slug 唯一冲突等场景统一复用，不散落字符串嗅探。

**核验 2 — `src/routes/auth.ts:84-103`（注册 insert 真实包 try/catch）**
```ts
let inserted: User[];
try {
```

## 五、非阻塞观察（2 项极轻量，不阻 B2）

> 以下为"完美"口径下的锦上添花建议，非缺陷、不要求改。

1. **`isUniqueConstraintError` 匹配略宽（P3）**：当前把父码 `SQLITE_CONSTRAINT`（含 NOT NULL / 外键等子类型）也当唯一冲突。在 register 路径实际只会命中 username/email 唯一约束，风险极小；若要更精确可只匹配 `SQLITE_CONSTRAINT_UNIQUE`。
2. **catch 兜底分支缺确定性单测（P3）**：TOCTOU 并发竞态单线程单测难以确定性触发，开发者已诚实标注。可考虑补一个**纯函数单测**直接喂合成 `SqliteError({code:'SQLITE_CONSTRAINT_UNIQUE'})` 断言 `isUniqueConstraintError` 返回 truthy——这一支是确定可测的，且成本低、能锁定工具语义。
