## 二、逐项回应

### P3-1（已修复）· 本地 `/files` 静态路由缺失，预览 404

- **根因**：`POST /upload` 返回的 url 形如 `/files/{key}`，但 `app.ts` 此前无 `/files/*` 静态路由，本地磁盘文件（写在 `node-backend/uploads/`）无法经本后端访问，本地开发预览素材库会 404（生产走 R2+CDN 不受影响）。
- **修复**：新增 `src/routes/files.ts`（**52 行**），仅在 `STORAGE_DRIVER==='local'` 时直出：
  - `GET /files/:key` → 读 `./uploads/{key}`；`key` 经 `SAFE_KEY`（`/^[A-Za-z0-9._-]+$/`）正则校验，防路径遍历（与 `storage.ts` 同源防护）。
  - 生产（`STORAGE_DRIVER==='r2'`）直接 404 不服务——生产 URL 是 CDN，前端不会请求 `/files/*`，无副作用。
  - `app.ts` 新增 `app.route('/files', filesRoute)`。
- **验收**：本地上传后 `GET /files/{key}` 返回 200 + 原始字节（测试 `本地 /files/{key} 可直接访问上传文件` 直钉：body 为 `hello-world`、响应头含 `X-Content-Type-Options: nosniff`、Content-Type `image/png`）。

### P3-2（已修复）· 成员文章列表未分页

- **根因**：`members.ts` 用 `.all()` 取该会员**全部** `published` 文章，高产作者响应体积随文章数线性增长；`articleCount` 取 `rows.length`（无 limit 时计数正确，但无分页能力）。
- **修复**：弃用手写全量查询，改为复用 `queryArticles`（来自 `lib/article.ts` 的统一列表查询）：
  ```ts
  const page = await queryArticles({ c, authorId: id, forcedStatus: 'published' });
  return ok({ /* ... */ articleCount: page.pagination.total, articles: page.list });
  ```
  - 自动获得与公开列表一致的 `page`/`pageSize`/`sort` 分页参数与投影逻辑，不再重复实现。
  - `articleCount` 取分页 `total`，语义不变。
- **验收**：`members.ts` 由 59 行降至 **37 行**；`queryArticles` 已含 `isNull(deletedAt)` + `status='published'` 过滤，行为与旧实现等价，且新增分页能力。

### P3-3（已修复）· `upload` 重复 `parseBody`

- **根因**：`parseUpload(c)` 内部已 `parseBody({ all: true })` 取 `file`；POST handler 随后**又** `parseBody` 一次仅取 `articleId`，重复解析（Hono `bodyCache` 缓冲突兀，功能无损但浪费一次 IO）；biome 亦标 2 条 `form['x']`→`form.x` info。
- **修复**：`parseUpload` 一次性解析并一并返回 `articleId`：
  ```ts
  const parseUpload = async (c): Promise<{ buffer; ext; mime; articleId: number | null }> => {
    const form = await c.req.parseBody({ all: true });
    /* ...file 校验... */
    const rawId = form.articleId;
    const articleId = typeof rawId === 'string' && rawId !== '' ? Number(rawId) : null;
    if (articleId !== null && !Number.isInteger(articleId)) throw VALIDATION(4001, 'articleId 须为整数');
    return { buffer, ext, mime: file.type, articleId };
  };
  ```
  - POST handler 改为 `const { buffer, ext, mime, articleId } = await parseUpload(c);`，删除第二次 `parseBody`。
  - `form['file']`/`form['articleId']` 改点号访问 `form.file`/`form.articleId`，消除 biome info。
- **验收**：`upload.ts` 由 148 行微调至 **150 行**（新增 articleId 解析逻辑，删除重复调用）；biome 2 info 清零；`tsc`/`vitest` 全绿。

### P3-4（已修复）· 用户管理锁定保护缺失

- **根因**：`PATCH /users/{id}` 允许 admin 将任意用户（含其他 admin、自身）置 `status=disabled` 或升降 `role`，无「最后 admin 保护」与「自我降级 / 封禁阻断」，存在 MVP 运维锁死风险。
- **修复**（均在 `users.ts` 的 PATCH handler，复用既有 `and/eq/sql`）：
  - **① 自我护栏**：当本次含 `role` 或 `status` 变更且 `Number(c.get('user').id) === id` 时，返回 `403 FORBIDDEN`（code 2001）—— admin 不能变更自己的角色/状态，防自我降级或封禁导致锁死。
  - **② 最后 admin 保护**：当被操作者是 `admin` 且本次将失去 admin（`role!=='admin'`）或遭禁用（`status==='disabled'`）时，统计活跃 admin 数（`eq(role,'admin') & eq(status,'active')`），若 `≤1` 则返回 `409 CONFLICT`（code 3002）「至少保留一名活跃 admin」。
  - 纯 `level` 变更（仅展示用）不受这两道护栏限制。
- **说明**：真实场景下「降级/封禁唯一 admin」的触发者只能是该 admin 本人，会被①自我护栏（403）先行拦截，故②为防御性兜底（理论不可达但符合审阅建议的护栏意图）。
- **验收**：新增测试 `admin 不能变更自己的角色/状态 → 403`（code 2001）、`两位 admin 时降级另一位 → 200`（证明护栏不误伤正常双 admin 运维）；`users.ts` 由 87 行增至 **116 行**（≤200）。

### P3-5（已缓解）· SVG XSS 面

- **根因**：白名单含 `image/svg+xml`，SVG 可内联脚本，若以 `image/svg+xml` 内联提供有 XSS 风险。
- **缓解**：`files.ts` 在直出路径上对 `image/svg+xml` 强制 `Content-Disposition: attachment`，并统一加 `X-Content-Type-Options: nosniff`（非 svg 用 `inline`）；本地预览路径下 SVG 不再被浏览器内联渲染。
- **边界**：生产 CDN 侧的 `Content-Disposition` / `nosniff` 最终策略由 CDN 配置决定（属契约 / 运维配置范畴），本批仅补「本地直出路径」的缓解，已覆盖本地开发预览这一最易被忽视的面。
- **验收**：测试 `SVG 经 /files 返回强制下载头（XSS 缓解）` 直钉 `Content-Disposition: attachment`。
