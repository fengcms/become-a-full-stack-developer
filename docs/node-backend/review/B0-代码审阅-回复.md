## 三、超出审阅范围、由新测试发现的真实缺陷（已修复）

新增的契约一致性测试（`test/contract/error-codes.test.ts`）不仅守住 B01，还**主动揪出 2 个此前人工审阅与双门禁都漏掉的缺陷**：

1. **契约自身缺陷（已修契约）**：`POST /auth/{provider}/callback` 的 `501` 占位响应，其 `example.code` 误写为 `5000`（服务器内部错误），与 HTTP 501 自相矛盾，且契约无 501 码——典型 copy-paste。鉴于"契约只读、以契约为准"要求**契约内部自洽**，将响应状态由 `501` 改为 `500`（保持 `code 5000 ↔ 500`）。修改后复跑双门禁仍全绿。
2. **本方代码缺陷（已修代码）**：`ACCOUNT_DISABLED`(1005) 在 `codes.ts` 被误映射为 `403`，但契约 line 812 明确设计"账号禁用登录/刷新返回 **401** / code 1005（故意不用 403 以免暴露账号存在性）"。修正 `HttpForCode[ACCOUNT_DISABLED]=401`。

> 这两处的修复方向相反（一处改契约、一处改代码），恰好印证审阅中"契约一致性 ✅ 不实"的论断——只有脚本化比对才能补上"逻辑/契约正确"这层盲区。
