### P3-2（已修复）· DELETE 重复查库

- **根因**：`resolveCommentOwner`（guard 内）已查一次评论用于归属判定与存在性 404；handler 又 `select` 查一次 `existing` 仅作存在性 404——功能正确，仅冗余。
- **修复（类型安全、不引入自定义 `c.set`）**：删除 handler 内的 `existing` 重查，改为复用删除 `run()` 返回的 `changes` 判定存在性——
  ```ts
  await db.delete(comments).where(eq(comments.parentId, id)).run(); // 级联删子回复
  const res = await db.delete(comments).where(eq(comments.id, id)).run();
  if (res.changes === 0) throw new AppError(ErrCode.NOT_FOUND, 404);
  ```
  - member 路径：缺失评论由 `resolveCommentOwner` 先 404；
  - editor/admin 路径：guard 短路不调 `resolveCommentOwner`，改由 `res.changes === 0` 兜底 404——**所有角色删不存在评论均 404**，行为不变，且少一次 SELECT。
  - 刻意不采用审阅建议的 `c.set('comment', row)` 复用：该写法会破坏 `AuthVars` 类型（仅声明 `user`），正是上一轮修复轮已剔除的反模式，故用 `changes` 判定替代。
