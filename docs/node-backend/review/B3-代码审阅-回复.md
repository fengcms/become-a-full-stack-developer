## 二、逐项回应

### P2-1（已修复）· 移动带子孙的子树可能越过 x-max-depth:4
- **根因（审查推演成立）**：`categories-write.ts` 变更 parentId 仅校验 `depthOf(新父) + 1`（被移动节点自身新深度），未计入其子孙子树高度。把 `A(深3)→B(深4)` 挂到另一深3节点下时，`A` 变4、`B` 变5，违反契约 `x-max-depth:4`。
- **修复**：`lib/category.ts` 新增纯函数 `subtreeHeight(rows, id)`（含自身、单节点=1）；`categories-write.ts` PUT 校验改为 `depthOf(新父) + subtreeHeight(被移动节点) ≤ MAX_CATEGORY_DEPTH`。
- **测试**：`test/routes/categories.test.ts` 新增「移动带子孙的子树使子孙超界 → 409」集成测试，含「叶子（depth4）移到同深父允许」正对照，证明新校验不误杀合法移动。
- **NOTES 过度声称更正**：`B3-NOTES` 第 3 节原「覆盖把某节点挂到深节点下使其超界」对**被移动节点自身**成立、对**其子孙**原先不成立，已据本项修正重写，明确 `subtreeHeight` 把关。

### P3-1（已修复）· `buildTree` 缺数据环防御
- **修复**：`lib/category.ts` 的 `buildTree` 递归内持 `seen` 集，命中自身即截断、不展开子孙、不死循环——与 `depthOf`/`toBreadcrumb` 同款防御（审查亦指出这两处已有，现已统一补齐）。
- **测试**：`test/lib/category.test.ts` 新增 `buildTree` 环防御单测（人为构造 `1→2→1` 自循环数据集），断言返回值节点数有界（≤ 输入规模）且不挂死。
- **说明**：单父约束下纯环无 null 根不会进入遍历，但 `seen` 是数据腐化时的硬兜底，零成本保留。
