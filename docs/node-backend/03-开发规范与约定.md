## 一、用户的 6 条硬性编码约定

1. **思考即文档**：编码过程中任何有价值的思考（大或小、架构或踩坑），随手落到 `docs/node-backend/`，文体/风格不限，目的是让"后面的我"和"相关 AI"能学习。统一收口到 `DEV-LOG.md`（按批次追加），重大决议另开文件。
2. **代码精炼、可讲、可炫**：这是**学习教程性质**项目，代码要经得起检验；能封装/抽象/共用的务必提炼；命名优雅、风格规范；**允许在恰当处"炫技"**——但可读性仍是底线。
3. **注释与篇幅**：
   - 每个文件头部必须有"该文件说明"注释块。
   - 每个函数必须有 TSDoc 风格注释（`/** ... */`）。
   - **单文件尽量 ≤ 200 行**；确属特殊情况超长的，必须加注释说明原因。
4. **工程化**：
   - 包管理用 **pnpm**。
   - 默认用**箭头函数**；除非必要，不写 `function` 声明。
5. **质量门禁**：
   - 代码用 **Biome** 格式化（`pnpm format`）。
   - **禁止 `any` 主类型**（用精确类型 / 泛型 / 类型推导替代）。
6. **更优雅的实现**：对上述各项，凡我能想到更优雅的写法（更少的样板、更强的类型安全、更清晰的抽象），主动采用，并在 `DEV-LOG` 注明。

## 三、B0 落地的具体规约（供后续批次继承）

- **信封构造器** `src/lib/response.ts`：返回原生 `Response`（`Response.json`），与 Hono 解耦，便于单测与跨运行时复用。
- **错误模型** `src/lib/http-error.ts`：`AppError(code, httpStatus?, message?, details?)` + `fail()` 抛出助手，返回 `never`。
- **鉴权守卫** `src/middleware/auth.ts`：`authMiddleware`（Bearer→`c.set('user')`）+ `guard(minRole, resolveOwner?)`（实现第 4 铁律 ④(a) 角色阶梯 **OR** ④(b) 归属者放行）。
- **环境** `src/config/env.ts`：`zod` 解析 + `setActiveEnv/getActiveEnv` 单例，业务与中间件不直接读 `process.env`。
- **DB 适配** `src/db/client.ts`：`getDb/setDb` + `createLocalDb`（better-sqlite3）/ `createD1Db`（CF D1，受控转换边界）。
- **测试** 用 Hono 内置 `app.request()`，不引入 supertest。
- **文件头注释模板**：见 `src/` 各文件头部。
