# 微信登录最小契约增补说明

2026-10-07。用户已授权本轮增补、后端开发、本地与线上迁移和部署。只推进后端；不开发小程序、APP 或网站微信入口。

基线为 OpenAPI 1.11.0，本轮兼容增补至 1.12.0。不覆盖历史冻结版本：历史可从 Git 获取，既有登录/注册/刷新/改密的请求要求保持不变。

## 唯一新增能力

1. 实现现有 `POST /api/v1/auth/wechat/callback`：仅 code 必填；服务端验证微信身份，首次自动创建 member，否则登录原 userId。补充 400/401 失败响应，保留 429/500。不实现微博/GitHub。
2. User 增加可选 `canSetCredentials`，缺失按 false。它是服务端计算的首次设置资格，不接受客户端修改。
3. 新增 `POST /api/v1/me/setup-account`：Bearer 身份 + username/password，成功返回既有 AuthResult，同时刷新 Cookie。重复设置、旧账号或用户名冲突 409/3002。禁用用户拒绝。确认密码仅前端校验。

微信 code 不等于业务 Token；AppSecret/session_key 不下发、不记录。配置采用单个小程序 AppID，当前不支持微信网页/App OAuth code；state/redirectUri 不参与微信请求，也不产生重定向。未配置明确返回 500/5000，不伪造身份。

## 内部实现与兼容

新增微信身份表，唯一键 app_id + open_id，关联 users.id。新增 users.credentials_configured，历史用户默认 true，微信新用户为 false。保持 password_hash 非空：随机不可预测密码仅保存哈希，原值丢弃；未设置用户不能使用密码登录。

微信建号不伪造邮箱；临时用户名在长度限制内随机生成。设置用户名不改变昵称、userId、角色、收藏、文章或评论归属。用户名占用拒绝，不绑定/合并旧账号。已有网站账号继续密码登录。

账号设置与旧刷新令牌撤销在同一数据库原子批次内完成，完成后签发新 AuthResult。如果提交已完成但响应丢失，重复设置会返回冲突，可通过新密码或微信重新登录恢复。管理员重置密码标记凭据已设置。旧 JWT 按既有到期策略失效，不承诺立即失效。

## 范围外

不新增手机号登录、onboarding ticket、账号绑定/合并、解绑、自助找回密码、登录方式查询，不把 password_hash 改成 nullable。不更改 APP/网站 UI。

## 发布节点

契约说明与校验 → 后端与测试 → 本地 SQLite 和本地 D1 迁移/验证 → 线上备份、迁移、部署和最小烟测 → 交付记录。每个完成节点独立 Conventional Commit。若缺少微信真实配置，部署能力但明确记录未完成真实微信验证；不能用 mock 验证冒充真实登录。
