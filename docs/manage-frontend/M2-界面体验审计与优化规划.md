# M2 管理后台 · 界面体验审计与优化规划

> 背景：后端接口与系统架构已通过测试（契约冻结、E2E 32/32、四门门禁）。本轮**只审计并优化「页面实现细节 + 组件体验」**，不动后端、不动契约、不重构整体框架。
> 主旨：这是一个**文章系统**的管理后台，设计要围绕「文章」组织信息，把使用者当新手，提供好懂、好用的后台。
> 方法：逐文件读码 + grep 取证，不凭记忆。框架层（响应式侧栏/移动 Drawer/暗色/状态令牌/Suspense/骨架/错误态/空态/批量/防抖/校验）经上轮 T1–T9 已扎实，且走查确认**不在本轮改动范围**。
> 视角：以「前端界面开发专家」适用的铁律为尺——无障碍（焦点/对比度）、交互必有反馈、组件一致、移动优先、把用户当菜鸟；在保留你已满意的整体框架前提下做针对性打磨。

## 1. 现状盘点（已实现、保留）

- **框架层扎实**：`AdminLayout` 侧栏 `lg:flex` + 移动 `Drawer`；Topbar 做了 `lg:` 断点；暗色 `next-themes` + `.dark` 变量块；路由懒加载 + 大页 Suspense。
- **反馈层扎实**（上轮 T1–T9）：列表骨架、内联错误态+重试、空态图标、搜索防抖、表单 `onTouched`、图标按钮 `aria-label`、批量操作、图片懒加载。
- **组件资产齐**：shadcn `select/button/dialog/dropdown-menu/popover/input/textarea/switch/card/avatar/calendar/drawer/separator/label/sonner` 均备；自建 `DataTable/BatchActionBar/QueryErrorState/ImageUploadField/MarkdownEditor` 可用。
- **分类树**：状态编排与渲染/纯计算拆分清晰（`CategoryTreePage` + `CategoryNodeRow` + `categoryTree`），小数量默认全展开，结构合理。

## 3. 优化规划（分期，独立可交付）

### Phase A — 必做（先修根因，再收一致性）
1. **P0-1 主题补 `--popover`**：在 `index.css` 的 `:root` 与 `.dark` 各加
   ```css
   --popover: var(--card);
   --popover-foreground: var(--card-foreground);
   ```
   （复用已定义的 `--card` 同值，明暗各自继承；一行修复，解锁所有弹层/Select 视觉）。
2. **P0-2 封面改上传**：`ArticleFormPage` 的 `coverImage` 由 `TextField` 换 `ImageUploadField`（复用现有 R2 上传 + 懒加载预览）。
3. **P1-1 列表筛选迁 shadcn Select**：4 处原生 `<select>` → `SelectField`（依赖 P0-1 先修）。
4. **P1-2 文章表单双栏布局**：主列 + 侧栏（响应式 `lg:` 断点塌缩）。
5. **P1-3 取消守卫**：未保存时 `ConfirmDialog` 确认。
- **验收**：四门门禁全绿 + 浏览器走查（**含暗色模式**，重点验证用户菜单/分类下拉可读）。

### Phase B — 一致性收尾（按价值排序，可全做可挑做）
- P2-2 列表封面 + 查看外链 → P2-1 分类搜索 Combobox → P2-3 角色约束 → P2-4 Dashboard KPI → P2-5 标签联想 → P2-6 对比度走查。
- 每期独立门禁；Phase B 内按上表价值排期。
