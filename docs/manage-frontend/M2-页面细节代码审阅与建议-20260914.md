# M2 页面细节代码审阅与建议

日期：2026-09-14。范围：当前管理后台页面及共用交互组件的静态审阅。保留现有整体框架、技术栈和后端边界；本次只提出建议，不修改业务代码。

说明：下文“代码确认”指源码明确存在的行为或缺失，不代表浏览器已经复现。时序、中文输入法、实际布局表现另列为待复现。优先级按用户操作影响排列，不按代码美观排列。

## 一、整体判断

主要不足是页面围绕字段、接口与增删改查组织，对“用户如何完成一次工作”的照顾不够。结果是：功能入口有了，但按钮含义、下一步动作、出错后的恢复、长时间输入的保护没有形成一致体验。

建议保留导航、布局与视觉基调，从写作、审核、维护三类任务逐步收口。每个页面明确主要任务、主要操作、操作结果和失败恢复路径。

## 二、先处理会损失输入或造成误操作的问题

### A1. 保存内容与改变文章状态混在一起（优先处理，代码确认）

证据：`src/pages/articles/ArticleFormPage.tsx:136` 构造带 status 的 payload，`:157` 保存草稿固定传 draft，`:294` 所有编辑状态都显示相同双按钮；`node-backend/src/services/article-mutation.ts:62` 明确采用传入状态。

体验影响：编辑一篇已发布文章时，用户只想改错字，却要在“保存草稿”和“发布文章”之间判断。保存草稿会改变其公开状态；成功后两条路径都直接返回无筛选的文章列表，也中断持续写作。

建议：草稿提供“保存草稿／发布”；已发布内容主操作为“保存修改”，保留当前状态；下架单列为明确的次级操作并解释后果。保存默认留在编辑页，反馈“已保存”，另提供返回列表。新建保存成功后切为编辑已有稿件，避免重复创建。状态动作严格沿用已有角色与接口边界。

### A2. 稿件离开保护覆盖不完整（优先处理，代码确认）

证据：`ArticleFormPage.tsx:169` 仅自定义返回按钮检查 isDirty，源码未实现路由拦截与 beforeunload。

建议：统一覆盖侧栏跳转、浏览器返回、刷新／关闭窗口。短期先补离开保护与保存状态显示，不必立即引入复杂自动保存。是否增加本地草稿恢复可在这一步完成后评估。

### A3. 图片上传与提交不同步，正文插图有旧值覆盖风险（优先处理）

代码确认：`ArticleFormPage.tsx:175` 提交禁用条件只有文章 mutation；`components/form/ImageUploadField.tsx:51` 上传状态留在组件内部；站点与头像表单也没有与上传状态联动。

体验影响：选图后立刻保存，可能提交的仍是旧地址或空地址，随后离开页面，用户却以为图片已经保存。

待复现风险：`components/editor/MarkdownEditor.tsx:64` 用闭包中的 value 拼正文，`:83` 等待上传后再调用插入。上传期间继续打字、一次粘贴多图时，可能基于旧正文覆盖新输入或前一张图片。

建议：页面统一感知待完成上传，完成前显示“图片上传中”并阻止提交；插图使用最新正文和可靠的插入位置。验证“上传时继续打字、连续多图、切 Tab、上传失败后重试”四种场景。

### A4. 加载失败与空数据混淆（优先处理，代码确认）

证据：文章编辑页 `:75/:177`、站点设置 `:112`、个人资料 `:73` 只处理 loading，未拦截首次数据加载失败；分类页只判断 loading 与 tree.length；仪表盘多个区块只区分 pending 与数据长度。

体验影响：打不开已有文章时显示空表单；站点配置失败时出现可提交空字段；分类和仪表盘失败会被误认为没有内容。

建议：统一“加载中／加载失败并可重试／确实为空／正常数据”。依赖原始数据的编辑表单加载失败时禁止提交。有筛选的列表空态改为“没有符合条件的结果”，提供清除筛选，区别于首次使用的空态。

### A5. 批量操作的对象与结果不清楚（优先处理，代码确认）

证据：`pages/articles/ArticleListPage.tsx:186` 的“批量发布”对所有已选 id 调 approve；后端 `routes/articles-admin.ts:39` 明确仅接受 pending。文章／评论页面 selected 不随筛选或翻页清理，失败后统一清空；批量调用的 hooks 又逐条 toast。

体验影响：选择草稿后执行批量发布会失败；更换筛选后仍可能操作已经看不见的记录；部分失败只知道数量，不知道是哪几条。多次成功提示后又出汇总，反馈重复。

建议：先采用简单的“仅当前页选择，切筛选清空”规则。操作命名为“通过审核并发布”，只针对待审记录；执行前显示有效数量。只给一次结果汇总，保留失败记录供重试；批量请求期间锁定选择和相关动作。

## 三、按页面改善信息和工作流

| 页面 | 代码中可见的不合适之处 | 建议 |
|---|---|---|
| 文章列表 | 标题为普通 span；编辑只能找右侧小图标；没有分类筛选和清除筛选；返回路径丢失列表条件 | 标题可点击编辑；保留常用文字操作；补现有 API 支持的分类筛选；编辑返回恢复原列表条件。封面缩略图作为次级信息，控制行高 |
| 文章设置 | 建议 16:9 的封面却用 64×64 object-cover 预览；分类平铺下拉；标签只支持自由输入 | 封面使用横向预览并可查看完整图片；分类显示清楚的父子路径，数量增多再加搜索；标签提供已有项联想，同时保留新建 |
| 评论审核 | 所属文章只有 #ID，点击去编辑文章；回复关系没有呈现；审核依赖“目标状态”下拉；通过时仍可填写拒绝理由 | 同页查看完整评论及必要上下文，按 articleId 使用现有筛选；正文旁提供“通过／拒绝／待复核”；理由随所选动作显示。文章标题缺失时按需加载，避免每行额外请求 |
| 分类 | 树默认全展开；无搜索与一键折叠；名称旁优先显示 slug；维护顺序靠填数字 | 增加搜索、展开／收起；名称和层级优先，slug 次级。数量少时继续保留排序值输入，不必立刻引入拖拽排序 |
| 标签 | 全量表格没有搜索、排序；删除受文章引用限制，但缺少下一步入口 | 用已有数组做本地搜索、按使用量排序；文章数可进入对应文章筛选，帮助用户理解引用关系。保留契约边界，不新增合并能力 |
| 用户 | 角色、禁用、等级塞在同一弹窗；说明大量使用英文状态；只防自我禁用，角色下拉仍允许自我降权 | 普通资料与权限操作分组，角色说明写清能做什么；当前账号醒目标识；自我降权增加明确保护，后端是否限制另行核实 |
| 站点设置 | 六个字段纵向堆在“基础信息”；站点名称与站点标题区别含糊；重置无改动判断 | 分成品牌、搜索展示、页脚三个小组；给具体示例或轻量预览；重置改成“撤销未保存修改”，没有修改时禁用 |
| 仪表盘 | 待审数量、近期文章、近期评论都是展示，不能就地进入处理；图表比工作入口突出 | 加“写文章／处理待审／查看待复核评论”入口；统计和近期内容可点击进入对应页面；保留现有图表，调整信息顺序 |
| 收藏／点赞 | 文章标题不可点击；收藏操作仅写“取消”；点赞固定请求 20 条却不说明范围 | 增加合适的阅读入口，未有前台地址时使用独立只读预览，避免让普通用户进入编辑路由；改为“取消收藏”；说明范围或按既有接口能力补上一页／下一页 |
| 通知 | 不区分站内后台路径和通知 link 的目标，直接 navigate；长正文截断且无展开 | 校验并映射通知目标，明确属于前台还是后台；无可达目标时在本页看完整消息，避免点一下跳到 404 |

上述证据分别位于同名页面组件及 `components/form/ImageUploadField.tsx`。通知跳转问题需用真实通知 link 验证，不能仅凭静态代码认定所有通知都会失效。

## 四、跨页面统一的细节

### 文案改写（高收益，代码确认）

| 当前可见文案 | 建议表达 |
|---|---|
| 标签云计数由 GET /tags 的 articleCount 直接给出 | 管理文章标签，查看各标签的使用情况 |
| approved / rejected / reviewing 三态人工审核 | 查看评论，处理待复核内容 |
| 审核置位 | 审核评论 |
| 保存即全量局部更新 | 保存后应用到站点 |
| 该操作软删除，关联评论 / 附件将隔离可见性 | 删除后文章将不再展示，相关评论也将隐藏 |
| v1 无邮件找回，此端点为唯一兜底 | 设置后请将新密码告知用户 |

技术解释保留在代码和文章中。操作界面只解释使用者需要知道的结果。

### 反馈和上下文（代码确认）

- 保存按钮区分“未修改／已修改／保存中／已保存”；当前文章提交中只禁用，按钮文字不变。
- 表单可编辑期间的数据重新获取不应无条件 reset。文章、设置、资料都有数据变化即回填的写法；全局已关闭窗口聚焦刷新，仍需验证重连或缓存失效触发的重新获取。
- 回复被内容过滤拒绝时，`hooks/useComments.ts` 仍使用 success toast，页面 onSuccess 随后关闭弹窗。应保留内容、显示未发布原因，让用户继续修改。
- 删除最后一条记录后应回到有效页码。收藏页 `FavoritesPage.tsx:52` 将分页器放在非空分支：末页删空可能连“上一页”都消失，而页面却说从未收藏。
- 搜索参数只在输入真正变化时提交。文章／用户页挂载就触发防抖 setFilters，后者固定写 page=1，因此需要验证带 page 的链接和返回列表是否被重置；不能把“URL 存了参数”当成恢复体验已完成。
- 标题链接、图标提示、禁用原因、错误区与空态采用统一规则。常用操作不要求用户猜图标。

### 输入与校验（待浏览器复现）

- `components/form/TagsField.tsx:77` 回车添加未检查中文输入法 composing。验证候选确认是否提前提交标签；支持中文逗号分隔。
- 文章“设置”Tab 的字段出错后应自动切换到相应区域；当前只有发布缺分类显式切 Tab。
- 封面/头像选择器提示 10MB，但上传 hook 未做大小预检；按实际后端限制做立即反馈，避免上传完才报错。
- 小视口的编辑器高度、长评论弹窗、长标题表格、暗色对比度需要视觉验收，本次不做“已经溢出／不好看”的结论。

## 五、建议实施顺序

1. **写作完整性**：A1–A4，优先明确保存状态、保护输入、协调上传与提交。
2. **管理操作可预测**：批量行为、评论审核、错误与空态、分页和筛选恢复。
3. **页面易用性**：统一文案、可点击入口、封面预览、分类／标签检索、设置分组。
4. **视觉收口**：用真实长标题、多级分类、长评论和窄窗口，验证间距、密度、弹窗及浅深主题。

无需一次重做全部页面。先把“写一篇文章并成功发布”做到顺手，形成可复用的细节标准，再逐页应用。每一轮只验证其影响的交互，继续复用已有检查，不为静态建议新增测试或调整后端。
