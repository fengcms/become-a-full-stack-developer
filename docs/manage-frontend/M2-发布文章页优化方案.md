# M2 · 发布文章页（ArticleFormPage）优化方案

> 范围：仅「发布文章页」（`src/pages/articles/ArticleFormPage.tsx`）。其余页面（列表筛原生 select、Dashboard、列表封面缩略图等）暂不动，回头再议。
> 目标：在接口/契约已稳定的前提下，只优化界面实现细节与新手友好度。
> 决策来源：用户 2026-08-31「先围绕发布文章这个页面做优化，其他的暂时靠后」。

## 0. 现状（代码实证）

`ArticleFormPage.tsx`（215 行）当前是**单列长表单**，字段自上而下：
1. `title` — TextField（必填）
2. `content` — MarkdownEditor（`@uiw/react-md-editor`，左写右预览，暗色跟随）
3. `summary` — TextAreaField
4. `coverImage` — **TextField 裸 URL 输入框**（问题点：新手不会用，应改上传）
5. `categoryId` — SelectField（树拍平，含「未分类」；**因 `--popover` 缺失，下拉背景透明**）
6. `tags` — TagsField
7. `slug` — TextField
8. `status` — SelectField（draft/pending/published）
9. 操作栏：提交 + 取消（**无未保存守卫**）

复用件就绪：`ImageUploadField`（方形/圆形预览、选图即传 R2）、`ConfirmDialog`（受控）、`useImageUpload`。
缺口：`tabs.tsx` 不存在，`@radix-ui/react-tabs` 未装 → 自建轻量受控 Tabs（零新依赖）。

## 1. 方案选型：A（弹窗）vs B+（标签页）

用户原提两方案：A=写作页仅标题+编辑器，保存时弹窗填元数据；B=Tab 式（Tab1 内容 / Tab2 细节）。
**专家结论：选 B+**，理由（对新手友好度）：
- A 的元数据有 6 项且含文件上传，弹窗窄长、移动端体验差、取消时内容去向尴尬。
- B 的 Tab1 与 A 写作区专注度等同，但元数据可见有组织、不 surprise；Tab2 空间充足放上传/树选择。
- B+ 加常驻操作栏 + 跨 Tab 校验，是「专注 + 引导」的最佳平衡。

## 2. 目标结构（B+）

```
PageHeader（新建/编辑文章）
└─ Sticky 操作栏（始终可见）
     ├ 取消（左）
     └ 保存草稿 | 发布文章（右，主按钮）
Tabs
 ├ Tab1 「内容」
 │    ├ 标题（TextField, required）
 │    └ 正文（MarkdownEditor 分屏）
 └ Tab2 「设置」
      ├ 摘要（TextArea, ≤500）
      ├ 封面图（ImageUploadField, square）
      ├ 分类（SelectField, 必填校验）
      ├ 标签（TagsField）
      └ URL 别名（TextField）
```

状态控制：**移除 status 下拉**，由双动词决定——
- 「保存草稿」→ `status='draft'`（不强制分类）
- 「发布文章」→ `status='published'`（分类必填）
