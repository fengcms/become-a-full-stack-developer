## 1. 技术约束（强制）

1. **文档归位**：本计划与所有 M2 文档只在 `docs/manage-frontend/`。
2. **编码规范**：严格执行 `docs/manage-frontend/开发规范.md`——箭头函数、文件头注释、函数级 TSDoc、单文件 ≤200 行（超限注明例外）、页面组件单职责。
3. **契约唯一真相**：端点/字段以 `docs/api/openapi.v1.yaml`（v1.11.0）为唯一来源；改动先改契约再改实现。
4. **后端已冻结**：`node-backend-v1.0` 冻结，前端只消费，不反向要求改后端（联调发现契约缺口记差异表，交后端 AI）。
5. **门禁强制**：每阶段结束必须 `typecheck` + `lint` + `build` 全绿再进下一阶段。
6. **先 curl 实测后编码**：对接每个新端点先 curl 对齐字段，差异入「差异表」。

## 3. Phase 0 · 基础件补全（所有业务模块的前置）

目的：把骨架里的「列表页范式 / 表单页范式」沉淀为**可复用组件**，并补齐文章与权限两件硬依赖。

### F0.1 `DataTable` 通用列表组件
- 能力：分页（`Page<T>`：`items/total/page/size/pages`）、带符号 `sort`、列定义、行选择、空态/加载态（`Skeleton`）、操作列插槽。
- 文件：`src/components/data/DataTable.tsx`（若超 200 行，拆 `useTableQuery` hook + `TablePagination` + `TableToolbar`）。
- 复用骨架已验证的 `Page<T>` 约定与 `invalidateQueries` 助手。

### F0.2 表单字段组件（`FormField` 系列）
- 包装 RHF + zod：`TextField` / `TextAreaField` / `SelectField` / `SwitchField` / `ImageUploadField`。
- 文件：`src/components/form/*`（每类单文件单职责）。`ImageUploadField` 走 `POST /me/attachments`（R2/local 驱动）拿 URL。

### F0.3 `ConfirmDialog` 两阶段确认弹窗
- 删除 / 状态变更等危险操作。复用 shadcn `dialog` + `sonner` 反馈；危险操作禁用背景关闭、按钮二次确认（继承参考项目纪律）。
- 文件：`src/components/feedback/ConfirmDialog.tsx`。

### F0.4 全局 Toast 封装 `useToast`
- `sonner` 已装且 `<Toaster/>` 已注册；封装 `useToast().success/error` 统一文案（不露后端原文，走 `resolveErrorMessage`）。
- 文件：`src/hooks/useToast.ts`（薄封装，≤60 行）。

### F0.5 Markdown 编辑器（M2-10，Phase 1 前置）
- 选型：**@uiw/react-md-editor v4**（CodeMirror6，左写右预览 + 工具栏 + 暗色跟随应用主题）。**已定案（2026-08-29）**：原计划拟 TipTap，但 TipTap v3 已移除 `@tiptap/extension-markdown`（markdown 序列化脆弱），且 Article.content 为纯 string，故改用真·Markdown 编辑器；体积偏大（引 CodeMirror + highlight.js），由 M2-13 分包缓解。
- 粘贴上传：`clipboard`/`drop` 事件 → `POST /upload`（契约上传端点，非 /me/attachments）→ 回写 `fileUrl(attachment.url)`（`ORIGIN + /files/<key>`，**不带 `/api/v1` 前缀**，已记 FAQ）。
- 文件：`src/components/editor/MarkdownEditor.tsx` + `src/hooks/useImageUpload.ts`、`src/api/attachments.ts`。

### F0.6 按钮级权限组件（M2-12）
- `<Can role="editor" ownerOverride>` 包裹按钮/菜单项；底层复用 `lib/permission.ts` 的 `canOperateOwned` / `canForceArticleStatus` 等判定。
- 文件：`src/components/auth/Can.tsx`。

**Phase 0 出口**：Phase 1~7 所有列表/表单/危险操作/权限按钮均复用以上件；新增端点只在 `src/api/*.ts` 补函数。

## 4. Phase 1 · 文章管理（M2-11，最大模块）

端点（`src/api/articles.ts` 已含 list/detail/create/update/delete/approve/setStatus；待补 `submitArticle`）：

| 能力 | 端点 | 页面/组件 |
|:---|:---|:---|
| 列表（状态/分类/标签/关键词筛选） | `GET /admin/articles` | `pages/articles/ArticleListPage` + `ArticleFilterBar` |
| 新建/编辑（抽屉或独立页） | `POST /articles` / `PUT /articles/{id}` | `pages/articles/ArticleEditDrawer` + `ArticleForm`（用 F0.2 + F0.5） |
| 提交审核 | `POST /articles/{id}/submit` | 列表行操作（`<Can editor>`） |
| 审核通过 | `POST /admin/articles/{id}/approve` | 列表行操作（`<Can editor>`） |
| 强制状态（下架=published→draft 等） | `POST /admin/articles/{id}/status` | admin 专属（`<Can admin>`） |
| 删除 | `DELETE /articles/{id}` | `ConfirmDialog`（F0.3） |

**状态机前端表达**：`draft → pending → published`，外加 admin 强制回退。用 Badge 颜色 + 行操作按当前态显隐（参考 `Article.status.x-allowed-transitions` 机器化约束）。
**拆文件**：列表页（列表 + 筛选）、编辑抽屉（表单 + 编辑器）、`ArticleForm` 字段组件，各自 ≤200 行。

1. **每 Phase 一次 PR**：Phase 0 → 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 严格串行，前一个门禁全绿再进下一个。
