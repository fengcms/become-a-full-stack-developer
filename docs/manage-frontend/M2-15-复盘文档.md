## 2. 返工点（根因分类）

### 2.1 计划文档与冻结契约冲突（共 4 处，全部以契约为真相源回流）
| # | 计划写 | 契约实际 | 处置 |
|:---|:---|:---|:---|
| 1 | `POST/DELETE /admin/comments`（代回复/删） | `/admin/comments` 仅 GET | 改走 `PATCH /comments/{id}/status` + `DELETE /comments/{id}`；测试钉死防后人改 404 |
| 2 | 标签「合并」端点 | 契约无 merge | 不实现，记「先改契约再改实现」 |
| 3 | 用户 `/admin/users` | 实际在 `/users`（仅 reset-password 带 `/admin`） | 测试反向断言 `not.toContain('/admin/users')` |
| 4 | `GET /me/likes` 返回分页 `{list,pagination}` | 契约是**裸数组** `ArticleSummary[]` | R5 矛盾；`me.test.ts` 反向断言 `data.list` 为 undefined 钉死 |

> **结论**：计划是意图、契约是唯一真相源、冲突回流——这条纪律在三轮审阅里被审阅专家反复点名「最值得肯定」。值得固化进 `M2-开发计划.md` 头部警示。

### 2.2 第一轮审阅整改（A-P2-2 + P3-1~P3-5）
- **A-P2-2 开启 strict**：`tsc --showConfig` 实测生效值 `strict:true`，0 类型错误（先前已习惯 `??` + `isApiError` 守卫，故零回归）。
- **P3-2 体积 -47%**：`manualChunks` 把编辑器生态拆出 → `ArticleFormPage` 1.06 MB → 8.79 kB；继续归因出真凶 `refractor/all` 默认 297 语言全量 → 自建 41 语言集 alias → md-editor 1,059 → 563.94 kB。
- **P3-3 语义令牌**：`status-*`/`role-*`/`user-status-*` 抽 CSS 变量 + `@theme inline` 双主题映射，取代硬编码 `bg-slate-200`。

### 2.3 后端 bug 引发的返工（非前端责任）
- 分类 `PUT /categories/{id}` 省略 parentId 静默挪根 → 后端增量修复（局部更新）+ 前端 `buildParentMap` 双保险。属冻结后首个行为 bug，走增量维护纪律（先改 YAML→改实现→补回归→复跑双门）。

## 3. 选型对错

| 选型 | 结论 | 证据 |
|:---|:---|:---|
| **@uiw/react-md-editor v4**（弃 TipTap） | ✅ 对 | TipTap v3 移除 markdown 扩展；Article.content 为纯 string。体积偏大但拆包后仅编辑页按需（gzip 180 kB），owner 已裁决接受 |
| **方案 B Vite 代理**（dev 绕 CORS） | ✅ 对（dev）/ 🟡 待上线验 | owner 暂定决策；代价是 Cookie 刷新分支 dev 无实测，转上线前 checklist |
| **refractor 297→41 语言集** | ✅ 对 | 省 ~50% 编辑器体积；补 jsx/tsx/nginx/docker/http 满足 React 后台高频 |
| **TS strict 早开** | ✅ 对 | 规模化前清零隐性 bug，门禁真在工作（哨兵验证 TS18047/TS7006 被拦） |
| **co-location 测试** | ✅ 对 | Vitest+Vite+React+RTL 生态事实标准；审阅专家不建议改集中式 |
| **不擅自抬高 chunkSizeWarningLimit** | ✅ 对 | 告警是真实信号（md-editor 大），抬阈值=藏问题；与原则相悖故未动 |
| **公共件 <Can>/ConfirmDialog/DataTable 复用** | ✅ 对 | Phase1~7 列表/表单/危险操作全复用，零重复造轮子 |

## 4. 与七端契约一致性（最高价值维度）

- 信封 `{code,message,data,requestId,timestamp}`、`code:0` 成功、数字分段错误码、分页 `list`（非 `items`）、`Page<T>`、`fileUrl` 根路径、**三角色 `x-authz`**——逐项 grep + 对照后端运行时 `node-backend/src/shared/response.ts` 核验对齐冻结契约 v1.11.0。
- 契约守卫测试持续加厚（articles/comments/users/site/me/notify），把「会静默失败」的风险固化成 CI 反向断言。
- 唯一跨端遗留 **R4**：公开 `GET /site/settings` 旧后端可能 5000 → 转上线前 checklist（前端只碰 admin 端点，未触公开版）。

## 5. 工程化爬坡项（非阻塞，留给后续）

1. **组件级 / E2E 测试缺口**：当前 62 测试覆盖请求层 / 契约守卫 / 纯函数，但 `pages/*` 缺 jsdom/RTL 渲染测试、缺 Playwright 关键流 E2E。三轮审阅一致标记 R4（工程化爬坡项），非本轮 regression。
2. **覆盖率门禁**：未设 `--coverage` 阈值；规模化后可加行/分支阈值。
3. **`openapi-typescript@7` 要求 ts ^5，项目 ts 6.0.3**：仅影响类型生成工具，运行时无碍；待工具链升级时一并解。
