## 3. 架构设计模式（45/50）

**正向（亮点，逐文件取证）**
- **请求层高内聚分层** `src/lib/request/{core,errors,session,helpers,index}.ts`：信封解析 `code===0`（`core.ts:181`）、401 并发去重刷新（`refreshInFlight` Promise 锁，`core.ts:66-99`）、启动静默恢复（`bootstrapSession`）、`fileUrl` 修正 `/files` 根路径（`helpers.ts:69-73`）。依赖方向 `core→session→store` 无环，注释清楚。
- **鉴权存储纪律** `store/auth.ts`：accessToken/refreshToken **仅内存、不落 localStorage**（line 6 注释阐明 XSS 放大风险），store 不发请求、不与 request 成环。
- **权限单一事实源** `lib/permission.ts` + `config/menu.ts` + `router/guards.tsx` 三处共用同一套 `canXxx` 判定；`visibleMenu` 直接复用 `permission` 函数，菜单显隐与路由守卫判据同源，杜绝「菜单能点、进去 403」分裂。`canOperateOwned` 精确映射契约 `x-authz.ownerOverride`（本人资源可越权）。
- **守卫三件套** `RequireAuth / RequireConsole / RequireCan` 分层，失败去向不同（登录/没资格进后台/能力不足），且 `bootStatus` 未落定时拦住防误跳（`guards.tsx:35`）。`App.tsx` 根组件统一注册全局 401 兜底。
- **列表契约对齐** `Page<T>={list,pagination}`（`types/common.ts:41`）与冻结契约 `ArticlePage` 完全一致；`ArticleListPage` 取 `data?.list` 正确。
- **RQ 缓存键工厂** `queryClient.ts:qk` 集中管理，写后 `invalidateQueries(['articles'])` 前缀失效（`useArticles.ts:46`），规避双 key 漏刷。
- **路由懒加载 + 两壳分层** `router/index.tsx`：裸页（`/login`、`/no-access`）不套后台布局；其余 `RequireAuth→RequireConsole→AdminLayout`，业务路由按能力套 `RequireCan`。

**问题**
- 🟡 **P3-4（仓库卫生）**：仓库根存在 `_tmp_75915_…`、`_tmp_75925_…`、`_tmp_80644_…` 三个 0 字节文件，**已被 git 跟踪**（非 ignore）。应删除并加 `.gitignore` 规则（如 `_tmp_*`）。
- ℹ️ `core.ts` 约 210 行超 200 软上限，文件头已自陈并论证「拆碎会致循环依赖」——属合理例外，记录不扣分。

## 5. 性能与可维护性（37/50）

**正向**
- `QueryClient` 重试策略精准：`shouldRetry` 仅对断网（status 0）与 5000 重试、上限 2；403/404/4001 确定性错误不重试；mutation `retry:false`（避免重复提交）；`staleTime:30s` + `refetchOnWindowFocus:false`（`queryClient.ts:23-43`）——后台场景正确权衡。
- 响应式布局 `AdminLayout.tsx`：≥1280 展开 / <1024 汉堡浮层，用 `useUiStore` 管折叠态，登出编排清本地会话后跳登录。
- 设计令牌落地：侧栏用 `sidebar-background/sidebar-border`、主区 `.app-bg`/`.animate-rise`，符合简报视觉基因。

**问题**
- 🟡 **P3-2（包体积）**：`vite build` 告警 `ArticleFormPage` chunk **1.06MB**（gzip 364KB），主因 `@uiw/react-md-editor` + markdown preview 整包打入。路由级已懒加载，但编辑器内部未再拆。建议：`MDEditor` 在 `ArticleFormPage` 内二次 `lazy()`，或 `build.rollupOptions.output.manualChunks` 把 md-editor 拆独立 chunk，避免列表页/仪表盘承担编辑器重量。
- 🟡 **P3-3（状态色硬编码）**：`ArticleListPage` 的 `STATUS_CLASS` 用 `bg-slate-200/text-slate-700` 等硬编码色（`ArticleListPage.tsx:30-34`），偏离简报 §5「不写死颜色，一律令牌」。语义状态色可保留，但建议抽成 `status-draft/status-pending/status-published` 语义令牌，明暗主题下可控。
