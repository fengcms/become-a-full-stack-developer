## 3. 重点复验详情

### 3.1 A-P2-2 strict：不是"开了没报错"，是"真强制"
仅看 `typecheck` 0 错不足以证明 strict 生效（可能配置被继承覆盖）。补充 `tsc --showConfig` 确认最终编译配置 `"strict": true` 进入解析——证明 `strictNullChecks`（`??` 收敛）、`noImplicitAny`、`useUnknownInCatchVariables` 等核心严格族**确实在编译期强制**。开发 AI 此前还用哨兵文件（插入 null 隐式使用 / 隐式 any）反向验证门禁会红，手法专业。

### 3.2 P3-2 体积瘦身：归因到位，不是"隔离即交差"
多数工程做到 `manualChunks` 隔离就停。开发 AI 继续下钻根因：`rehype-prism-plus` 默认 `import 'refractor/all'`（297 全量语言），用 `build/refractor-languages.ts` + vite alias 顶替为 41 种（common 36 + jsx/tsx/nginx/docker/http，因官方 common 缺 jsx/tsx 会让 React 代码块高亮静默失效）。这是真优化。

> 风险点复核：alias 仅顶替 `refractor/all` 不顶替裸 `refractor`（否则 `build/refractor-languages.ts` 自身 import 形成死循环）——`vite.config.ts:62-64` 注释已说明，设计正确。

### 3.3 P3-3 状态语义令牌：双主题对比度都照顾到
`index.css` 不仅定义 `:root` 浅色，`--status-*-bg/-fg` 在 `.dark` 下改为"深底 + 亮字"（如 `draft-bg 0.32 → fg 0.88`），保证暗色主题徽标仍达对比度。映射为 Tailwind 工具类 `bg-status-draft` / `text-status-draft-fg`，组件侧无硬编码调色板。一个被低估但正确的细节。

### 3.4 P3-5 测试质量：超出"冒烟"预期，把风险固化成守卫
抽查两份测试文件，质量高于一般冒烟：

- **`refresh.test.ts`**：401 并发刷新去重——给刷新接口 `setTimeout(20ms)` 撑开并发窗口，断言 3 个并发 401 只打 1 次 `/auth/refresh`；并断言新令牌落内存、环境无 `localStorage`（方案 B 安全底线）。这类 bug 只在并发窗口复现，手工点页面撞不到，测试守得对。
- **`articles.test.ts`**：分页消费——**反向断言** `(page as any).total` 与 `.items` 均为 `undefined`，且空列表必须是 `[]` 而非 `undefined`（否则 `map(undefined)` 崩）。这把第一轮最担心的"参考项目 `{items,total}` 习惯串味导致页面静默空白"直接变成了 CI 红/绿开关。

**这是本轮最值得肯定的改进**：测试没有堆数量，而是钉住了两条会"静默失败、联调难查"的关键路径。

### 3.5 P3-5 CI：只读门禁，防本地假绿
`manage-frontend-ci.yml` 用 `biome check .`（只读）而非本地 `check --write`；`paths` 过滤仅前端变更触发；`pnpm install --frozen-lockfile`；Node 22。回复提到 CI 当场抓到 2 处 import 排序（本地 `--write` 会自动改掉、永远绿）——只读门禁的价值在此体现。

## 6. 关于「测试是否该放 `tests/` 目录」的专业建议（回应 owner 提问）

**结论：把单元测试与源码同目录（co-location，如 `Button.test.tsx` 紧邻 `Button.tsx`）是前端、尤其本项目这套栈（Vitest + Vite + React + RTL + shadcn/ui）的「事实标准/主流做法」；集中塞进顶层 `tests/` 目录反而是次主流，多见于后端或旧版 Jest 工程。因此不建议改为 `tests/`。**

### 6.1 对比（为何 co-location 更优）

| 维度 | co-location（当前做法 ✅） | 集中 `tests/`（owner 提议） |
|---|---|---|
| 生态默认 | Vitest / Vite / React / RTL / shadcn 生成器**全部默认 co-location** | 需手动改 `vitest.config.ts` 的 `include` + 重配路径别名 |
| 重构安全 | 移动/重命名组件，测试跟着走，不易漏 | 易与实现漂移，「忘了同步测试」高发 |
| import 路径 | 短、相对引用直观 | 深层 `../../` 或重配 alias |
| 运行命中 | vitest 默认 glob `src/**/*.test.ts` 直接命中 | 需额外 include 配置 |
| 发布剥离收益 | SPA 打包产物，无源码发布场景，此"优势"不成立 | 唯一常被引用的优势，在本场景无效 |

### 6.2 何时才适合集中式
仅两种场景推荐集中目录：
1. **E2E 测试**（Playwright 通常独立 `e2e/` 目录，因需浏览器环境、与单元隔离）；
2. **团队既有强约定**（若团队历史项目全用 `tests/`，为统一可妥协）。

单元测试（本项目当前的 node 环境冒烟）co-location 是主流且更优。

### 6.3 建议（不作整改项，反作肯定 + 补强）
1. **维持 co-location**，不要求改 `tests/`；
2. **补一条开发规范**：把测试约定写进 `docs/manage-frontend/开发规范.md`——位置 co-location、命名 `*.test.ts`、环境 `node` 仅覆盖无 DOM 逻辑、React 组件若需 DOM 测试再开 jsdom 子配置。防止后续模块各放各的、命名混乱；
3. 若 owner **仍坚持**集中式：可行但非标准，需改 `vitest.config.ts` 的 `include` 并评估漂移代价——请 owner 明确拍板后开发 AI 再动，我不默认执行。

> 说明：本条为专业建议，非第一轮审阅发现的缺陷。第一轮审阅本身未要求统一测试目录，开发 AI 选 co-location 是正确默认。
