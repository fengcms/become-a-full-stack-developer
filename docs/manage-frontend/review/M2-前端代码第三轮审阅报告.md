## 4. 架构质量亮点

### 4.1 权限守卫同源（首轮建立的好纪律延续）
`router/index.tsx` 业务路由外均套 `RequireCan`，判据直接 `import` 自 `lib/permission` 的 `canModerateComments` / `canManageCategories` / `canManageTags`（均 `roleAtLeast editor`），与菜单可见性**同一函数源**——「菜单看不见」与「硬敲地址进不去」永远一致。editor 管内容、admin 管用户/站点配置（路由里 `/users`、`/settings/site` 走 `canManageUsers`/`canManageSiteSettings`）的三角边界守住了。

### 4.2 契约硬约束前置到 UI（而非点了才吃 409）
`categories.ts` / `tags.ts` 文件头把三条硬约束显式写出，UI 落实：
- `CATEGORY_MAX_DEPTH = 4` → 深度达 4 节点「新建子分类」禁用；
- `DELETE /categories/{id}` 须无子无文章、不级联 → 有子节点删除禁用并提示先迁移；
- `DELETE /tags/{id}` 须无文章引用 → `articleCount>0` 删除禁用。
避免了「用户点了才返回 409」的无意义挫败，是成熟的 UX 取舍。

### 4.3 纯函数 `categoryTree.ts`（本轮代码质量最高处）
抽 `buildParentMap` / `collectSubtreeIds` / `nodeDepth` / `canAddChild` / `flattenTreeOptions` 五个纯函数：
- **环防护**：`collectSubtreeIds` 收集自身+子孙，编辑父级候选排除，提交前掐环（而非等后端 409/3002）；
- **死循环兜底**：`nodeDepth` 沿 parentMap 上行走 `depth <= CATEGORY_MAX_DEPTH + 1` 上限，防自关联表成环；
- **可测**：8 测试守卫（见 §5）。

### 4.4 评论审核细节正确
- `reviewing` 态唯一进出路径是 `PATCH /comments/{id}/status`（契约 openapi:393 同述），前端实现一致；
- **代回复不做乐观插入**：契约返回可能 `rejected`（敏感词），前端就地提示不插列表（`comments.ts` 头注释 + `CommentReplyDialog` 逻辑）；
- 三态用语义令牌（`status-approved/rejected/reviewing`），与文章状态令牌同源；
- `CommentListPage` 经 grep 确认**不传 sort**（契约 `GET /admin/comments` 无 sort），与 NOTES 自陈一致。
