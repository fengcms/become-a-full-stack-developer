## 2. 每个操作的证据字段

开发时维护机器可读的覆盖记录，至少包含：operationId、实现位置、schema 测试、角色测试、边界场景、数据库后置断言、Node 差分结果、三数据库结果、已知差异。测试名称可追踪到 operationId，不只靠总测试数量判断覆盖。

| 场景族 | 共同验收要求 |
| --- | --- |
| 公开读取 | published/删除/禁用可见性；匿名/合法/非法令牌；分页投影与限流 |
| 鉴权读取 | 缺失/过期/无效 token；最低角色；私有资源不得横向访问 |
| 创建与更新 | 缺失/null/零值；非法枚举；唯一冲突；事务失败无部分结果 |
| 删除与状态迁移 | 重复调用；不存在；ownerOverride；关联同步；计数与通知正确 |
| 认证与微信 | 轮换重放；撤销范围；并发首次登录/设密；外部故障；Cookie |
| 上传 | 类型与大小；重复字段；路径安全；共享对象；数据库/对象存储失败 |

## 3. 契约以外但现有客户端/运行需要的能力

| 能力 | 当前 Node 行为 | Go 验收 |
| --- | --- | --- |
| `GET /api/v1/health` | JSON 信封，data.status 为 ok | 保留路径与响应；不能悄悄改成裸文本 |
| `GET /files/{key}` | local/R2 字节流；MIME 由扩展名决定；SVG attachment；nosniff | 本地与 R2 读取、缺失404、安全 key、响应头与完整字节一致 |
| CORS / OPTIONS | 按环境与 origin 配置处理 | 四类客户端所需 origin/凭据/预检验证，不把预检作为业务操作计数 |
| 公开端点网关限流 | 契约要求；应用与网关责任需核查 | 有界单机限流器；429/code5001/Retry-After；可信 IP |

这些能力单独测试，不修改冻结 OpenAPI 来凑覆盖率。路由扫描与68项对照后，还需检查有没有额外路径或配置行为被遗漏。

## 5. 规划与实测的区别
