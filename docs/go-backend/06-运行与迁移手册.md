# M6 运行与离线迁移手册

日期：2026-10-08。这里的命令针对本地或隔离演练环境。本轮没有修改线上D1/R2、域名或现有客户端默认配置。

## 1. 开发环境

源码位于 `go-backend/`，命令从该目录执行。Go 1.26.6、C编译器、Node已有依赖和Docker均在本机验证。原生构建使用CGO；Node仅用于快照/差分/客户端/性能执行器，不参与Go服务运行。

```bash
cd go-backend
docker compose -p befull-m6 up -d --wait
make migrate
make run
```

当前本机 `.env` 已配置独立 PostgreSQL `befull_dev`，服务端口8080、随机JWT密钥、local上传目录。演示管理员 `m6admin` / `m6-local-password`，一篇已发布演示文章。以上凭据仅供本地；server只绑定127.0.0.1。首次初始化用 `SEED_USERNAME`/`SEED_PASSWORD` 后执行 `make seed`，已有账号拒绝覆盖，避免把重启变成改密。

`.env`自动读取，已有环境变量优先；包含 `&` 或空格的DSN可在文件中用单引号。`data`工具刻意使用单独的 `TRANSFER_DATABASE_URL`，不默认取应用库，避免导入错目标。不要把本地配置或迁移快照提交Git。

| 项目 | 本地配置 |
| --- | --- |
| PostgreSQL | 127.0.0.1:15432，postgres:17 |
| MySQL | 127.0.0.1:13306，mysql:8.4 |
| 应用 | 127.0.0.1:8080；`/api/v1` 与 `/files` |
| 持久卷 | befull-m6 的 pgdata / mydata；属于本项目 |
| 应用表 | 15业务表 + goose版本表 |
| 模式迁移 | 显式 `cmd/migrate`；启动不迁移 |

Docker健康检查使用TCP查询，避免MySQL初始化临时socket服务误报ready。日常停机用 `docker compose -p befull-m6 stop`；`down -v`会删除项目数据卷，仅用于确认可丢弃的环境。

## 2. 配置项

- `HTTP_ADDR`、`DB_DRIVER=postgres/mysql/sqlite`、`DATABASE_URL`、至少32字节 `JWT_SECRET`。
- `STORAGE_DRIVER=local/r2`、`UPLOAD_DIR`。local目录需要可写与持久化。
- `CORS_ORIGINS`逗号分隔。开发通配会回显请求Origin；生产拒绝通配。客户端同源代理优先。
- `TRUSTED_PROXIES`使用CIDR；未配置时不信任客户端X-Forwarded-For。
- `COMMENT_REJECT_RATIO`默认0.1，范围0..1，拒绝NaN/Infinity。
- `WECHAT_MINI_APP_ID` / `WECHAT_MINI_APP_SECRET`，兼容WECHAT_APP_ID/SECRET。缺失时普通功能可运行，微信回调返回5000。真实联调使用同一个小程序AppID和后端密钥，服务只访问官方固定域名。
- R2为 `R2_ENDPOINT`、`R2_BUCKET`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`；切到r2但配置不完整则启动失败。使用对应桶权限的S3凭据，不把带签名URL或AppSecret写日志。
- 可选 `DB_METRICS_FILE`：优雅停止时写入聚合查询数、累计/最大耗时、失败数；无SQL与参数。是进程级诊断，不是公开监控端点。

Go模块与驱动已经锁定。`make build`生成四个原生二进制。Dockerfile使用Debian/glibc多阶段原生Linux构建，默认非root用户；镜像manifest已经确认存在，完整Linux镜像运行需要部署时单独验证。

## 3. 验证复现

```bash
make verify
make matrix
go test -race ./...
go run golang.org/x/vuln/cmd/govulncheck@v1.8.0 -show verbose ./...
```

matrix创建带时间/随机后缀的独立测试库，完成全包、升级、导入，再清理该次测试库，不使用befull_dev。SQLite采用临时文件。出现失败先看具体包和后置状态，不用反复切换驱动掩盖失败。

差分从仓库根目录或对应目录执行：

```bash
cd go-backend

cd ../node-backend
```

这些trace包含测试账号/令牌，只用于隔离测试，脚本写入0600；不把真实生产trace交给这个执行器。Node端使用隔离SQLite、测试JWT、微信替身和临时local目录，原Node源码不改。

## 4. 数据迁移格式与演练

`cmd/data`输出version=1的JSON：source、createdAt、tables。只允许编译内白名单表/列；日期和ID为整数，布尔统一为boolean，SQLNULL保留null。导出不覆盖已有文件，文件权限0600。

保留users、categories、tags、wechat_identities、articles、article_tags、comments、attachments、favorites、view_history、likes、notifications、site_settings。排除refresh_tokens、article_view_dedup和goose版本表：会话重新登录、阅读冷却重新建立，历史累计viewCount仍保留。

旧用户缺credentials_configured时默认true；微信身份/用户ID、bcrypt哈希、日期、JSON标签投影、对象key与存储类型保留。父节点可能比子节点ID大，分类/评论拓扑排序后插入。检查未知字段、类型、枚举、深度、重复ID、外键、跨文章回复、在用分类与附件关系、点赞计数；不悄悄修复脏数据。软删除文章保留历史分类投影，允许对应已删除分类不再存在。

先导出只读源副本，不在运行中的生产库直接演练：

```bash
TRANSFER_DATABASE_URL=/absolute/path/to/node-copy.db \
go run ./cmd/data -mode export -driver sqlite -file /secure/path/m6-snapshot.json
```

SQLite源用mode=ro打开，不修改journal_mode，不创建不存在的文件。PostgreSQL/MySQL导出在repeatable-read/read-only事务中执行。D1的SQL导出应先在隔离SQLite恢复为副本，再用同一工具；本轮没有调用线上D1导出。

建立独立空目标库，先运行该方言迁移，再演练：

```bash
TRANSFER_DATABASE_URL='postgres://USER:PASSWORD@HOST/EMPTY_DB?sslmode=require' \
go run ./cmd/data -mode import -driver postgres -file /secure/path/m6-snapshot.json -dry-run

# 复核无误后执行实际导入：
TRANSFER_DATABASE_URL='postgres://USER:PASSWORD@HOST/EMPTY_DB?sslmode=require' \
go run ./cmd/data -mode import -driver postgres -file /secure/path/m6-snapshot.json
```

dry-run确实插入并执行关系核查，最后回滚，不是只读JSON算“迁移成功”。实际导入整体事务提交；非空目标拒绝合并；站点仅更新既有id=1。PostgreSQL修正序列，MySQL/SQLite显式ID插入会推进自增序列。PostgreSQL序列自身非事务资源，失败事务可能产生间隙，不影响ID唯一性；空目标条件禁止覆盖既有业务数据。

本轮演练证据：Node真实Hono流程生成的SQLite副本导入PG，13张保留表逐字段一致；另有带反向ID父子关系、微信身份、密码哈希和点赞关系的SQLite→三库精确对照、dry-run不写入、后段外键失败回滚、非空拒绝与PG序列用例。

附件字节不在JSON中。local需另复制uploads并核对key/大小/哈希；R2需保留实际桶/对象与provider配置。对象缺失不能靠元数据导入补齐。

## 5. 未来生产切换顺序

1. 确定Linux主机、TLS反向代理、数据库备份、存储与微信配置；本轮未购买或部署。
2. 在隔离目标环境验证真实微信/R2、Linux构建、四端UI与Cookie，执行迁移演练和文件核查。
3. 约定停写窗口，冻结Node内容/账号/互动/附件新增，建立一致源快照；不进行缺乏一致性保障的双写。
4. 导入空目标，复核行数/关系/已知账号密码登录/微信身份/目录锚点/文件与计数；明确统一重新登录。
5. 同一路径反向代理保留 `/api/v1` 和 `/files`；Cookie保留Secure、HttpOnly、SameSite=None。JWT密钥是否延续决定旧access的短时兼容；不承诺无感迁移refresh会话。
6. 受控切换并观察失败率、权限错误、数据库连接和对象清理日志；本版本采用单写服务实例。
7. 回退时先停Go写入，核对切换后的增量并处理再开Node；不能仅把域名指回旧库而丢失新数据。保留源快照、目标快照与日志。

故障清理对象需对照同storage/key的全部附件引用；重试删孤儿不能误删在用对象。跨实例锁/共享限流扩展属于以后新的工程范围。
