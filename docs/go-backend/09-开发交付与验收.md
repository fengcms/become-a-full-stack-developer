# M6 开发交付与验收

日期：2026-10-08。G0–G8 开发阶段已完成，源码位于 `go-backend/`，冻结契约、Node 后端及四个客户端源文件保持原样。

## 可运行交付

本机服务：`http://127.0.0.1:8080/api/v1/health`；API 根地址：`http://127.0.0.1:8080/api/v1`。当前使用独立 PostgreSQL 数据库 `befull_dev`，不连接生产库。进程运行期间可直接访问；终端或系统重启后在 `go-backend` 执行 `make run`。数据库容器使用命名卷，启动命令见运行手册。

本地演示账号 `m6admin`，密码 `m6-local-password`，仅供这个隔离的本地环境；真实 JWT 密钥保存在被 Git 忽略的 `.env`，未写入文档和提交。

工程提供 server、migrate、seed、data 四个命令；迁移显式执行，不在服务器启动时改表。local 和 R2 存储可配置，PostgreSQL 为默认主数据库，MySQL/SQLite 有真实测试证据。应用层覆盖冻结 68 个操作及 health、文件直出。

## 验收依据

- 全部 68 操作的成功流程及响应 schema，逐操作鉴权/输入边界、事务失败回滚、并发不变量。
- PostgreSQL 17、MySQL 8.4、SQLite 的迁移、完整业务、版本升级和离线导入；全包检查脚本可以复现。
- 既有网页、管理后台、Flutter、小程序的真实请求及会话代码 smoke；微信替身创建的账号设密后，Flutter 实际 Dio 登录成功。
- Go race、vet、格式、契约快照一致性和依赖安全检查；具体范围见 [验证报告](07-验证与兼容报告.md)。
- 本地 Node SQLite 业务夹具只读导出到 PostgreSQL，13 张保留业务表完成 dry-run、真实导入及规范化逐表核对，见 [迁移核查记录](reports/migration-verification.json)。刷新会话和阅读去重不迁移，附件对象需单独复制。
- 同库同机性能样本、原始数据及限制见 [性能总结](08-性能对照与教学总结.md)。
