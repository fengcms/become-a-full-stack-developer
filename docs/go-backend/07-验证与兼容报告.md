## 3. 双实现差分

在隔离 seed、受控时间和微信替身下，将 Go 生成的中立请求 trace 重放到 Node 的真实 Hono 应用。测试数据不访问生产网络。保留状态码、业务码、空值、字段类型、ID、数组顺序和计数，只规范化随机令牌、随机微信用户名和明确列出的生成时间。

| 场景 | 请求 | 完全一致 | 明确产品差异 | 未解释差异 |
| --- | ---: | ---: | ---: | ---: |
| 全部操作成功流程 | 74 | 71 | 3 | 0 |
| 47 个受保护操作的鉴权失败 | 111 | 111 | 0 | 0 |

成功差异包括搜索默认 pageSize（冻结10，Node20）、通知列表与未读数：Go 按产品事件新增一条 `article_published`，Node 没有生成该通知。脚本核对通知类型、标题、正文、链接、未读状态及精确增量，不能忽略任意通知差异。通知列表也精确校验其冻结默认10与Node默认20；搜索差异只允许默认分页大小变更，列表及其余计数必须一致。完整结果见 [成功差分](reports/node-go-success-differential.json)、[鉴权差分](reports/node-go-auth-differential.json)。

其他业务边界由 Go 契约与领域断言验证，不能把这 185 次差分夸大成所有参数组合都已穷尽。

bcrypt 的 ASCII、超过 72 字节、中文 emoji 向量来自真实 bcryptjs；Go 均验证成功。Node 签发 JWT 在 Go 中验证并测试准确到期边界；Go 流程中的认证 JWT 也由 Node 校验 subject/role。两个方向共用 HS256、字符串 sub 和原有效期。

## 5. 冻结资料和 Node 源码之间的处理

| 事实 | Go 决策与证据 |
| --- | --- |
| 3.1 文件仍使用 nullable | 只在校验器内转换 JSON Schema union，源 YAML 不变 |
| 三个 SiteSetting 响应声明裸对象；全局铁律和全部客户端使用信封 | 保留信封，同时验证 data 的 SiteSetting schema |
| URI format 与实际相对附件/通知 URL 不一致 | 输入 format 验证；响应 format 保留注解，字段和业务结构严格验证 |
| PUT Article 引用 ArticleCreate，title/content 必填；Node 允许局部更新 | HTTP 遵守冻结必填；领域内部仍保留字段存在性。现有四客户端编辑器提交完整 title/content，无需改造 |
| 产品敏感词阈值 10%，Node 写 30% | 默认 10%，可配置；UTF-16 中文/emoji 专项验证 |
| 产品阅读冷却 24 小时，Node 使用 UTC 时间桶 | Go 滚动 24 小时；午夜与并发测试通过 |
| Node 软删除没有释放非空 slug | Go 删除设 slug=null，复用用例通过 |
| Node 评论删除只处理一层子项 | Go 递归删除整支，保持平面 parentId 响应 |
| 评论输入 65535、响应 2000 字符；reason 响应 200 | 存储评论全文，响应有界预览并标省略号 |
| 阅读历史 progress schema 不可为 null，Node 返回 null | 未设置/清空时省略，显式 0 和未提交保留语义分别测试 |
| 搜索、点赞、通知端点声明10/50；Node沿用通用20/100 | Go采用各端点的冻结默认和上限，精确差分记录 |
| Node 没有发布/复核通知写入 | Go 在对应状态变更事务内写入，故障回滚与重复事件用例通过 |
| 最初规划提到 fields/括号过滤 DSL，实际 OpenAPI、冻结 PRD、Node 没有定义这些查询 | 修正规划误述；不发明新查询协议。保留已定义分页、keyword、category、tag、status、sort |
| 契约公开端点限流、Node 本地没有同等实现 | Go 各操作独立限流，60 次/分钟，Retry-After；中间件测试通过 |

这些是可审阅的取舍，不表示修改了冻结契约。未对 Node 进行修补；后续修改 Node 应另立任务。
