## 5. 对审阅口径的补充和保留

1. **教学优先级与生产故障等级分开。** 中文注释和 err 命名值得优先处理，但本报告的 P0 是自定义教学口径，不等于已经发生认证、数据或可用性事故。
2. **不采纳“e 会让 errcheck 格格不入”的工具论据。** 原报告没有提供按变量拼写影响错误检查的证据；本次改名依据是清晰表达和风格一致性，不是工具兼容修复。正常的条件内 err 作用域不必机械消灭。
3. **map 字面量不直接等于已测得的堆分配问题。** 统一固定映射有助审阅，但本轮没有对其分配和性能做基准，不声称节约某个比例。
4. **scope 是显式复用，不是自动安全保证。** 新增查询仍需采用规则和测试，不能因为抽了一个函数就宣称未来不会漏过滤。对离线历史和别名审计保留不同语义，避免为了出现次数统一所有 SQL。
5. **统计不是教学质量的充分条件。** 不填充同义注释，不为缩短函数拆碎完整请求链。导出说明与关键规则共同覆盖读者需要的“做什么”和“为什么”。
6. **含测试代码门禁仍为9项通过、4项未通过。** 已实际运行并保存 [含测试统计](results/第一轮/含测试代码门禁.txt)，不能称为全量静态门禁通过。未通过项是测试函数文档、测试包文档、长测试流程及夹具长行；TestAllOperations 等完整场景不按生产函数80行门槛拆散。本轮验收采用原报告的生产口径，测试代码则通过编译、行为、三库与 race 验证。

未修改评审工具、评审报告或冻结 API 来取得门禁结果。原有依赖版本未改，本轮没有重复性能/漏洞扫描或声称 Linux 部署、真实微信/R2 网络验收；这些边界仍沿用原交付说明。
