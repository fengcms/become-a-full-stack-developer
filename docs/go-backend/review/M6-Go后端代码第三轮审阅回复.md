## 2. 新检查的范围和自检

运行方式：在 `go-backend` 下执行 `go run ./scripts/doccheck .`；`make verify` 自动执行。

检查只依赖标准库，用 `go/parser` 的 `ast.File.Doc` 判断真正附着在 `package` 声明上的说明，以相对目录和包名分组。跳过 `_test.go`、隐藏目录及 vendor；覆盖业务代码、命令以及测试服务命令。每包必须恰好一份说明，缺失、重复、说明不含中文都失败；缺失规则与现有包文档覆盖要求一致。

自检包含六组：正常中文说明及接口/实现相同文本、不同行目录同名包、重复包说明、纯英文包说明、缺失包说明、与 package 隔开一行的普通版权注释。合法场景通过，缺陷场景均被捕获。证据见 [包说明检查及自检](results/第三轮整改/包说明检查及自检.txt)。

语言检查判断是否含汉字，能够发现纯英文遗漏，不能证明整段散文已完全中文化，更不能证明业务语义正确。混合语言、责任边界和说明准确性仍需人工核对。这不是通过改评分工具绕过审阅：两份原评审工具和阈值保持原样，新增的是项目自己的检查入口。

## 3. 对报告两处技术依据的订正

### 3.1 多份包说明不会普遍只取一份

报告 §5-1、§8 将“go/doc 只呈现一处，其余无效”作为事实。本机 Go 1.26.6 的 `src/go/doc/reader.go` 中，`readDoc` 会依次收集说明并用换行拼接。使用两个 AST 文件调用 `doc.NewFromFiles`，相同与不同文本的结果分别是：

```text
两份说明相同=true，go/doc.Doc="Package example 第一份中文说明。\n\nPackage example 第一份中文说明。\n"
两份说明相同=false，go/doc.Doc="Package example 第一份中文说明。\n\nPackage example 第二份中文说明。\n"
```

因此，不能把报告扫描器的显示结果推广成 `go/doc` 的通用行为。实验源代码和输出分别保存为 [实验源代码](results/第三轮整改/go-doc包说明呈现实验.go.txt) 与 [实验输出](results/第三轮整改/go-doc包说明呈现实验.txt)。复现时把源代码复制为临时 `.go` 文件并执行 `go run`。

但重复说明会让包文档冗长、维护入口分散，因此接受收敛建议，按项目规范只留一份。这是对技术依据的订正，不是保留重复说明的理由。

### 3.2 GOPROXY=off 不等于完整断网证明

接受报告关于自身 import 的结论：当前主模块下的包从本地目录解析，无需修改模块身份。本轮实际验证 `go list -m` 的主模块身份，并用 `go list -f '{{.Dir}}'` 确认 article 包位于本机工作区。

`GOPROXY=off go build ./...` 在当前依赖缓存下通过，`go mod verify` 通过。这证明本环境能够在关闭模块代理下载后构建，不能等同于禁用所有网络、关闭校验和服务，或者证明空缓存环境无需第三方依赖。模块身份、包路径和子目录标签规则见 [Go Modules Reference](https://go.dev/ref/mod#module-path)。构建与本地解析原始输出见 [证据](results/第三轮整改/模块构建与本地解析.txt)。

[运行手册](../06-运行与迁移手册.md) 已写明 v0/v1 标签为 `go-backend/v0.x.y`、`go-backend/v1.x.y`；v2 及以上还需 module/import 主版本后缀。没有更改模块路径，也没有创建或推送标签。
