## 0. 基础约定（必读）
- 线上基址：`https://api-befull.kao9.com/api/v1`；附件直出：`https://api-befull.kao9.com/files/<key>`
- 响应信封：`{code, message, data, requestId, timestamp}`，`code:0` 成功；取数一律 `data.xxx`
- 鉴权：`POST /api/v1/auth/login` 返回 `data.accessToken`（**不是** `data.token`），内存持有，不落 localStorage
- ⚠️ **R1 修复尚未确认重部署**：分类 PUT 的「省略 parentId 保留原值」改动代码已通过六门门禁，但线上 Worker 截至本文撰写仍是旧逻辑。校验 R1 前，**先确认后端已 `wrangler deploy` 修复版（建议 node-backend-v1.0.1）**；否则 curl 会复现旧的静默挪根。

## 1. 【重点】分类树更新：省略 parentId 不再静默挪根（R1）
### 契约事实（已补明）
- `Category`（实体）含 `parentId`（openapi.v1.yaml:352）；`CategoryNode`（递归树节点）靠 `children` 嵌套表达父子，**刻意不含 parentId**（:355-367）—— 这是树结构正常设计，**不是字段缺失**。
- `PUT /categories/{id}`（:1538-1542）已注明本端点为**局部更新**：可选字段（parentId / description / sortOrder）省略时，后端保留该行原值，不会置空（例如省略 parentId 不会把子分类静默挪到根）。

### 后端修复（冻结后增量维护，六门门禁已通过）
- `src/services/category.ts:312`：`const newParent = input.parentId ?? existing.parentId;`
- `src/services/category.ts:334`：`description: input.description ?? existing.description;`
- 与 `:336` `sortOrder ?? existing.sortOrder` 对齐成统一「局部更新」语义（旧实现 `parentId/description` 误用 `?? null`，与 `sortOrder` 自相矛盾，即 bug 根因）。
- 回归测试已加：`test/routes/categories.test.ts`「更新时省略 parentId/description 保留原值（不静默挪根）」。

### 验证步骤（前端 AI 可照跑，需 editor/admin token）
```bash
TOKEN=$(curl -s -X POST https://api-befull.kao9.com/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"Admin.123"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['accessToken'])")

# ① 建父分类 P
P=$(curl -s -X POST https://api-befull.kao9.com/api/v1/categories \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"父分类","slug":"parent","description":"p-desc"}')
PID=$(echo "$P" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['id'])")

# ② 建子分类 C（parentId = P）
C=$(curl -s -X POST https://api-befull.kao9.com/api/v1/categories \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "{\"name\":\"子分类\",\"slug\":\"child\",\"parentId\":$PID,\"description\":\"c-desc\"}")
CID=$(echo "$C" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['id'])")

# ③ 编辑 C：只传 name/slug，省略 parentId/description/sortOrder
curl -s -X PUT https://api-befull.kao9.com/api/v1/categories/$CID \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"子分类-改","slug":"child"}' \
  | python3 -c "import sys,json;d=json.load(sys.stdin)['data'];print('parentId=',d['parentId'],'description=',d['description'])"

# 期望：parentId == $PID （不被置 null / 不挪到根）；description == 'c-desc'（保留原值）
```
反向用例（确认修复未破坏正常行为）：
- 传 `"parentId": null` → 应挪到根（parentId 为 null）
- 传合法的其它父 id → 应生效；传会造成环/超深（>4）的 parentId → 应 409 / code 3002

### 前端代码自查
- 编辑分类表单：提交时**应始终带上 `parentId`**（即使 UI 未改，也从当前分类对象回传），不依赖后端兜底。
- 渲染树：用 `CategoryNode.children` 递归，**不要在节点上找 `parentId`**。
- 若此前因误以为「CategoryNode 无 parentId」而在编辑时漏传 parentId：后端现已兜底，但**前端仍建议显式回传**，避免未来行为变化踩坑。

## 2. 列表分页字段是 `list`（非 `items`）（R2）
- 详见 `docs/prd/M2-分页字段名纠正报告.md`。要点：列表响应结构 `{ list: T[], pagination: {page, pageSize, total, totalPages} }`。
- 取数一律 `data.list`，**禁** `data.items`（参考项目 `telemarketing-saas-manage` 用的是 `items`，本项目不用）。
- 自检命令：
```bash
grep -rn "data\.items\|\.items\b\|items:" src/ | grep -v "node_modules"
# 期望：0 命中（api.gen.ts 里 ArticlePage 的 list 下方的 items: 是 OpenAPI 数组元素保留字，非字段名，可忽略）
```
- 类型：`src/types/common.ts` 的 `Page<T>` 须为 `{ list: T[]; pagination }`，勿复用参考项目的 `Page`。

## 3. 附件 URL 前缀是 `/files`（非 `/api/v1/files`）（R3）
- 详见 `node-backend/部署到Cloudflare指南.md` FAQ「取附件 404」。要点：`Attachment.url` 返回 `/files/<key>`（根路径直出，策略 A 中转），**不在** `/api/v1` 下。
- 前端拼接须 `ORIGIN + url`（如 `https://api-befull.kao9.com/files/<key>`），**不能** `API_BASE + url`（若 API_BASE 含 `/api/v1` 会拼成 404）。
- 自检命令：
```bash
grep -rn "/api/v1/files" src/          # 期望 0 命中
grep -rn "API_BASE.*files\|/files" src/ # 确认拼接用的是 ORIGIN 而非 API_BASE
```
