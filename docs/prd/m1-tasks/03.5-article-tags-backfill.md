## 关键行为指引

### ① article_tags 写同步（必须）
- **create**：在 `articles.ts:123-136` 的 `.insert(articles).values({...})` 拿到新 `article.id` 后，对 `input.tags` 中每个标签字符串，按 `slug === name` 约定解析出 `Tag` 实体 id（`SELECT id FROM tags WHERE slug = ?` 或 `name = ?`），对存在的每个 id 插入 `article_tags(article_id, tag_id)`。不存在的标签**跳过**（仍留在 `articles.tags` 供响应返回，不自动建 catalog 标签——建标签属 editor 职责，超出本批）。
- **update**：在 `articles.ts:215-223` 的 `.update(articles).set({...})` 后，先 `DELETE FROM article_tags WHERE article_id = ?`，再按新 `input.tags` 重新插入（覆盖式，幂等）。`input.tags` 省略时沿用 `existing.tags`（代码现状，保持）。
- **soft-delete**：`articles.ts:252-253` 软删时，建议一并 `DELETE FROM article_tags WHERE article_id = ?`（可选；articleCount 查询已 `isNull(deletedAt)` 过滤，不删也不影响计数，但删了更干净）。
- 插入使用 `article_tags` 唯一索引 `uniq_article_tag(article_id, tag_id)`（`migrate.ts:101`）：用 `INSERT ... ON CONFLICT DO NOTHING` / drizzle `.onConflictDoNothing()`，避免并发或重复标签抛错。
- **复用** B1 既有 `isUniqueConstraintError` 仅作兜底，正常路径靠 `onConflictDoNothing`。

### ② 存量回填脚本（必须，可重复跑）
- 新增 `scripts/backfill-article-tags.ts`（用与 `worker.ts`/`index.ts` 一致的 `getDb()` + 环境变量）。
- 逻辑：`SELECT id, tags FROM articles WHERE deleted_at IS NULL` → 每行 `parseTags(tags)` → 对每个标签名解析 `Tag.id` → `INSERT OR IGNORE INTO article_tags(article_id, tag_id)`。
- **幂等**：依赖 `uniq_article_tag` 唯一索引 + `ON CONFLICT DO NOTHING`，重复执行安全。
- 不在迁移里做（迁移只管 schema）；作为独立脚本，由人在部署后跑一次，或在 `index.ts` 启动期可选调用（二选一，写进 NOTES 说明选择）。
- 回填后 `GET /tags` 的 `articleCount` 应从 0 变为真实值——这是本批"可见正确性"的验收点。

### ③ 列表标签过滤切 JOIN（强烈建议，关 B2 P3）
- `lib/article.ts:158-159` 当前：
  ```ts
  if (q.tag) conds.push(sql`${articles.tags} LIKE ${`%"${q.tag}"%`}`);
  ```
- 改为：由 `q.tag`（slug/name）解析出 `tagId`（`SELECT id FROM tags WHERE slug = ?`），对 `article_tags` 做 `innerJoin` 过滤 `article_tags.tag_id = tagId AND article_tags.article_id = articles.id`。
- **行为变化（预期且正确）**：旧 LIKE 会子串误匹配（如 `js` 命中 `json`）；新 JOIN 仅匹配真正链接到 catalog 标签的文章。若 `q.tag` 无对应 catalog 标签 → 返回空列表（正确）。
- 调整 `articles.test.ts` 中 tag 过滤相关断言以匹配新语义（精确匹配，不再子串）。

### ④ articles.ts 拆分（建议，还 200 行欠债）
- `src/routes/articles.ts` 当前 358 行，越 200 行铁律。按"公开读 vs 登录写"职责拆：
  - `articles-read.ts`：列表 `GET /`、详情 `GET /:idOrSlug`、`POST /:id/view`（公开/登录读）。
  - `articles-write.ts`：`POST /`（创建，member）、`PUT /:id`（更新）、`PATCH /:id/status`、`DELETE /:id`（写，含 ownerOverride）。
  - 两者在 `app.ts` 同挂 `/api/v1/articles`；共享 `lib/article.ts` 的 `queryArticles/toArticle/toArticleSummary` 等纯函数。
- **门禁兜底**：现有 54 条 article 测试须全绿；拆分不得改任何对外行为。
