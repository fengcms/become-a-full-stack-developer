## 阅读顺序

新加入的协作者按 `00 → 01 → 02 → openapi.v1.yaml` 顺序读。其中 00 号文档的**第四节 Non-goals**、**第六节 API 契约**和**第九节文风约定**是硬约束，任何设计与文章不得违反。

## 核心结论速查

- **定位**：文章是产品，代码是素材
- **发布**：主阵地 CSDN，单篇约 2500 中文字，发布频率周更 2 篇
- **节奏**：波次串行，一个 M 只讲一件实现（一个代码库）
- **交付点**：M3 结束即为完整交付，M4–M7（含 Go/Vue 重写）是加分项与差异化王牌
- **硬地基**：领域模型 + API 契约（OpenAPI），唯一值得提前投入设计的部分，已在动工前定稿
- **规模**：主线 103 篇 + 支线 14 篇（总计 117 篇）；最小可交付集 33 篇（含已升 P0 的 M1-25/26/27）
