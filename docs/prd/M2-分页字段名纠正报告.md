# M2 前端分页字段名纠正报告

> 受众：负责 `manage-frontend` 的前端 AI
> 触发：联调时观察到文章列表接口返回的数据在 `list` 字段里，怀疑与契约不一致
> 结论：**后端返回 `{ list, pagination }` 是正确的，与契约完全一致；前端当前文章列表模块也已正确实现 `list`。本报告的要点是澄清误读来源，并给后续列表模块一份自检清单，避免误用参考项目的 `items` 约定。**

---

## 1. 一句话结论

文章接口把数组放在 `data.list` 里 —— **这是对的，不是 bug**。

契约 YAML 中 `ArticlePage.list` 字段下的 `items:` 是 **OpenAPI 描述数组元素的保留关键字**（`type: array` 下用 `items` 声明元素类型），**不是数据字段名**。真实数据字段名就是 `list`。

---

## 2. 契约真相（权威依据）

契约文件：`docs/api/openapi.v1.yaml`（基线 v1.11.0，冻结未改）

`ArticlePage`（第 190–200 行）：

```yaml
ArticlePage:
  type: object
  properties:
    list:            # ← 真实字段名（数组）
      type: array
      items:         # ← OpenAPI 保留字：描述数组元素类型，不是字段名！
        $ref: '#/components/schemas/ArticleSummary'
    pagination: { $ref: '#/components/schemas/Pagination' }
  required: [list, pagination]
```

- 所有分页 schema 结构一致：`ArticlePage / UserPage / CommentPage / AttachmentPage / HistoryPage / MemberPage / NotificationPage` 均为 `required: [list, pagination]`。
- `Pagination`（第 182–188 行）字段：`page / pageSize / total / totalPages`（均为 integer）。
- 后端线上实测（`GET /api/v1/articles`）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [],
    "pagination": { "page": 1, "pageSize": 20, "total": 0, "totalPages": 1 }
  },
  "requestId": "...",
  "timestamp": "..."
}
```

---

## 3. 误读来源（为什么会有“是不是不一致”的错觉）

1. **参考项目约定不同**：`telemarketing-saas-manage` 的分页是 `{ items, total }`（数组在 `items`，总数平铺在 `total`）。本项目**不用**这个约定。
2. **简报曾笔误（已纠正）**：`docs/prd/M2-前端开发准备简报.md` 一度误写 “取 `data.items`”，现已改为 “取 `data.list`”。这是文档笔误，**后端与契约从未漂移**。

---

## 4. 当前前端代码核查（已查，文章列表模块正确）

| 位置 | 现状 | 结论 |
|---|---|---|
| `src/types/common.ts:41-44` `Page<T>` | `list: T[]; pagination: Pagination` | ✅ 正确 |
| `src/types/api.gen.ts:1121` `Pagination` | `page / pageSize / total / totalPages` | ✅ 与后端一致 |

| `src/pages/articles/ArticleListPage.tsx:138` | `data={data?.list ?? []}` | ✅ 用 `.list` |

→ **文章列表模块无需改动，已经是对的。**

---

## 5. 前端 AI 自检清单（后续列表模块必查）

后续要落地的列表端点（评论审核、用户管理、会员、附件、通知、阅读历史等）务必遵守：

1. **数组取值一律 `data.list`**：禁止 `data.items` / `res.items` / `res.data.items`。
2. **分页元数据用 `data.pagination`**：字段为 `page / pageSize / total / totalPages`；禁止 `data.total` 平铺取值（本契约分页是**对象**，不是参考项目的 `{items, total}`）。
3. **不要复用参考项目的 `Page` 类型**（`{items,total}`）：统一用本项目 `src/types/common.ts` 的 `Page<T> = { list, pagination }`。
4. **若直接引用 `api.gen.ts` 的 `Schemas['XxxPage']`**：确认其 `properties` 含 `list` 而非 `items`（本项目当前生成类型已正确，但**重新生成 `api.gen.ts` 后要复查**，生成器若误把 OpenAPI `items` 当成字段会出问题）。
5. **表格组件接线**：`DataTable` / `TablePagination` 的 `dataSource` 接 `data?.list ?? []`，`total` 接 `data?.pagination?.total`。
