## 2. 请求层 / 鉴权 —— 必须按本契约改写（核心差异）

参考项目的关键假设与本系列契约不同，逐条对齐：

### 2.1 统一信封：`code:0` 成功（非 `success:true`）

本系列契约 `ApiResponse<T> = { code:number; message:string; data:T|null; requestId:string; timestamp:string }`，`code===0` 成功。

> 实测线上 `GET /api/v1/health` → `{"code":0,"message":"ok","data":{"status":"ok"},...}`；登录错误 → `{"code":1001,"message":"用户名或密码错误",...}`。

改写点（`request.ts`）：把 `'success' in payload` 判定改为 `payload.code === 0`；失败抛 `ApiRequestError(code, message, status)`，`code` 为**数字**（非字符串）。`resolveErrorMessage` 用 `codes.ts` 的中文映射表（后端 `message` 已是中文，可直接兜底）。

### 2.2 API base path：`/api/v1`（非 `/api`）

`BASE = \`${import.meta.env.VITE_API_BASE ?? ''}/api/v1\``，dev 用 `VITE_API_BASE=https://api-befull.kao9.com`。

### 2.3 刷新令牌：浏览器走 **HttpOnly Cookie**（非请求体 + 手动持久化）

契约 `AuthResult`：`required:[accessToken, expiresIn, user]`，`refreshToken` 对浏览器由 `Set-Cookie` 写入 HttpOnly+SameSite Cookie（`POST /auth/refresh` 读取优先级「Cookie 优先，缺失取请求体」）。

→ 改写点：
- 每个请求 `fetch(init)` 加 `credentials: 'include'`，让浏览器自动带/收刷新 Cookie。
- `tryRefresh()` 调 `/auth/refresh` **不传 body**（靠 Cookie），只回写 `accessToken`+`user`。
- `store/auth.ts` **不存 refreshToken**（Cookie 由浏览器管）；仅存 `token`+`user`，**不 persist 到 localStorage**（贴合「accessToken 绝不 localStorage」铁律）。首页刷新后由「启动静默 refresh」恢复 accessToken。
- 登出：`POST /auth/logout`（带 `skipAuthRedirect` 豁免）+ 后端清 Cookie；前端 `clear()`。

### 2.4 401 无感刷新（并发去重）照抄

`refreshTask` Promise 锁避免并发 401 多次刷新；`_isRefresh`/`_retried` 标记防递归；refresh 自身 401 → `clear()`+跳登录。白名单：`/auth/login`、`/auth/refresh`、`/auth/logout` 不被 401 逻辑误伤。

### 2.5 错误码为数字分段

`1xxx` 认证 / `2xxx` 授权 / `3xxx` 资源 / `4xxx` 参数 / `5xxx` 服务；`5001` 限流（429）。`resolveErrorMessage` 接收数字 `code` 映射中文（直接复用 node-backend `src/shared/codes.ts` 的 `ErrorMessages`）。

## 3. 角色模型（改成本系列三角）

- 本系列 `Role = 'member' | 'editor' | 'admin'`（无 `tenant_*`/`platform_*`）。
- `ROLE_LABELS`：`member=成员 / editor=编辑 / admin=管理员`。
- `ROLE_HOME_MAP`：`admin|editor → /dashboard`（或各自首页）；`member` 禁入后台（若登陆后台）按 `ADMIN_BLOCKED_ROLES` 处理。
- 权限语义：editor 管全站内容（文章/评论/分类/标签），admin 另管用户/角色/站点配置；**前端权限仅体验层**，真防线是路由守卫 + 后端 403（`x-authz` 已在契约机器化）。
- `visibleMenu(role)` 数据驱动；`RequireAuth`+`RequireRole` 双层守卫照抄。

## 5. 必须继承的工程纪律（来自参考踩坑）

- **pnpm 11 状态检查 bug**：门禁用显式 `./node_modules/.bin/tsc -b` / `./node_modules/.bin/vite build`，不裸 `pnpm build`。
- **列表分页取 `data.list`（不是 `items`！）**：本契约分页数组字段名是 `list`（与 telemarketing-saas-manage 参考项目的 `items` **不同，切勿照搬**）。`Page<T>` 类型应为 `{ list: T[]; pagination: { page: number; pageSize: number; total: number; totalPages: number } }`。所有列表接口（articles/users/comments/attachments/members/notifications/likes/history）统一返回 `{ list, pagination }`，前端务必 `data.list` 取数组、`data.pagination` 取分页。契约依据：`docs/api/openapi.v1.yaml` 各 `*Page` schema（如 ArticlePage 的 `list` 为 `array<ArticleSummary>`）+ 领域模型 `docs/prd/02-领域模型与API契约.md:418`「列表统一返回 `{ list, pagination }`」。
- **双 key 漏刷**：同类数据的 RQ 缓存 key 前缀统一，变更后用 `invalidateQueries` 助手一次性失效相关 key。
- **登出/刷新豁免**：`/auth/logout`、`/auth/refresh` 走 `skipAuthRedirect`/`_isRefresh`。
- **错误信息不露原文**：统一 `resolveErrorMessage(code, message)`。
- **不写死颜色**：一律 `text-primary`/`bg-muted`/`border-border` 令牌；动效包 `prefers-reduced-motion`。
- **先 curl 实测后编码**：对接每个接口先 `curl` 对齐字段，差异记「差异表」。

## 6. 🔴 开工前唯一硬阻塞：线上 API 的 CORS `allow-origin` 未回显

实测 `https://api-befull.kao9.com`（带 `Origin: http://localhost:12000`）：

- ✅ `access-control-allow-credentials: true` + `vary: Origin` 已返回。
- ❌ **从不返回 `Access-Control-Allow-Origin`**（对照 example.com / localhost:5173 同源，均无 allow-origin）。

按 CORS 规范，凭据模式（`credentials:'include'`）下浏览器要求响应带**精确** `Access-Control-Allow-Origin`（非 `*`），缺失则拦截响应。这会使「HttpOnly Cookie 刷新」方案在 `localhost:12000` 跑不通。

**两种解法（待 owner 拍板）：**

- **方案 A（推荐，完全贴合契约）**：直连 `https://api-befull.kao9.com` + `credentials:'include'` + Cookie 刷新；需 owner 把 `http://localhost:12000` 加入部署后端 `CORS_ORIGINS` 环境变量（一处改动，Hono 即回显 allow-origin + 保持 credentials:true）。最安全、最合规。
- **方案 B（dev 零后端改动）**：Vite 代理到线上 API（同源，免 CORS），但代理会破坏 HttpOnly Cookie 的跨域携带 → 改为**内存存 refreshToken + `/auth/refresh` 请求体刷新**（契约支持「缺失取请求体」），`credentials` 不必开。偏离「浏览器用 Cookie」约定，但 dev 期可用。

> 无论 A/B，登录响应字段都是 `data.accessToken`（非 `token`），附件 URL 用 `ORIGIN + /files/<key>`（**不带 `/api/v1` 前缀**，否则 404——已记 FAQ）。
