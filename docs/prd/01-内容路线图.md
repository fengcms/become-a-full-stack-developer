## 一、怎么读这份路线图

这份文档是整个项目的**北极星**。产品该做什么功能，由这里的文章需求倒推，而不是反过来。

### 编号规则

编号一经确定不再变动，因为它要和 git tag、代码仓库、文章链接三方绑定。

**核心约束：一个 M 系列只讲一件实现（一个独立代码库 / 端）。**

> **说明（R17）**：「一件实现 = 一个代码库」适用于 M1–M7（均为具体端）。M0（开篇规划）与 M8（收官复盘）是**非实现的特殊段落**——M0 产出规划文档（含本路线图与领域模型契约），M8 产出总结，均不对应独立代码库。读者问「M0 的实现在哪」时，答案即本系列的前期文档本身。

| 前缀 | 含义 | 示例 |
|---|---|---|
| `M0` | 主线 · 开篇与规划（地基） | `M0-05` |
| `M1` | 主线 · Node 后端（API 首实现） | `M1-15` |
| `M2` | 主线 · React / Vite 管理后台 | `M2-07` |
| `M3` | 主线 · Next.js 网站前台（含会员中心） | `M3-05` |
| `M4` | 主线 · Flutter App | `M4-04` |
| `M5` | 主线 · Taro 小程序 | `M5-03` |
| `M6` | 主线 · Go 后端重写（同契约） | `M6-07` |
| `M7` | 主线 · Vue3 管理后台重写（同契约） | `M7-02` |
| `M8` | 主线 · 收官 | `M8-03` |
| `B` | 支线 · 基础补充（面向零基础） | `B-05` |

对应的 git tag 格式：`article/M1-15`。

### 优先级分级

| 级别 | 含义 | 处理方式 |
|---|---|---|
| **P0** | 系列骨架，缺了就断链 | 必发，不可跳过 |
| **P1** | 显著提升完整度 | 推荐发，精力紧张时可合并进相邻篇 |
| **P2** | 锦上添花 | 可选，也可作为独立番外 |

### 单篇形态

- **篇幅：约 2500 中文字（±300）**。每篇只讲一个聚焦的技术决策或一步实现，不注水。
- **结构**：本文目标 → 前置知识 → 正文 → 小结 → 延伸阅读（CSDN 站内互链 ≥2）。
- **文风**：比过往博客更克制、更结构化，保留个人判断与中文注释。详见章程第九节。
