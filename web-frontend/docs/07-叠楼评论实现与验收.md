# 叠楼评论

## 接口依据

现有 `GET /api/v1/articles/:id/comments` 返回扁平分页，包含 `id / parentId / userId / userName / content / status / createdAt`。后端按创建时间升序返回已通过审核的评论；POST 支持 parentId 指向同文章的已有评论。因此无需修改后端或契约，可以在新前台重建楼层关系。

接口没有按主楼分页、按主楼加载回复、单独读取某条评论等能力。原先逐页切换会把父评论与回复分开，所以改为保留已加载记录的“加载更多评论与回复”。每次仍请求 20 条，不一次下载全部评论。楼内数量明确标为“已加载回复”，不伪装成完整回复数。

## 展示

- 主评论独立成楼；所有后代回复放入该楼的浅蓝背景区域。
- 回复显示直接回复对象的昵称、原文短摘要，点击摘要定位原评论。
- 深层回复保留真实 parentId，视觉缩进只增加一档，手机端避免内容越来越窄。
- 默认显示每楼前 4 条已加载回复，可展开或收起；本人刚发布的回复所在楼自动展开。
- 原评论未公开、被删除或尚未加载时，显示“回复的原评论暂不可见”，不显示裸编号、不泄露审核隐藏内容、不猜测作者。
- 父评论后续加载到时重新归楼。分页重叠数据按评论 ID 去重；异常环形引用不会造成无限递归。
- 评论输入区显示正在回复的昵称和摘要，可取消回复；未登录用户仍需登录。
- 发表沿用审核反馈；删除提示子回复可能一起删除，之后重新获取服务端结果，不自行推断后端多级删除范围。

## 验证

- 新增跨页父子关联、多级直接回复对象、缺失/未审核父评论、分页去重、环形关系、1,000 层深回复的单元测试。
- 保留原请求鉴权、投稿和会话测试。
- 浏览器验收使用新前台 `.local/test.db` 中的专用测试文章，不修改原项目数据。
- 18 项单元测试、类型检查、Biome 检查和 Next 生产构建通过。
- 真实浏览器通过：20 条主评论与跨页多级回复归楼、展开收起、昵称及摘要、刚发布回复归入原楼、本人删除回复、审核隐藏原评论后不泄露原文。
- 桌面 1440px 与手机 375px 截图已检查，手机没有横向溢出。截图位于 `screenshots/comment-thread-desktop.png` 和 `screenshots/comment-thread-mobile.png`。
