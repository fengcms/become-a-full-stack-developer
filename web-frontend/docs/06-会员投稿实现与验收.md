# 会员投稿：实现与验收

本次范围经过用户确认，替代原方案“仅查看我的文章、不增加编辑器”的限制。仅调整 `web-frontend-codex`，原前台、管理后台、后端代码不变。未部署到远程环境。

## 页面与交互

- 我的文章：写文章入口、全部/草稿/待审核/已发布筛选。草稿可编辑、预览、提交、删除；待审核可修改、预览、撤回；已发布可查看及修改后重新送审。
- 会员下拉菜单：我要投稿快捷入口。
- `/member/articles/new`：新稿件。
- `/member/articles/[id]/edit`：本人稿件编辑。
- `/member/articles/[id]/preview`：带登录鉴权的私人预览。
- 写作页沿用白底、蓝灰文字与蓝色主按钮，收起会员侧栏，保留 Header/Footer。桌面默认编辑/预览分栏，手机单栏切换；底部操作栏随滚动保持可见。
- 设置包含摘要、封面、完整分类路径、已有标签。分类为提交审核时的前台必填项，草稿允许未分类。
- 采用与后台相同的 `@uiw/react-md-editor@4.1.2`。预览使用前台 Markdown 渲染器，保留代码高亮、表格滚动、标题锚点，禁用原始 HTML。

## 状态与数据约束

1. 新建保存后地址变为该稿件的编辑地址，后续保存更新同一篇文章。
2. 投稿先保存最新内容，再调用 submit；第二步失败提示“草稿已保存，提交审核失败”，可重试。
3. 待审核稿件保存维持 pending；撤回使用更新接口转 draft。
4. 发布稿件修改时明确确认，保存请求显式传 pending，包括从会员中心进入的管理员。没有直接发布按钮。
5. 后端不存在独立版本、驳回原因、审核历史；本次不虚构这些字段。重新送审会影响公开版本，既有公开缓存可能短暂保留旧内容。
6. 保存前重新读取文章的状态和更新时间，发现其他修改或审核则保留输入并提示核对。这是客户端冲突提示，后端没有原子版本号/CAS，不能保证消除并发写入窗口。
7. 私有稿件由客户端带 token 读取，页面另核对 authorId；后端依然是权限边界。页面继承会员区 noindex，不进入 sitemap。

## 图片

- 正文支持选择、粘贴、拖拽图片；连续上传串行执行，单图失败提示重新选择或粘贴，不阻断后续图片。
- 封面支持上传和移除；上传未结束时禁止保存/投稿。
- 类型与后端一致：PNG/JPEG/GIF/WebP/SVG，每张最大 10MB。
- 后端返回 `/files/...`，新项目新增限定哈希文件名的同源 `/files/[key]` 转发。封面保存为完整 URL，满足后端 URL 字段校验。
- 文件响应使用 nosniff 与 CSP sandbox，SVG 不获得站点脚本执行权限。
- 无稿件 ID 时允许上传，后续正文 URL 可使用，但现有接口无法补关联旧附件的 articleId；不自动删除被移出正文的附件，避免误删共享文件。

## 内容保护

- 按账号 ID + 稿件 ID 保存本机恢复副本，新建稿件独立使用 new 键；仅在用户选择恢复后覆盖编辑内容。
- 不自动写服务器，避免编辑已发布文章时意外下线。
- 本机存储不可用会提示；本机副本不等同服务器保存，也不是跨设备草稿。
- 链接离开、刷新和关闭时对未保存内容提示；浏览器历史导航仍以本机恢复副本兜底，不宣称所有浏览器都能拦截后退。
- 保存和上传有进行中状态；后台数据刷新不覆盖正在输入的内容。
- 服务器返回失败保留输入；保存前校验标题、正文和摘要长度。
